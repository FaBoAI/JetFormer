# AI走行のベストプラクティス(1周のタイムを縮めていくために)

2026-10-10 の AI走行(ai_run_003〜008、モデル `first_trial_20261010-s3-20261010-153629`)の解析から。
車体はタミヤ TT-02 SRX、65mmタイヤ。コースは左回り、1周 約9〜10秒。
詳しい数値と図は `data/reports/ai_runs_20261010/` にある。

- `params.md`: パラメータの効果と調整手順
- `collision_map.md`: どこで・なぜぶつかるか
- `human_recovery.md`: ESCの後退の規則と、人のリカバリー
- `tof_predictor.md`: 距離センサーで衝突を予測する

## 0. 今の状態(2026-10-10 夜)

| 項目 | 結果 |
|---|---|
| ラップ | **AIはすでに人と同じくらい速い**。AIだけの周の中央値は ai_run_006 で 9.5〜9.7秒(ベスト 8.15秒)、人は中央値 9.8秒(ベスト 7.2秒)。AIのほうがばらつきは小さい |
| 弱点 | **衝突**。AIは 1周に約1.2回ぶつかる(人は約0.75回)。91% が3か所(下の R1・DE・GM)。止まって動けなくなると人が交代している |
| 速度のゲイン | 上げても速くならない。モデルが自分の速度を見て、指令を下げて打ち消すため |
| 不安定な電源 | 強く加速すると、コントローラ基板が再起動する(ai_run_008 で12回)。Jetsonの電源も2回落ちた。バッテリーと配線の確認が先 |

## 1. 走る前のチェック

1. **バッテリーを満充電**にする。走行中に電圧が下がると、次のことが起きる。
   - 基板が再起動し、車両データが途切れて AIが中立で止まる
   - Jetsonの電源が落ちる
   - 走行画面に「基板の再起動 N回」が出たら、走行を止めて充電する
2. **管理画面を再読み込み**する。画面の版が古いと走行を開始できない。
3. ライブ画面で、どのセンサーにも「データなし」や途切れがないことを確かめる。目安はカメラ・ToF が 30Hz、IMU・車両が 100Hz。
4. 走行画面で次のスイッチと値を確かめる。
   - 「リカバリー」と「後退の前に中立を挟む」が ON
   - 「後退の強さ」の既定は中立+300µs
5. 評価するときは、必ず「走行中のデータを収集する」にチェックを入れる。後で `tools/drive_report.py` で振り返れる。

## 2. パラメータの調整

### 最初の設定

| パラメータ | 最初の値 | 試す範囲 | 理由 |
|---|---|---|---|
| 速度のゲイン | **1.0** | 1.0〜1.2 | 上げても速くならず、加速の突き上げと衝突が増えるだけ(2.0 でも速度の中央値は +9%) |
| ステアリングのゲイン | **1.3** | 1.1〜1.5 | モデルの小さな切れ角は人の約半分なので、1より少し大きく。1.6 以上はハンドルが限界に張り付く時間が増える |
| 先読み | **3** | 2〜3 | 5 は予測が揺れて、コーナーの入口で内側を削った。5 は使わない |
| トリム | 0 | — | 直進するステア値は中心(1443µs)と一致している |
| 時計補正 | 0 | — | 人とAIのステアの効き方に、はっきりした差は見られなかった |

### 調整のしかた

- **1回の走行(ログ)では1つの設定だけで走る。走行中にスライダーを動かさない。**
  - 今日は走行中に何度も動かしたので、36区間の大半が短すぎて比べられなかった。
- **一度に変えるのは1つ**。A → B → A の順で走り、最初と最後の A の差を、電池や路面の変化の目安にする。
- **1回の試行はAI側で4分以上(約24周)**。
  - これで衝突の3倍の差が見分けられる。
  - 2倍の差を見分けるには約43周(7分)が必要。
  - ラップは20周ずつあれば、0.4秒の差が見える。
- **順番**:
  1. ステアリングのゲイン(1.1 / 1.3 / 1.5)
  2. 先読み(3 と 2)
  3. 最後に速度のゲイン(1.0 → 1.2)。1.2 にするのは、ラップが0.3秒以上縮み、衝突/周が3割以上増えないときだけ。

### 何で判定するか

走行画面の周回表示と、`python tools/drive_report.py <ログ名>` で見る。

| 指標 | 今日 | 目標 |
|---|---|---|
| AIだけの周のラップ中央値 | 9.5〜10.2秒 | 少しずつ縮める(人のベストは 7.2秒) |
| 衝突/周(水平 2.5G 以上) | 約1.2 | 人と同じ 0.75 以下 |
| 交代/周、スタック/10周 | 007 で 0.5 / 2.2 | 0 に近づける |
| ハンドルが限界(1000/2000)にいる割合 | 8〜23% | 5〜15%(20%超ならゲインが大きすぎる) |
| 中立で止めた(hold) | 0 | 0 でなければ、その試行は無効(電源・センサーを直す) |

`data/reports/ai_runs_20261010/params_study.py <ログ名>` を使うと、衝突/周、集中区間の割合、ステアの統計まで一度に出る。

## 3. 衝突を減らす

ぶつかる場所は3か所に集中している(`collision_map.md`、コースの写真あり)。

| 場所 | 何が起きるか | 原因 | 対策 |
|---|---|---|---|
| **R1**: 黒いカーテン前の左ヘアピンの直後の右ヘアピン | 右いっぱいのまま、白い仕切り(柱つき)の端に正面から当たって止まる。交代のほとんどがここ | **入口の速さ**。モーター回転数 6200 以上で入ると 8回中6回当たり、5500 未満なら21回中1回 | 入口を遅くする(下のToFガード、データ) |
| **DE**: 緑マットの後の直線の終わり、右の外壁の角 | 右前をこすりながら走り続ける(006 で16回中11回) | 緑マットを出たときの向きが、人より約15度右(壁の角)を向いている | 緑マットの出口で左寄りを走るデータを増やす |
| **GM**: 緑マットの左コーナー | 入口で内側の板の端を削る。出口では外の板に触れる | ステアゲイン1.8・先読み5で目立った | ゲイン1.3・先読み3にする |

- **AIは人の運転をまねている。** 学習データ(22シーン)には人の衝突が33回あり、同じ場所でぶつかっている。人も R1 の手前で加速していた。きれいな運転のデータを増やすのが根本的な対策になる(5章)。
- **距離センサー(ToF)で衝突を予測できる。** 床を取り除いてから、予測コースに沿って衝突までの時間(TTC)を求める。
  - TTC 0.5秒未満で警告すると、衝突の 88% を0.3秒以上前に予測できる。誤警報は約13回/分。
  - 減速と、近い側から離れるハンドルを足す「ToFガード」を作る予定(`tof_predictor.md`、`tof_guard.py`)。
  - まず**記録だけするモード**で走って警報のタイミングを確かめ、それから減速を ON にする。
- **IMUは90度回して付いている**(+x = 右、+y = 前)。大きな衝突は横ではなく**正面〜右前**から当たっている。

## 4. ぶつかったとき(自動リカバリー)

### ESC(TT-02)の後退の規則

ログ116回分で確かめた規則は次のとおり。

- 前進の直後に後退側を出すと、**ブレーキ**になる。前へ転がっている間は、何をしても後退しない。
- **止まってから「後退側 → 中立(約0.12秒)→ 後退側」で下がる**。人は、ブレーキ約0.27秒 → 中立 → 後退(約1712µs)を約0.3秒 → 惰性 → 曲がっていた向きへハンドルを切って前進、と操作している。

### 自動リカバリーの動き

ぶつかって止まると、次の順に動く(走行画面のスイッチで ON/OFF)。

1. ブレーキ
2. 止まるのを待つ
3. 中立 0.15秒
4. 後退(**強さ**: 中立+300µs、画面で 150〜500。**時間**: 0.4秒、画面で 0.2〜1.2)
5. 下がり始めなければ、中立を長く・少し強くして最大2回やり直す
6. 惰性
7. 止まる前に曲がっていた向きへハンドルを切って前進 0.5秒
8. AI に戻す

- 後退中に後ろへぶつかったら、すぐ前進する。
- 20秒以内に3回続くと、中立で止まって人を待つ。CH3 を人側へ戻すと解除される。
- 車のスピーカーが「リカバリー」と読み上げる。
- 後退が弱い・強すぎるときは、「後退の強さ」と「時間」を調整する。
- **まだ実車で確かめていない(v2)。** 最初は人がすぐ交代できるようにして試す。

## 5. データの集め方(タイムを縮める本命)

モデルは人の運転をまねるので、**速く・きれいに・ぶつからずに走ったデータ**がそのまま上限になる。

1. **R1・DE をきれいに抜ける周を約30周**集める。人のベストに近い周を多くする。
   - 直線の終わりでブレーキ。
   - 左ヘアピンと R1 の入口は回転数 5000 以下。右いっぱいに切ってから加速する。
   - 緑マットを出たら、右の壁から車1台分以上離れて左寄りを走る。
2. **AIがよく失敗する位置から立て直す操作**を、それぞれ10〜15回集める(DAgger のように)。
   - 対象の位置: DE の壁の角へ向いた状態、R1 に速く近すぎる状態、緑マットの出口で外へふくらんだ状態。
   - ぶつからずに、後退も使わずに立て直す。
3. **ぶつかった前後(1秒前〜2秒後)は学習に使わない**。今の学習データに人の衝突が33回ある。
4. **後退して抜け出す操作は別のジャンル**(例: 6「リカバリー」)にするか、学習に使わない。リカバリーは自動の補助に任せる。
5. **ジャンルを分ける**: 速い周は「高速走行」、遅くてきれいな周は「低速走行」。今は全部「低速走行」になっている。
6. 新しいデータで学習したら、`tools/evaluate.py` で今のモデルと比べてから実車で走る。今の操作値を入力しないモデル(コマンド入力なし)も比べる。

## 6. 1周のタイムを縮めるサイクル

```
走る(1設定・4分以上・収集ON)
  → drive_report / params_study で ラップ中央値・衝突/周・交代/周 を見る
  → 衝突が多い場所 = データを足す場所(5章)/ パラメータは2章の順で1つずつ
  → 学習 → evaluate.py → 実車
```

- まず**衝突/周を減らす**。ぶつからなくなれば、交代とリカバリーの時間が消えて、平均ラップが縮む。
- 次に、**速い人の周を学習データに足して**速度を上げる。速度のゲインでは上がらない。
- ToFガードは安全のための床(下限)として使う。タイムは下がるので、常にONにするかは計測して決める。

## 7. 既知の問題

- **Jetsonは電池で動いている。** 2026-10-10〜11 の電源断(収集中・学習中)は電池切れだった。
  - 学習・夜間の作業の前は、充電するかAC電源にする。
  - 学習は各エポックの終わりに `last.pth` を保存する。止まったら、同じ引数に `--resume` を付けて `tools/train.py` を実行すると、続きから再開する。
- コントローラ基板の再起動(強い加速のときの電圧低下とみられる)。ライブ画面に「基板の再起動」が出る。
- 走行のログを消すと、その後のシーンの時刻の基準が変わる。解析の時刻は、そのときのファイルから計算し直す。
- 加速度センサーは ±8G で頭打ち。強い衝突は実際より小さく見える。

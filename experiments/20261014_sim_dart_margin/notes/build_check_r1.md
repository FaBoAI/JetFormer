## 1. やり方(準備の段の道具を使わない計算)

ブラウザの試しのシーンの記録(frames.jsonl・session.json)は準備の段で消されていたので、残っているもので作り直しました。

1. **記録の操作の作り直し**: 付け替えの道具が記録の状態から出した先生のきれいな操作(`smoke/browser/D*/relabel_work/*.json` の clean_actions)に、
   sidecar の乱しの予定(`events`: 始まり・終わり・舵のかたより・速さの倍率)を自分で足した。これを **収集器が書いた元の正解**(`relabel_backup/*.npz` の future_actions。
   付け替えの道具とは無関係に、ブラウザ → 収集器で作られたもの)と比べ、**600 フレーム × 10 個の PWM が 0 µs で一致**(D1・D3 とも)。作り直しは記録そのもの。
2. **物理**: ベストラップの `lib/app_emulation.mjs`(元。今日の写しではない)→ ユーザーの dist と同じ sim-core.js(sha256 `aaeb2379…`)。
   記録の操作を開始から連続周回で再生(開いたループ)。
3. **先生**:
   - fast: ベストラップの `sim/dist/rl/` の features.mjs・policy_forward.mjs・policy_weights.mjs を自分で組み立てた(`rl-teacher-bestlap.js` と同じ順。前回の行動だけ外から渡す)
   - margin: modes の `rl/runtime/mode_runtime.mjs` の **createModeTeacher そのもの**(mode 'line'、c0 = +0.3、c_v = 1.0、`line_r2/policy.json`)。前回の行動は `extra.applied` で渡す
   - 前回の行動は protocol どおり(乱した成分は適用した操作を方策の単位に戻した値、ほかは先生の値)
   - 再生の状態で出した先生の操作と、付け替えの道具が記録の状態で出した操作の差: **D1 6.2e-13・D3 9.4e-13**(Node とブラウザの最後の桁の差)
4. **正解**: 分かれ(fork・単周の initialState・経路の回し)を使わず、**連続周回の sim を開始から t まで記録の操作で進め、そのまま先生だけで 60 フレーム**(O(N²))。
   最初の 10 個を正解、60 フレームで 衝突・ゲートの外し(sim の数えが止まったまま R 上の s が 2.019 m 進む)・すき間 < 2 cm を「立て直せない」とした。
   比べたフレーム: D1 154(6 フレームおき + 乱しの始まり・終わりの前後 + 最後の 5)、D3 170(同じ + t = 568〜589 の全部)。

## 3. 遅延と時刻の約束(確かめた筋道)

- 記録(連続試験、RC 教師、制御遅延 0): フレーム t の初めにカメラ・ToF・IMU を s_t で取り、先生が s_t で操作 ã_t を出し、sim が s_t → s_{t+1}。
  収集器は vehicle[t] = PWM(ã_t)、`future[t,k] = vehicle[t+1+k]`(`dataset_recorder.py` の finish)。`pose_pre_action` = s_t、`state_post_action` = s_{t+1}。
- 評価(遅延 1・先読み 1): 画像 t の予測 P_t の `chunk[0]` が、遅延の待ち行列でフレーム t+1 の操作(s_{t+1} → s_{t+2})になる(`control-delay.js`・`jetformer_policy.py`)。
- 付け替え: `future[t,0]` = π(s_{t+1}、前回 = ã_t)。s_{t+1} は ã_t を適用した本当の状態 = `state_post_action[t]`。上の 2 つと合っている。

## 4. 見つけたこと

### 4.1(直すこと)D3 の試しのシーンは、最後に **本当にゲートを外している**。build.md の説明と deviations.md 7 の理由は誤り

- 受け入れた D3 の試し(k = 1、session b8cd589e)を再生すると、**フレーム 584 でゲート 3(経路の 4 番目)の線を横 0.666 m(半幅 0.65 m の外)で横切り、sim は数えていない**。
  乱し(565〜577、+0.197 rad)のあと、乱しなしの先生がわずか 1.6 cm 外を通った。記録の終わり(フレーム 600)でも route_index は 3 のまま。
  先生だけでその先を 240 フレーム走らせても、ゲート 3 は一度も数えられない(s が 22 m 進んでも止まったまま)。
- build.md 6.1 の「外で横切ったあと曲がりで線の手前に戻り、内側で横切り直して sim が数えた」は、このシーンには当てはまらない。数え直し(lap_audit)の「外側の横切り 1 回」は正しく、本当の外しだった。
  deviations.md 7(合否を「s が 2.019 m 止まる」決まりだけにした)はこの例を理由にしているが、この決まりでは **シーンの最後の約 0.5 秒の外しは見えない**(止まりが 1.66 m のまま記録が終わる)。
- 学習への影響: **D1・D3 では無い**。付け替えの 60 フレームの判定が t = 576〜589 を「立て直せない」として外している(独立の計算でも同じ 14 フレーム。t ≤ 575 からは先生がゲート 3 を正しく通る)。
  ただし **付け替えを書かない D2 では、こういうフレームが学習に残る**。
- 直し方(記録の段で): ① build.md 6.1 / 6.4 の 5 と deviations.md 7 の説明を直す。② `verify_dart_collection.py` で「外側の横切りのあと、そのゲートが記録の終わりまでに数えられなかった」を
  「終わりの外し」として数えて報告する。③ D1・D3 はそのまま受け入れてよい(付け替えが外す)が、外したフレームの数を記録の報告に書く。
  ④ D2 は `relabel_dataset.py --mode check` の立て直せないフレームが 0 でなければ、取り直す(次の k は無いので同じシーンの取り直しは同じ結果になる → そのシーンの該当フレームの future_valid を落とすか、
  シーンを外して deviations.md に書く)。

### 4.2(報告に書くこと)乱しが「前回の行動」の入力を通って正解に少し入る

- 先生の観測には「前回の行動」があり、protocol は「乱した成分は実際に適用した操作」と決めている。乱したフレームの次の正解を、前回の行動だけ「先生のきれいな操作」にしたものと比べた
  (全フレーム。`R/build_check_r1/prev_effect.mjs`):

| | 乱したフレームの次 | 乱しの向きへの寄り(舵の PWM) | 乱しの大きさ | 割合 | 乱しの向きに寄る割合 |
|---|---|---|---|---|---|
| D1(T_fast) | 92 | 平均 **+16.0 µs**(中央値 19.0、90% 点 23.4、最大 31.8) | 96.9 µs | 約 17% | 87% |
| D3(T_margin) | 143 | 平均 **+31.5 µs**(中央値 32.2、90% 点 48.2、最大 79.4) | 176.4 µs | 約 18% | 98% |

- つまり、乱れた直後の正解は、先生の「本当の戻し」より乱しの向きに 2 割ほど寄っている(先生の方策が前回の行動になめらかにつながるように学習しているため)。
  正解はそれでも記録の乱し入りの操作から大きく戻している(98 µs・178 µs)。決まりどおりで、ブラウザで記録した先生も同じ計算なので **誤りではない**。
  ただ、JetFormer は前回の行動を見ない(`--no-command-input`)ので、この 2 割は画像から読めない「正解のゆれ」になる。報告の限界に書く。時間があれば「前回の行動 = 先生の値」の付け替えとの比べが考えられる。

### 4.3(気をつけること)DAgger で使うとき

- `relabel_scene.mjs` は「乱したフレーム」を `info.dart.noise` からしか取らない。DAgger の再生(JetFormer が運転したフレーム)に印が無いと、先生の「前回の行動」が
  JetFormer の適用した操作ではなく先生自身の値になる。R3 の確かめ(乱していないフレームの次の正解 = 記録の操作)が落ちるので見逃しはしないが、DAgger をするなら
  再生の差し込みモジュールが JetFormer の区間に印(例: `info.dart.noise` に相当する印)を付けること。

### 4.4(細かいこと)60 フレームの判定は、先の方で外すゲートを見逃しうる

- 「止まり 2.019 m」は、分かれの走りの終わり近く(約 1.5 秒より後)で外したゲートは数えない。今回の D3 では境目がはっきりしていて(t = 575 は通る、576 は外す)影響は無かった。

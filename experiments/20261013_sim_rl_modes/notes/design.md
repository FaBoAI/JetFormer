## 1. 前提(確認済みの事実。数字は understand_rl.md / understand_ui.md から)

- **環境**: ベストラップの作業の `RlEnv`(停止から 20 秒の連続周回、ユーザーの `sim-core.js` そのもの、高速版はビット単位で同じ)。
  PPO は 64 環境で 5,300〜5,800 steps/s、1,000 万ステップ約 30 分、メモリは学習側 0.65 GB + ワーカー 4 × 130 MB。
- **観測**(features.mjs、79): 参照ループ R(26.12 m)への射影と先読み 16 点、19 本のレイ(10° おき、3 m、全障害物)、車体と全障害物の最小距離 d_min、
  目標ゲートの along/lateral、速さ・舵角・ヨーレート・前回の行動・μ。**v3 コース専用**。
- **今の方策は 1 本の線しか走らない**: 記録の 60 条件で線の違い 1.0 cm(教師 0.39 cm)。広い開始からも 3 m で同じ線に戻る(1.9 cm)。
  観測の R を ±10 cm 以上ずらすと 16/16 で衝突。柱を足すと 6 か所中 4 か所で衝突。舵を端に 0.2 秒固定する乱れで 50%、0.4 秒で 30% しか生き残らない。
- **学習なしでできるばらつき**: 開始をアプリの範囲いっぱい(ゲート 0〜32・±0.3 m・±25°)に広げても 93% が走り切る。速さの上限 4.0〜2.0 m/s で完走
  (1 周目 8.4〜13.8 秒)だが、2.5 m/s 以下ではすき間が 1〜4 cm に減る。チェックポイント 7 つを混ぜると線の違い 4.9 cm。
- **すき間の上限**: 奥の直線(ゲート 21〜25)は 5 cm のすき間で動ける横の幅が 0.18〜0.36 m、取れる最大のすき間は **14 cm**(s ≈ 18、x −2.3, z −2.45)。
  ほかの区間は 5 cm のすき間で 0.5〜1.9 m の幅。黒シートの近道では R が内側の柱に 4〜7 cm まで寄る(左に 0.5 m の余地)。
- **物理**: 加速 = min(6, μg, (目標−v)/0.4)、減速はいつも 1.2 m/s²、舵の速さ 1.2 rad/s、ヨーレートは μg/|v| で頭打ち、**摩擦円はない**(縦と横は別々)。
  確認 r1: 選んだ方策は舵の速さ 0.9〜1.0 rad/s・ブレーキ ≤ 1.0 で衝突。r2(物理のランダム化 500 万)は 39 条件中 36 で完走するが、1 周目 8.337 秒・すき間 2.27 cm。
- **sim の周の扱い**: ゲートを外すと、次の周でそのゲートの線を窓の中で越えるまで数えない。連続周回で 33 ゲートを通ったのに黒シートを横断していないと
  `required_crossing_missing` で**回が終わる**(600 フレームにならない = 記録に使えない)。
- **ブラウザの記録**: RL は `./rc-speed-controller.js` の差し込み口(`speed-rc`、連続周回で唯一使える教師)から入れる。JetFormer の index.html の
  import map で `./_jf/rl/teacher.js` に差し替える(非ループバックの Firefox で確認済み)。教師は snapshot の**写し**だけを受け取る(状態に触れない)。
  行動の `info` は収集器の `simulation/frames.jsonl` の `action_info` に残り、集約後も残る(確認済み)。収集器にはフレームごとの有効・無効が無い。
  `context.teacher`(metadata)はシーンの間で同じでないと集約できない。1 シーンの記録は Jetson の Firefox で約 60 秒 + ZIP 約 10 秒。
- **空き容量** 約 25 GB。ブリッジの集約は空き 20 GiB + 元の 2 倍を要求するので、JetFormer の側でシーン ZIP をまとめて取り込む。

```
          │ teacher.js: createRcTrainingTeacher → mode_runtime.createModeTeacher(world, config, …)       │
          │ sim-rl.js:  モードの選択欄・モードごとの設定・JetFormer の収集プランの実行係                  │
          └───────────────────────────────┬───────────────────────────────────────────────────┘
                                             │ シーン ZIP(frames.jsonl の action_info.jf に印)
          ┌───────────────────────────────┴───────────────────────────────────────────────────┐
          │ JetFormer: data/sim_rl/modes/<key>/(登録簿)・/api/sim/rl/*・まとめて取り込み・学習除外・タグ │
          │ シミュレーター タブのカード「強化学習モード」                                                │
          └────────────────────────────────────────────────────────────────────────────────────┘
```

- **試験した走り = 記録する走り**にするため、方策の計算・観測の包み・シールド・乱しの予定・経路の形は全部 `mode_runtime.mjs` の中で決め、
  Node の試験(元の sim-core.js を動かす)とブラウザの教師で同じファイルを使う。乱数は `config.seed` とフレーム番号だけから作り、時刻を使わない。
  同じフレームで 2 回呼ばれても同じ答えにする(アプリは止めたときに同じフレームで `action()` を 2 回呼ぶことがある)。
- ベストラップの作業のファイルは**写して使う**(`experiments/20261013_sim_rl_modes/snapshot/`、元のパスと sha256 を `SNAPSHOT.json` に)。
  features.mjs・reference_loop.mjs(.json)・policy_forward.mjs は**バイト単位で同じ写し**(ブラウザと Node の観測を同じにするため)。
  その作業が後でファイルを変えても、こちらは写しのまま(変わったことに気づいたら deviations.md に書く)。

## 4. 各モードの設計

### 4.1 最速(`fastest`)

- **方策**: ベストラップの作業の最終の検証済みの方策。決め方(記録の段で 1 回だけ判断し、記録の報告に書く):
  1. その作業の `rl/best/main/policy.json` の sha256 が `7c43cb53…53ee` から変わっていて、その作業のあとの確認の報告(`rl_check_r*.md` など)が
     その方策を「本物・合格(valid)」と書いていれば、それを使う。
  2. そうでなければ `7c43cb53…`(main 種 1・1,000 万ステップ、停止から 8.092 秒・走りながら 7.656 秒、REC60 60/60、確認 r1 で本物)を使い、
     「確認 r1 で確かめた方策を使った」と書く。
  - r2(物理のランダム化、`5f6f5716…`)は**最速には使わない**(その作業の手順で「選べる」に入らない: 1 周目 8.337 秒・すき間 2.27 cm)。
- **ばらつきの作り方**: 開始をアプリの範囲いっぱい(ゲート 0〜32・±0.3 m・±25°)に広げる(Halton 列で重ならない)。Node で前もって走らせ、
  走り切らない開始(約 7%)はプランから外す。最速は「1 本の速い線」なので、線のばらつきは小さいのが正しい(物差しは報告だけ)。
- **合格**: 方策の同一性(sha256)、元のコアで停止から 1 周がその作業の報告の値と 1e-6 秒以内で同じ、REC60 60/60、ブラウザと Node の操作が 1e-6 以内で同じ。

### 4.2 絶対壁にぶつからない(`no_wall`)

**目標**: 標準の物理で全周の最小すき間 ≥ **8 cm**(教師の REC60 は 3.2 cm、最速は 5.7 cm)、物理をずらした試験でも**衝突 0**・すき間 ≥ **5 cm**、
摩擦円の内側の無理のない加減速。遅くてよい(停止から 1 周 ≤ 12 秒)。

- **8 cm の理由**: 奥の直線で取れる最大のすき間は 14 cm(車体の向きを R にそろえたとき)。8 cm なら中心から ±6 cm の誤差まで許される。
  10 cm では ±4 cm で、物理のずれ(遅延・舵の遅さ)の中ではきびしすぎる。5 cm(ずらした物理)は ±9 cm。
- **学習**(Node、高速版):
  - 初期化: r2(物理のランダム化 500 万、`rl/r2-dr-s11/checkpoints/step_005013504.pt`)。ずれに強い方策から始める。読めなければ main 種 1。
  - 報酬: 進みと終了の罰はベストラップの v2-gatecap のまま。なめらかさを 3 倍(舵 0.06・速さ 0.03)。
    横の頭打ち `−0.2·max(0, ρ_req − 0.9)`、**摩擦円** `−0.2·max(0, ρ_comb − 0.9)`(ρ_comb = √(a_long² + a_lat²)/(μg)、実際の加減速と v·ヨーレート)、
    すき間の壁 `d_min < 0.12 m で −0.25·min(4, ((0.12 − d_min)/0.04)²)`、**d_min < 0.075 m で終了 −10**(すき間を約束にする)。
  - 物理のずれ(DR-NW-train): 舵の速さ 0.75〜1.9 rad/s・ブレーキ 0.65〜2.3 m/s²・時定数 0.25〜0.6 秒・加速の上限 3〜6・μ ×0.82〜1.12・
    遅延 0/1/2 フレーム(4:4.5:1.5)・舵のゲイン ±7%・前進ゲイン ±5%・**摩擦円あり 30%**・舵の白色雑音 σ 0.03 rad(回の半分)・標準の物理 15%。
    観測は標準の物理の値で作る(方策は今の物理を知らない。r2 と同じ約束)。摩擦円は高速版の文字列の置き換えで入れ、
    確認 r1 の `own_physics_r1.mjs`(frictionCircle)と 1e-9 で一致することを試験する。
  - 開始: 半分はアプリの範囲(ゲート 0〜32・±0.2 m・±15°、開始のすき間 ≥ 12 cm)、半分はゲート 0 の近く。
  - 予算: パイロット 100 万 → 本番 1,000 万(約 32 分)。合格しなければ 1 回だけ作り直し(1,000 万まで)。
- **安全シールド**(走行中。`shield.mjs`、Node とブラウザで同じ):
  - 特権の情報を使う: world の全障害物の正確な形、物理の config、今の状態(snapshot の x, z, yaw, speed, steering)。教師なので使ってよい
    (JetFormer の生徒はカメラから学ぶ)。
  - 方策の指令を 1 フレーム、そのあと**予備の操縦**(最大すき間の線を 0.6 m 先で追う舵 + ブレーキ)で 24 フレーム(0.8 秒)先まで、
    sim-core と同じ式の写しで進め、小区間ごとの正確なすき間を測る。**標準の模型で ≥ 7 cm**、**悲観の模型**(舵の速さ 0.85・遅延 1・ブレーキ 0.8)で ≥ 5 cm なら
    そのまま使う。だめなら候補(予備の操縦、舵 5 段 × 速さ {0, 方策の値})から合格のうち方策に一番近いもの、どれも合格しなければ予想のすき間が一番大きいもの。
  - ブレーキは 1.2 m/s² しかないので、「止まって逃げる」はできない。予備の操縦は「広い所へ舵を切りつつ減速」で、それが 0.8 秒の間に安全かを毎フレーム確かめる形
    (「安全な予備の操縦が続けられる指令だけを通す」= 予備の方策つきのシールド)。
  - シールドが替えた指令もそのまま正解ラベル(安全な操作なので)。`info.jf.sh = 1` で印を付け、割合を報告する。標準の物理で 5% 以下を合格の条件にする
    (シールドが運転しているのでなく、RL の方策が主に運転していること)。
  - 学習中はシールドを使わない(計算が 50 倍になるため)。すき間の約束と DR で、シールドがほとんど要らない方策を作る。
- **合格**(試験は 340 回、全部シールドあり): N60(標準の物理 60)・STD 2・r2 の条件の表 GRID(標準 + 39 条件)のうち DR-T の範囲の中の 34 行 × 単周・連続 = 68・R200(DR-T で乱数 200)・FC10(摩擦円 10)で
  **衝突 0**、標準の物理で最小すき間 ≥ 8 cm、ずらした物理で ≥ 5 cm、停止から 1 周 ≤ 12 秒、R200 の 95% 以上で 1 周以上の有効な周、
  N60 で ρ_req > 1 と ρ_comb > 1 のフレームが各 2% 以下、シールドの作動 5% 以下。シールドなしの値も並べて報告する(判定しない)。
- **画面の言い方**: 名前はユーザーの呼び方のまま「絶対壁にぶつからない」。数字は「N 回の試験で衝突 0・最小すき間 X cm」と書き、「絶対」とは言い切らない
  (sim の中の試験の結果であり、実車の保証ではない)。

### 4.3 離脱復活(`recover`)

**目標**: 走っている途中で押されたり、わざと線を外したりしたあとに、**ぶつからずにコースへ戻る**操作を集める。乱しの操作は学習に使わない。

- **学習**(Node、高速版。初期化 main 種 1・1,000 万):
  - 乱し(学習): 舵のパルス 35%・わざと外す 25%・ブレーキ/踏み込み 15%・**状態のキック 25%**(`sim.peek().state` を書き換え: 向き ±0.1〜0.5 rad・
    横 ±0.05〜0.25 m・速さ ×0.5〜1.3)。最初の出来事 1〜4 秒、終わってから 1.5〜4 秒あけて次。強さは記録の 0.5 倍から始め、最初の 300 万ステップで 1.2 倍まで。
  - **差し込んだ行動のステップは方策の損失から外す**(その行動は方策が選んだものではない)。価値の学習には使う。キックは行動ではないので外さない。
  - **ゲートを外しても終わらない**(−3 の罰)。観測の目標ゲートは「仮想のゲート番号」(sim の route_index が進まないまま s が目標ゲートの s + 0.30 m を越えたら、
    s から決めた次のゲート)。外していなければ今と同じ値(base79v)。衝突・停止・逆走・黒シート違反は −10 で終わる。
  - 開始: ベストラップの分布 70% + アプリの範囲いっぱい 30%。予算: パイロット 100 万 → 本番 1,000 万(約 32 分)。
- **記録の乱し**(ブラウザでもできる行動の差し込みだけ。`config.seed` とフレーム番号から決まる):

| 種類 | 割合 | 弱 | 中 | 強 |
|---|---|---|---|---|
| 舵のパルス(左右どちらか、速さは方策のまま) | 45% | 3〜5 フレーム、最大舵角の 0.6〜0.8 | 6〜9、0.8〜1.0 | 10〜12、1.0 |
| わざと外す(横へ d ずらした線を pure pursuit で T 秒) | 40% | d 0.12〜0.20 m、0.4〜0.7 秒 | 0.20〜0.30、0.6〜1.0 | 0.30〜0.40、0.8〜1.2 |
| ブレーキ / 踏み込み(舵は方策のまま) | 15% | 10〜15 / 6〜10 フレーム | 15〜25 / 10〜15 | 25〜30 / 15〜20 |

  - 強さは出来事ごとに 3 つから等確率(プランで固定もできる)。最初の出来事 2〜4 秒、終わってから 2〜3.5 秒あけて次、18.5 秒以降は始めない(1 シーン 4〜6 回)。
  - **始めてよい位置**: 先 2 m の区間の幅(すき間 5 cm)が 0.60 m 以上で、黒シートの区間(s 5.9〜8.0)と奥の直線(s 14.6〜19.3)の外。
    だめな位置なら、許される最初のフレームまで遅らせる。「わざと外す」は使える幅が足りない側には外さず、d_min < 10 cm になったら途中で終える。
    (黒シートの横断を外すと回が終わり記録に使えない。奥の直線の乱しは物理的に戻れない。)
- **学習から外す決まり**(取り込みで行う。6 章): 差し込んだフレーム [ps, pe) は `info.jf.l = 0`。観測 k の正解は k+1〜k+10 の操作なので、
  **k ∈ [ps − 10, pe − 2] の future_valid を false、mode を 0** にする。pe − 1 以降(正解が立て直しの操作だけ)は残す。
  乱しの間の観測(外れていく絵)も、正解が立て直しなら学習に使う。1 シーンで外すのはおよそ 15〜35% のフレーム。
- **「戻った」の定義**: 同じ方策の乱しなしの線(8 回の平均 ē_y(s)・ψ̄(s))に対し、|e_y − ē_y| ≤ 0.10 m かつ向きの差 ≤ 0.15 rad が 15 フレーム続いた最初のフレーム。
  立て直しの時間 = そのフレーム − pe。成功 = 3.0 秒以内に戻り、次の出来事(または終わり)まで衝突・停止・逆走なし。ゲートの外しは別に数える。
- **合格**: 乱しつきの 100 回で 90 回以上が有効(600 フレーム・衝突 0。衝突した回は記録では捨てて替える)、出来事の成功 95% 以上、立て直しの時間の中央値 ≤ 1.2 秒・90% 点 ≤ 2.5 秒、
  出来事 ≥ 3.5 回/シーン、外すフレームの割合 0.10〜0.40、状態のキック(向き 0.3 rad・横 0.15 m)の生き残り ≥ 90%(今の方策は 69%・86%)、
  乱しなしで停止から 1 周 ≤ 9.0 秒・REC60 60/60。

### 4.4 経路いろいろ(`line`)と 速さいろいろ(`speed`)— 1 つの条件付きの方策 cond

- **目標の線**: `e*(s) = c(s) × ρ(s)`。ρ(s) は R に沿った**使える幅の表**(`room_table.json`、5 cm おき): 全障害物とのすき間 ≥ 8 cm で動ける左・右の幅を、
  ゲートの窓(±0.65 − 0.12 m)と黒シートの車幅の条件で切り、±0.5 m の最小フィルター・σ 0.4 m でなめらかにして 3 cm 引いたもの。
  奥の直線では ±数 cm、ほかでは ±0.3〜0.5 m になる(区間の幅に比例してずらすので、狭い所でぶつけない)。
- **形 c(s)**(シーンごとに 1 つ): 一定 c0(左寄り・右寄り・中央)・イン `a·tanh(κ̄(s)/0.5)`・アウト(その逆)・レイトエイペックス(曲率を 0.5 m 後ろへずらす)・
  アーリーエイペックス・ランダム(1.5〜3 m おきの節を通るスプライン)。κ̄ は R の曲率の ±0.5 m の平均。
- **観測**(97): features.mjs の 79 + 先読み 16 点の e*(s+Δs)/0.5 + (e_y − e*(s))/0.5 + 速さの倍率 c_v。
- **行動**: 速さの上限 V_cap = 4.5·c_v(a1 の意味が c_v で変わる)。
- **報酬**: ベストラップの v2-gatecap + 線の追従 `−0.08·min(1, ((e_y − e*)/0.10)²)`。
- **学習**: main 種 1 から(1 層目を 0 で広げる = 初めは今と同じ走り)、c_v は 40% が 1.0・60% が U(0.5, 1.0)、形は 一定 30%・イン/アウト 各 12%・
  レイト/アーリー 各 8%・ランダム 30%。予算: パイロット 100 万 → 本番 2,000 万(約 65 分)。
- **記録**: 経路いろいろ = c_v 0.9〜1.0 で 15 シーンに 一定 左 2・右 2・中央 1、イン 2、アウト 2、レイト 2、アーリー 1、ランダム 3。
  速さいろいろ = 目標の線は R(c0 = 0)で c_v ∈ {1.0, 0.875, 0.75, 0.625, 0.5} を各 3 シーン。
- **合格(経路)**: 60 回で 57 回以上有効、すき間 ≥ 3 cm、追従の誤差 中央値 ≤ 5 cm・95% 点 ≤ 12 cm、6 つの形(左 0.8・中央・右 0.8・イン・アウト・レイト)の線が
  左右で平均 20 cm 以上・イン/アウトで平均 10 cm 以上違い、どの 2 つも 1 m 以上続けて 8 cm 以上違う所がある、横ずれのばらつき VM3 ≥ 8 cm、中央の線で 1 周目 ≤ 10 秒。
- **合格(速さ)**: 60 回で 57 回以上有効、すき間 ≥ 3 cm、停止から 1 周が c_v 1.0 < 0.75 < 0.5 の順に長く、差 ≥ 3.0 秒、
  平均の速さが c_v とともに増え(段ごとに 0.05 m/s 以上)、速さの 95% 点が上限 4.5·c_v + 0.05 m/s 以下、s でそろえた速さのばらつき ≥ 0.4 m/s。
- **代わり**(cond が合格しないとき): 速さ = 学習なしの速さの上限 {4.5, 4.0, 3.5, 3.0, 2.5} を no_wall(合格していれば)か最速の方策に掛けたものを同じ試験に。
  経路 = ベストラップの作業のチェックポイント(REC60 全部有効・すき間 ≥ 3 cm のもの)をシーンごとに替える「線の混ぜ合わせ」を同じ試験(線の違いは VM3 だけ)に。
  どちらも合格したときだけ出し、代わりの方法と書く。
- **注意(生徒への影響)**: 経路や速さは画像だけでは決まらない「隠れた条件」なので、同じ場所の絵に違う操作のラベルが付く(多峰)。
  JetFormer(L1)は混ぜると平均・中央に寄ることがある。状態の網羅を広げる効果は大きいが、学習で混ぜる割合は学習の側で決める(条件はフレーム 0 の `p` に残す)。

### 4.5 障害物よけ(`obstacle`)

- **配置**: 柱(円柱、半径 5〜10 cm・高さ 30 cm)と箱(カプセル、長さ 15〜35 cm・半径 5 cm・高さ 25 cm)を 1〜4 個、s で 2 m 以上離して、
  **最速の方策のふだんの線の上 ±15 cm**(いつもの線をふさぐ)に置く。黒シートの区間・奥の直線・開始の前後 1.5 m・ゲートの柱の近くには置かない。
  **通り道の保証**: 障害物の s ±0.6 m のどこでも、すき間 ≥ 8 cm で通れる横の範囲が 10 cm 以上残り、ゲートの窓と重なること(Python と Node の両方の検査器)。
  組: 学習(回ごとに乱数、10% は障害物なし)・検証 30・試験 50・記録 30(種の範囲を分ける)。
- **観測**(95): 79 + 足した障害物のうち近い 4 個(3 m 以内・左右 100° 以内)の車の座標系の位置・半径・有無。10° おきのレイは細い柱を見逃すため。
- **報酬**: v2-gatecap + 足した障害物とのすき間 < 8 cm の罰 `−0.1·min(4, ((0.08 − d)/0.04)²)`。予算: パイロット 100 万 → 本番 1,500 万(約 55 分。柱 20 本で 1 フレーム +42%)。
  `prepareGeometry` のキャッシュは上限つきにする。
- **ブラウザ**: 仮想コース `default-obstacles`(Default の scene.js・world.js + JetFormer の重ね描き)。重ね描きが `physics.disks`・`segments` の**同じ配列**の中身と
  メッシュ(橙・テクスチャなし)を入れ替えるので、次のリセットで物理・センサー・RL の観測に入る(確認済み)。配置はシーンの前(リセットの前)に変える。
  `WORLD_VERSION` は `'<元>+jf-obstacles-v1'`(障害物なしのデータと混ざらない)。配置 ID はフレーム 0 の `p` と `info.jf`、報告の `world_hash` に残る。
- **合格**: 試験の 50 配置 × 2 開始 = 100 回で 95 回以上有効、すき間 ≥ 3 cm、1 周目の中央値 ≤ 10.5 秒、障害物なしで停止から 1 周 ≤ 9.0 秒。
  最速の方策の同じ試験の結果を並べる(判定しない)。

## 6. 学習から外すフレーム(取り込み)と、フレームの印

- 教師が返す操作: `{steering, speed, info: {jf: {v:1, m, f, ph, l, ev, cl, es?, sh?}}}`(1 フレーム 200 バイト程度)。フレーム 0 だけ `p`(シーンの条件の全部:
  経路の形・c0/a・c_v・配置 ID・乱しの強さ・seed・方策の sha256 の先頭)。`steering_pwm`・`throttle_pwm` の鍵と `/` で始まる文字列は使わない。
- `context.teacher`(metadata)はモードの中で全シーン同じ: `{schema: 'jetformer-sim-rl-teacher/v1', id: 'jf-rl-<key>-v1', mode, policy_sha256, obs_wrapper,
  features_version, reference_loop_sha256, speed_cap_mps, runtime_version, catalogue_sha256, obstacle_set}`。
- **取り込み**(`import_archive` と `/api/sim/rl/import` の両方。「JetFormerへ送る」の道も同じ関数を通る): ZIP の `context.teacher.schema` を見て RL のデータなら、
  `frames.jsonl`(単体の `simulation/frames.jsonl` と集約の `simulation/scenes/<シーン>/frames.jsonl` の両方)の `action_info.jf.l` を読み、
  `l = 0` の操作 j を正解に含む観測 k(k+1 ≤ j ≤ k+10)の `future_valid[k] = False`・`mode[k] = 0` にする。`vehicle_valid` は変えない。
  カードに `label_mask = {schema: 'jetformer-sim-label-mask/v1', horizon: 10, masked_frames, per_scene}` と `rl = {mode, teacher_id, policy_sha256, scenes, minutes,
  obstacle_layouts, calibration}`。`training_frames`・`mode_frames` を数え直す。
- `mode = 0`(未設定 = 学習しない)を使うので、シーンタブへの展開・シーンからのデータセットの作り直しでも除外が残り、シーンタブで区間として見える。
- 同じ仕組みで、ほかに学習させたくない操作(例: 将来の別の乱し)も `l = 0` で表せる。シールドの置き換えは `l = 1`(安全な操作)。

## 8. ジャンル(JetFormer)と、実車の走行への影響

- **決定: 全モードともジャンル 8(シミュレーター)のまま。新しいジャンルは作らない。`data/modes.json` は変えない。**
  モードの区別は タグ(`simulator`・`sim-rl`・`sim-rl-<key>`、+ `sim-safe`・`sim-recover`・`sim-line`・`sim-speed`・`sim-obstacles`)と
  データセット名 `sim-rl-<key>_<YYYYMMDD-HHMM>`・シーン名 `rl-<key>-<train|val>-<NN>`、フレーム 0 の条件 `p` で行う。
- 理由: (1) アプリの収集器は mode_id 0〜5・8 しか受け付けない。(2) シミュレーターの推論アダプターは num_modes ≤ 9(ID 0〜8)しか受け付けず、
  ジャンルを足すとシミュレーターで評価できない。(3) 実車の走行・収集の画面に、実車のデータが無いジャンルが並ぶ。(4) ベストラップの作業と同じ扱い。
- **実車の走行で選ぶジャンルへの影響**: 実車ではふつう 4(高速走行)・5(低速走行)を選んで走らせる。シミュレーターのデータはジャンル 8 の埋め込みだけを
  学習させるので、**4・5 を選んだときの走り方は、直接には変わらない**(重みを共有する部分を通して、画像の見方・立て直しの操作などが間接に効くだけ)。
  モードの走り方(安全・最速など)を実車でジャンルとして選べるようにするには、学習のときにタグからジャンルを付け替える(例: sim-rl-no_wall → 5、
  sim-rl-fastest → 4)必要があり、シミュレーターの走り方を実車のジャンルに混ぜることになる。これは sim→実車の別の実験なので、この作業ではしない。
- 学習から外すフレームは mode 0 なので、シーンタブでは「未設定」の区間として見える。

## 9. 画面

### 9.1 シミュレーターのページ(`/sim/c/default/`、`/sim/c/default-obstacles/`)

- 「反復試験・教師データ収集」の「教師の走行」の下に **「強化学習モード」** の選択欄: 「使わない(RC加速教師)」+ 登録簿のモード

  物理とセンサーを記録の条件(`RC_COLLECTION_PLAN[0]`)にそろえる → アプリにリセットさせる。`speed-rc` の選択肢の文字を「強化学習: <モード名>」に変える。
- モードごとの小さな設定(シーンの条件。プランの実行係も同じ欄を使う):
  経路いろいろ = 形(自動・左寄り・右寄り・中央・イン・アウト・レイトエイペックス・アーリーエイペックス・ランダム)と強さ、

  絶対壁にぶつからない = シールドの作動の数(表示だけ)。「自動」は `config.seed` から決める(Node の試験と同じ)。
- 上の帯に「RL: <モード名>」。`?rl=<key>` で開くとそのモードを選んだ状態。連続試験・収集の間は選択欄を使えなくする。

### 9.2 シミュレーター タブ(JetFormer の画面)

- カード **「強化学習モード」**(「シミュレーターを開く」の下): モードごとに 名前・説明 / 状態(合格・不合格(参考)・学習中 N%・未学習) /
  停止から 1 周・走りながら / 衝突(「N 回の試験で衝突 0」)/ 最小すき間 / モードの主な数字(立て直しの成功率と時間、線の追従、速さの範囲、障害物の通過率) /
  集めたデータ(分)/ 「このモードで開く」。数字は RL の側が**元の sim-core.js** で試験した `eval.json`(JetFormer は表示するだけ)。
- **収集プラン**: 表(行 = モード、欄 = 分。既定は合格したモード 5 分・ほか 0、1 モード 20 分まで)+ train/val の割合 + シード →
  「プランを作って開く」(新しいタブ `/sim/c/<course>/?rlplan=<id>`)。プランは JetFormer(Python)が作る: 分 × 3 シーン、開始は Halton 列、
  シーンの条件(形・c_v・乱しの強さ・配置)を割り振り、Node で前もって走らせた結果で走り切らない開始を替える。
- ページの実行係: 「開始」で 換算の確認 → 自動ラベルの印・ジャンル 8 → シーンごとに モード・条件・配置を設定 → アプリ自身の「連続試験」を 1 条件で押す →
  結果を読み、進み具合を JetFormer に送る → モードが終わるたびに JetFormer がそのモードのシーン ZIP を 1 つのデータセットに取り込む(学習除外・タグ込み)。
- 進み具合(何シーン目・衝突で外れた数・取り込み済み)をカードにも出す。「シミュレーターで集めたデータセット」の一覧にモードの印(タグから)。

## 12. 合否と出し方(protocol.json の要約)

- 判定は `protocol.json` の `acceptance.<key>` の全部(判定する項目)。数字は元の sim-core.js(摩擦円とキックは高速版の写し)、すき間は小区間ごとの正確な距離。
- 出し方: 合格 → 登録簿に「合格」。優先 1 で不合格 → 「不合格(参考)」として出し、数字をそのまま見せる。優先 2・3 で不合格 → 出さない(代わりの方法が合格すればそれを出す)。
- 記録の判定(モードごと): 見本のシーンの 90% 以上が有効(600 フレーム・衝突 0)、再生(記録した操作を Node の元のコアで)で姿勢の差 ≤ 1e-6 m、
  全フレームに `info.jf`、換算の確認、取り込み後のジャンル 8・タグ・学習除外のフレームが決まりどおり、モードの VM の判定。
- 画面の判定: 8080(非ループバック)の Firefox で、選択・読み込み・1 シーンの記録・プランの作成と実行・取り込み・カードの表示、未選択で今と同じ動き、
  ブラウザと Node の操作の一致(1e-6)。

## 13. 危ないところと対策

| 危ないところ | 対策 |
|---|---|
| no_wall が 8 cm を取れない(奥の直線で ±6 cm、物理のずれ) | すき間の約束 + DR + シールド。1 回の調整と 1 回の作り直し。だめなら「不合格(参考)」で数字を出す(基準は変えない) |
| シールドがよく作動して走りがぎこちない | 判定に作動 ≤ 5%。シールドなしの値も報告 |
| ブラウザと Node で Math の結果がわずかに違い、シールドや乱しの判断が分かれる | 判定は記録したシーンの再生と sim の結果で行う。予想との一致は報告だけ。操作の一致は 1e-6 の試験(1 フレームずつ同じ snapshot を与える) |
| 離脱復活の乱しで黒シートを外す・奥の直線でぶつかる | 始めてよい位置の決まり、わざと外す側の幅の確認、d_min < 10 cm で打ち切り、Node で前もって走らせて替える |
| cond が線に従わない・遅くなる | 追従の重みの調整範囲。代わりの方法(上限・混ぜ合わせ) |
| 障害物の配置で通れない所ができる | 2 つの検査器で通り道を保証。試験・記録の配置は前もって Node の方策で走らせて確かめる |
| 記録の換算がずれる(シミュレーターだけで学習したモデルが読み込まれている) | 記録の前と途中で 1442/1498 ±5 µs を確かめ、外れたら止める |
| lock big が長く空かない | 記録はユーザーが Mac からでも同じプランでできる。見本は優先 1 から |
| メモリ(スワップなし 8 GB) | RL 2G・Firefox 2500M・GPU 3G の上限。RL と Firefox を同時にしない |

## 16. 手順の固定と逸脱

- `protocol.json` を固定し、sha256 を `protocol.sha256` に書いた(`sha256sum -c protocol.sha256` で確かめられる)。

# シミュレーター(CourseLab)を JetFormer の管理画面から使う

`~/sim/course-simulator-complete.zip` のシミュレーターを、JetFormer の管理画面(`http://<Jetson のアドレス>:8080`)の
**「シミュレーター」タブ** から使えるようにしました。いまのコースは **Default**。コースのデータ(ZIP)をアップロードすると、
ほかのコースも選べます。

- 描画(WebGL)は Mac などのブラウザ、学習済みモデルの推論(onnxruntime の CPU 版)とデータの保存は Jetson の「ブリッジ」が行います。GPU は使いません。
- シミュレーターのファイルは変えていません(JetFormer が写しを `data/sim/releases/` に持ち、その写しも変えません)。
- 詳しい記録: `design.md`(設計)・`implementation.md`(実装)・`verify.md`(本番の画面での確認)・`review.md`(レビューと修正)。

---

## 1. 使い方(シミュレーター タブ)

Jetson ではもう **導入と準備が済んでいます**(版 `20261013-144013-6f610dd5`、Python 環境 `data/sim/venv`)。ふだんは 3 からです。

1. **シミュレーター本体**: 新しい版の ZIP を Jetson の `~/sim/` に置くと、タブの一覧に出ます →「導入」。
   全ファイルを ZIP の `COMPLETE-MANIFEST.json` と照合して入れます(取り込み済みの大きなデータ `dataset-downloads/` は入れません)。
   版が 2 つ以上あると「この版を使う」で切り替えられます。本体(Python・JS)はブラウザからは入れられません。
2. **Python 環境(ブリッジ用)**: 「準備する」(数分・約 290 MB)。JetFormer の Python 環境には何も入れません。
3. **ブリッジ**: 「起動」(2 秒ほどで「動作中」)。使い終わったら「停止」。「ログ」で中身を見られます。
   - 管理画面(jetformer-web)を再起動するとブリッジも止まります。自動では起動しないので、このボタンを押してください。
   - シミュレーターのページの上の帯にある「ブリッジを起動」でも起動できます。
4. **シミュレーターを開く**: 「コース」と「モデル」を選んで「新しいタブで開く」。
   - アドレスは `http://<Jetson>:8080/sim/c/<コースID>/`(モデル付きなら `?model=<学習結果の名前>`)。`http://<Jetson>:8080/sim/` は既定のコースを開きます。
   - ページの上の帯: 「← JetFormer に戻る」・**コースの切り替え**・ブリッジの状態・モデルの読み込みの進み具合。
   - ページは自動でブリッジに接続します(「ローカルブリッジ URL」は JetFormer 経由なので変えられません)。
5. 走らせ方はシミュレーターそのままです(「コントローラー」で 手動運転 / 経路追従デモ / 学習済みAI を選んで「▶ 評価を開始」)。

## 2. モデルを読み込む

- **タブから**: 「シミュレーターを開く」の「モデル」で JetFormer の学習結果を選んで開くと、ページが JetFormer の `bundle.zip` を取り、
  シミュレーターの「ZIPからモデルを読み込む」に自動で渡します。帯に「読み込み完了」と出たら、コントローラーを「学習済みAI / ONNX」にして評価を始めます
  (モデル B で約 4〜8 秒)。
- **手で**: シミュレーターの「モデルZIP / ONNXを読み込む」から、JetFormer の「学習」タブなどで取った `bundle.zip` を選んでもかまいません。
- 対応するのは **TransFuser軽量型(jetformer_v0)** だけです。ほかの種類は一覧で選べないようになっています。
- モデルを読み込むと、シミュレーターが収集の「走行ジャンル」をモデルの走行モードに合わせます(モデル B なら 5)。シミュレーターの既定 8 で集めたいときは、収集の前に選び直してください。

## 3. コースを選ぶ・追加する

### 3.1 いま選べるコース

| コース | 中身 | 描画 |
|---|---|---|
| **Default(標準コース)** | v3 `indoor-course-eval-3-turf-board-removed`(world hash `0a464384`)。芝生の白い板を取り除いた評価コース | シミュレーター本来の描画 |
| 旧コース v2(芝生の白い板あり) | `indoor-course-eval-2-shortcut`(`547d7e80`)。シミュレーターに同梱のスナップショット | シミュレーター本来の描画 |
| アップロードしたコース | タブの「コースを追加」で登録したもの | ふつうは JetFormer の簡易描画(下記) |

- 「既定にする」で `/sim/` が開くコースを変えられます。アップロードしたコースは「削除」できます(Default と同梱のものは消せません)。
- RC加速教師・軌跡最適化教師・高速改善教師と「20分・60シーンの収集条件」は Default 専用です(ほかのコースでは隠れます)。

### 3.2 コースの ZIP の作り方(いちばん簡単な方法)

1. タブのコース一覧で、元にしたいコース(Default など)の「書き出し(雛形)」を押して ZIP を取ります。
2. 中の `physics-world.json` を編集します(壁・柱・路面・ゲート列・開始位置。下の表)。
3. `course.json` の **`world_version` と `id` を新しい名前に変え**、`world_hash` の行を消します(world_version はコースごとに一意。データセットや学習の記録がこれでコースを見分けます)。
4. ZIP にして(フォルダーごとでもよい)、タブの「コースを追加(ZIP をアップロード)」で選びます。登録されると、world hash が計算されて一覧に出ます。

### 3.3 ZIP の形式

受け付ける形式は 2 つです。

- **JetFormer 形式**: `course.json` + `physics-world.json` + 任意の `assets/*.jpg|png`
- **シミュレーターのスナップショット形式**(`qa/course-snapshots/` と同じ): `manifest.json` + `physics-world.json` [+ `scene.js`・`world.js`]

`course.json`(`//` のあとは説明です。実際のファイルには書かないでください):

```jsonc
{"format": "jetformer-sim-course/v1",
 "name": "自宅コース 1",                 // 1〜40 文字
 "world_version": "home-course-1-v1",    // 英数字・._- の 80 文字以内。コースごとに一意
 "id": "home-course-1",                  // 任意。英小文字・数字・- の 2〜48 文字(なければ world_version から作る)
 "description": "…",                    // 任意(200 文字まで)
 "visual": {                             // 任意(見た目だけ。衝突には関係しない)
   "floor_texture": "carpet.jpg",
   "surface_textures": {"turf": "turf.jpg"},
   "colors": {"rail": "#f2f2ee", "rail_alt": "#b81627", "curtain": "#1b1b1d", "post": "#1b2023", "gate": "#bcc2c2", "floor": "#bcc1c3"}}}
```

`physics-world.json`(シミュレーターの `makeWorld(buildCourse().physics)` と同じ形。単位は m・rad):

| 項目 | 中身 | 決まり |
|---|---|---|
| `segments` | 壁(線分)`{a:[x,z], b:[x,z], radius, height, kind}` | kind は `rail`・`curtain`・`gate-foot`。radius 0〜0.5、height 0〜5。2000 件まで |
| `disks` | 柱 `{x, z, radius, height, kind}` | kind は `post-foot`・`post`・`gate-post`。4000 件まで |
| `surfaces` | 路面 `{id, x, z, w, d, mu}` | 1〜64 件。mu(摩擦係数)0.01〜3。id 例: `carpet`・`turf`・`blue-mat`・`shortcut` |
| `bounds` | 範囲 `{minX, maxX, minZ, maxZ}` | 幅・奥行き 60 m まで。座標は ±50 m |
| `route` | ゲートの列 `[[x, z], …]` | 3〜400 点。bounds の内側 0.2 m。最後の点を最初の点に重ねない(自動で戻る) |
| `requiredCrossings` | 必ず通る開口 `{id, surface_id, minX, maxX, z, direction}` | 8 件まで。開口は路面の中。direction は 1 か -1 |
| `spawn` | 開始位置 `{x, z, yaw}` | bounds の内側。壁や柱から 0.10 m 以上(0.23 m 未満は警告) |

- テクスチャ: `assets/` に英小文字の名前の `.jpg`・`.png`(1 枚 8 MiB・4096 px まで・16 枚まで。保存し直して使います)。
  標準のテクスチャ `carpet.jpg`・`carpet-normal.jpg`・`turf.jpg`・`turf-normal.jpg`・`blue-pad.jpg`・`black-mat.jpg` はそのまま名前で使えます。
- ZIP は 64 MiB・展開後 128 MiB・256 ファイルまで。値は丸めずに確かめ、だめなときは理由の一覧を日本語で出します。
- 同じ world_version で形が同じなら「登録済み」、形が違うとエラー(world_version を変えてください)。同じ id のアップロード済みコースは「置き換える」にチェックを入れると置き換えます。
- **アップロードした JS(scene.js・world.js)は実行しません。** シミュレーターのページは JetFormer と同じアドレスで動くので、JS は実車の走行 API まで呼べてしまうためです。
  アップロードしたコースは JetFormer の **簡易描画** で表示します(衝突物をその高さのまま描くので ToF には正しく写りますが、部屋・LED 矢印・テープなどがないので、
  カメラ画像は Default と同じになりません。カメラを使う AI の評価は Default と直接は比べられません)。
  例外として、導入済みの版の Default・同梱コースの JS と **2 つそろって完全に一致する** ときだけ、その JS で本来の描画をします。

## 4. 集めたデータを JetFormer に入れる

```
シミュレーターの「データセット収集」(● 収集を開始 → 収集終了・ZIP作成)
   └→ Jetson のブリッジが data/sim/runtime/datasets/<収集ID>/ に ZIP を作る
        ├→ (A) タブの「シミュレーターで集めたデータセット」→「JetFormer に取り込む」  … ZIP をそのまま取り込む(送り直さないので速い)
        └→ (B) シミュレーターの「JetFormerへ送る」→「選択したZIPを送信」              … 送り先は自動でこの Jetson の JetFormer
             ↓
   JetFormer の data/datasets/<名前>/(タグ simulator)→「データセット」タブ・「学習」で使える
   + 「シーン」タブにもシーンとして展開される(ds-<名前>-0001 …)
```

- 取り込みの進み具合は「処理状況」に出ます。取り込んだら、タブの「削除」でブリッジの作業フォルダーを消してかまいません(JetFormer のデータセットは残ります)。
- **経路追従デモや AI で走らせたデータを学習に使うときは、収集の前にシミュレーターの「AI・デモの操作も学習対象にする」にチェックを入れてください。**
  入れないと「学習に使えるフレームがありません」で取り込みを断ります(手動運転のデータは不要です)。短すぎる収集も同じです(最後の 10 フレームは未来の値がないため)。
- 「収集終了・ZIP作成」は走行中に押せない時間があります。一時停止してから押すと確実です。
- 20 秒シーンの集約(「20秒シーンをまとめてZIP作成」)を使うときは、集約の ZIP を作り終えてから元のシーンを消してください。

## 5. 制限・注意

- **AI で走らせられるのは同時に 1 つのタブだけ** です。ブリッジは全体で 1 つ、モデルも 1 つ。2 つのページで同時に AI 評価をすると、モデルの「前の出力」の記憶が
  互いに消し合って結果が正しくなりません。別のページでモデルを読み込み直すと、もう一方は「モデルが変わった」エラーになります。収集も同時に 1 つだけです。
- ブリッジが異常終了したとき(10 分間に 3 回まで自動で起動し直します)や管理画面を再起動したときは、モデルを読み込み直してください。収集中のシーンは失われます。
- 推論は Jetson の CPU で動きます。学習など重い処理が動いていると遅くなります(Jetson 自身のブラウザで開くと描画も Jetson で行うので、さらに遅くなります。Mac からの利用がおすすめです)。
- コースを削除すると、そのコースを開いているページは次の読み込みから動きません。
- 電源が切れたり強制終了したりしたあと: 作業途中のファイルは次の起動のときに片付き、置き換えの途中だったコースは前のものに戻ります。
  導入・準備・コースの登録は、中身をディスクに書き切ってから「済み」にします。
- JetFormer には認証がありません(LAN の誰でも操作できます)。これは前からで、今回の統合で広げてはいません。
- まだ確かめていないこと: ユーザーの **Mac のブラウザ** での一連の操作(Jetson の Firefox では確認済み。Mac 向けの部分は自動テストで確認)。
- レビューで直した Python のコードは、次に jetformer-web を再起動したときに有効になります(学習・収集・走行が動いていないときに `sudo systemctl restart jetformer-web`)。

## 6. 困ったとき

| 症状 | 対処 |
|---|---|
| ページに「ブリッジが動いていません」 | タブの「ブリッジ」→「起動」(またはページの帯の「ブリッジを起動」) |
| ブリッジが「失敗」 | タブの「ログ」で理由を見る。メモリが足りないときは重い処理が終わってから起動 |
| モデルが読み込めない | 種類が jetformer_v0 か確かめる。ブリッジが再起動していたら、ページを開き直す |
| コースが登録できない | 一覧に出た理由のとおりに physics-world.json・course.json を直す。world_version を変える |
| 取り込みで「学習に使えるフレームがありません」 | §4 のチェックを入れて集め直す |
| Python 環境が「要対応」 | 「準備し直す」 |

データの置き場所: `data/sim/`(本体の版・venv・ブリッジの作業場所 runtime/・logs/bridge.log)、`data/sim_courses/`(アップロードしたコースと既定の設定)。
コード: `jetformer/sim/`。テスト: `tests/test_sim_*.py`(CPU だけ)。

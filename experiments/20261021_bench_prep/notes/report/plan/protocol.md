## 2. 1 日目の候補の選び方(決定的)

### 2.1 安全の門(gates)

desk_bench.json の値から、この式で計算し直します。全部に合格した候補だけを出します。

| 門 | 合格 |
|---|---|
| engine_ok | true(TensorRT と FP32 の差 ≤ 2.5 µs) |
| sanity_ok | true(10/10 の AI 走行のフレームで NaN なし・範囲内) |
| trt_p99_ms | ≤ 10.0 |
| steer_amp_ratio | 0.80 以上 1.25 以下 |
| l1_best_us | B より 10 µs 以上悪くない(差 < 10.0) |

- 欄が無い・null・NaN は不合格です(理由 `missing:<欄の名前>`)。
- desk_bench.json の gates_pass と食い違えば、この式の結果を使い、deviations.md に書きます。
- B は門に掛けません。ただし B の engine_ok か sanity_ok が false なら、10/23 は走らずにユーザーに知らせます。

### 2.2 選ぶ手順

1. 門に落ちた候補を外します。
2. **SLOW が門に通れば、必ず入れます**(R1 の課題への対策)。SLOW が落ちて、slow-s1 が通れば、それを SLOW の枠に入れます。
3. 残りの 4 家族(arch・robust・ens・weight)から、門に通った中で `desk_key` がいちばん良い 1 本ずつを入れます。これで最大 5 本です。
4. 5 本に足りなければ、残りの門に通った候補(同じ家族の 2 本目を含む)を `desk_key` の順に足します。
5. それでも足りなければ、その本数で走ります(3.2 の並び)。0 本なら、1 日目は B だけの基準(カード 1)です。

### 2.3 desk_key(同点の扱い)

| 順 | 鍵 | 向き | 丸め |
|---|---|---|---|
| 1 | l1_interv_us | 小さい方が先 | 小数第 1 位 |
| 2 | r1_app_thr_diff_us | 大きい方が先(R1 の手前で人より緩める) | 小数第 1 位 |
| 3 | l1_best_us | 小さい方が先 | 小数第 1 位 |
| 4 | \|ln(steer_amp_ratio)\| | 小さい方が先(人の振れ幅に近い) | 小数第 3 位 |
| 5 | trt_p99_ms | 小さい方が先 | 小数第 1 位 |
| 6 | id | 文字の順(ASCII) | — |

- 丸めた値が同じなら同点で、次の鍵で決めます。6 番目で必ず決まります。null はその鍵で最後です。
- 1 番目を介入の集合にした理由
  - 保留の L1 は、どの作り方でも約 49 µs です。差は人の揺れの床(約 31 µs)と実用の目安(10 µs)より小さいです。
  - 介入の集合は、ずれた状態からの立て直しを見ます。実車の失敗に近い場面です。

### 2.4 危なさ(risk)

| risk | 条件 |
|---|---|
| high | steer_amp_ratio が 0.85 未満か 1.20 超、または r1_app_thr_diff_us < −20(人より 20 µs 以上強く R1 に入る) |
| low | high でなく、0.90 ≤ steer_amp_ratio ≤ 1.10・r1_app_thr_diff_us ≥ −10・trt_p99_ms ≤ 8.0、かつ 10/21 に足した新しい方策のコードを通らない |
| mid | それ以外。新しい方策のコードを通る ENS は、数が low でも mid |

- r1_app_thr_diff_us が無いときは mid です(ほかの条件で high なら high)。
- bench_candidates.json の risk は、この規則で付けます。

## 3. 走る順番

### 3.1 決まり

1. SLOW の枠を **C1** にします。
2. ENS が選ばれていれば **C2** にします。
3. 残りは risk の低い順(low → mid → high)、同じ risk の中は desk_key の順です。
4. SLOW か ENS が入っていなければ、空いた先頭から 3 の順で詰めます。

### 3.2 理由

- SLOW は、今の課題(R1 の衝突)への直接の対策です。いちばん知りたい比べです。
  - 最初の B のすぐ後に置くと、電池と時間のずれの影響が最も小さくなります。
  - 途中で中止になっても、この比べは残ります。
- ENS は机上で一番良い候補です。SLOW と ENS を前半に置き、2 つとも近い B(1 回目と 2 回目)で挟みます。
- 後半は危なさの低い順です。危ない候補を後ろにすると、ぶつかって車が傷んでも、失う比べが少なくなります。
- 最後は必ず B で閉じます。

|---|---|
| 5 | B・C1・C2・B・C3・C4・C5・B |
| 4 | B・C1・C2・B・C3・C4・B |
| 3 | B・C1・C2・B・C3・B |
| 2 | B・C1・B・C2・B |
| 1 | B・C1・B・C1・B |
| 0 | B・B・B(カード 1) |

- 詰めて空いた時間は予備にし、ブレーキの測定を削らずに済ませて、早めに終えます。

### 4.2 1 ブロックの手順(約 8 分)

1. 画面でモデルを選びます。モデルの名前がブロックの run と同じか、声に出して確かめます。
2. 「説明」欄に書きます。
   - `bench=real_bench_20261023 day={date} block={block} cand={id} model={run} battery=#__ V_before=__ V_after=__ check=__ memo=`
   - check には「点検する」の結果を書きます。
3. その日に初めて走るモデルは、車輪を浮かせて dry run 30 秒(HOLD 0・infer_ms)。
4. 走行を始め、CH3 で AI 側へ。慣らしの周を走ります(数えません)。
5. そのまま数える周に入ります。
   - 画面の AI 時間が「数える時間 + 1 分」を過ぎたら(240 秒なら 5:00)、次の直線で CH3 で人に戻して止めます。
   - 多く走った分は、道具が数えません。
6. 走った後の電圧を測り、記録(シーン)の説明を直して V_after に書きます。シーンの説明は、走ったあとも直せます。

- 時間の内訳: 選択と説明 1 分・車輪を浮かせた確認 0.5 分・AI の時間 約 5 分・交代や置き直しの余裕 1 分・電池の交換 0.5 分。

### 4.3 慣らしと数える区間

- 慣らしは同じ走行の中で走ります。別の記録にはしません。
- **数える区間** = その走行で AI のフレームにある R1 の起点の K 番目(ta_K)の 0.5 秒前から、AI の時間の合計が 240 秒になるまで。
  - K = 3: そのモデルが実車で初めて走るとき(最初の半端な周+2 周)。B も実車は初めてなので、10/23 のブロック 1 は K = 3 です。
  - K = 2: 2 回目以降(1 周)。
  - 途中で切れて走り直したとき(Jetson・基板・電源の理由)は、走り直しを K = 2 として、AI の時間を足して 240 秒までです。
- 数えた周が 12 未満のブロックは「足りない」の印を付けます。順位の表には出しますが、上位 2 本には選びません。
- **B が回れないとき**(ブロック 1 の慣らしで、R1 か LH を 2 周続けて回り切れない)
  - ステア 1.3 で、慣らしからやり直します。そのときは、その日の全ブロックを 1.3 にします。
  - 1.3 でもだめなら、比べる走りをやめます。10/18 plan.md 5.2 の 6 のとおり first_trial の基準を取り、ブレーキの測定に進みます。
- **候補が回れないとき**: そのブロックを止めて「回れない」と記録し、次へ進みます(ステアは変えません)。

## 8. 実車の指標(記録から計算する)

- 元: `data/labels/<ログ>.json`(tools/label_events.py)と course_passes(tools/offline_rl.py)。
- 数えるのは、数える区間の中の AI のフレームだけです。

### 8.1 定義

| 名前 | 定義 |
|---|---|
| 衝突 | 水平の加速度 ≥ 2.5 G(0.6 秒以内は 1 件。センサーの異常と上下の bump は除く)で AI のとき |
| 強い衝突 | 衝突のうち ≥ 4.0 G |
| 周 | 数える区間の中で、AI のフレームにある R1 の起点 ta(1 周に 1 回の大きな右ヘアピンの入口)。周 j = [ta_j − 0.5 秒, ta_{j+1} − 0.5 秒)。最後の周は、tg + 2.3 秒が区間の中にあるときだけ数える |
| 基板の再起動の周 | 周あたりの指標から除く(分子も分母も)。reboots_per_4min だけに数える |

### 8.2 ブロックごとの指標

| 欄 | 中身 |
|---|---|
| laps_counted | 数えた周の数 |
| **incidents_per_lap** | **主の指標。失敗/周 = (衝突 + 衝突のあとでない失敗の交代(stuck・preemptive))÷ 周。** after_collision の交代は衝突と同じ出来事なので足さない |
| collisions_per_lap | 衝突 ÷ 周 |
| strong_collisions_per_lap | 強い衝突 ÷ 周 |
| r1_strong_per_pass | R1 の強い衝突([ta − 0.5, tg − 0.3]、tg が無ければ ta + 3.5)がある通過の割合 |
| r1_coll_per_pass | 同じ窓の衝突がある通過の割合 |
| gm_coll_per_pass | GM の衝突が [ta, tg + 0.3] にある通過の割合(tg がある通過だけ) |
| de_coll_per_pass | DE の衝突が [tg − 0.3, tg + 2.3] にある通過の割合(tg がある通過だけ) |
| failure_takeovers_per_lap | 失敗の交代(after_collision・stuck・preemptive)÷ 周 |
| takeovers_per_lap | 人の交代(CH3 で AI → 人)全部 ÷ 周(参考) |
| lap_median_s / lap_best_s | ラップ = ta_{j+1} − ta_j(あいだがずっと AI で、交代・戻し・HOLD・再起動が無い周)の中央値と最小。衝突した周も入れる |
| clean_laps / clean_lap_share / clean_lap_median_s | きれいな周(AI だけ・衝突なし・失敗の交代なし・リカバリーなし)の数・割合・ラップの中央値(5 周未満なら出さない) |
| lapcounter_clean_median_s | 参考: 画面と同じ LapCounter の clean の中央値・ベスト |
| t_r1gm_median_s | 区間の時間: tg − ta(R1 の起点 → 緑マットの出口) |
| t_rest_median_s | 区間の時間: ta_{j+1} − tg_j(DE → 次の R1 の起点) |
| r1_entry_erpm_median / r1_entry_ge6200_share | R1 の進入 eRPM(ta の手前 0.4 秒の最大)の中央値と、6,200 以上の割合 |
| reboots_per_4min / holds / infer_ms_p99 | 基板の再起動 ÷(AI の時間 / 240 秒)・HOLD の数・推論の時間の 99% 点 |
| cap_brake_in_r1_turn | B+上限だけ: R1 の旋回中のブレーキの数(0 でなければならない) |

### 8.3 90% 信頼区間

- 周を並びのまま 3 周ずつのかたまりにし、かたまりを復元抽出するブートストラップ(10,000 回、百分位)。
  - 種: 10/23 は 20261023、10/24 は 20261024。
  - 差は、候補と基準をそれぞれ別に抽出して取ります。走行が複数あるときは、走行ごとに抽出してから合わせます。
- 数が 0 の率は、ポアソンの正確な片側 95% の上限(3.0 ÷ 周)も出します。

### 8.4 電池の減りと時間のずれ(B の 3 回で補正)

1. **基準** = その日の B の全ブロックの周を合わせたもの。
2. **電池の直し(ラップだけ)**
   - 周の電圧 V = V_before + (V_after − V_before) ×(その周の真ん中までの AI の時間 ÷ 走行の AI の時間)。
   - その日の B の全部の周で、lap = a + b·V を最小二乗で当てます。
   - b の 90% 区間が 0 を含まず、b < 0(電圧が高いほど速い)のときだけ、全部の周を lap − b·(V − B の周の V の平均)に直します。
   - 電圧の書き忘れが 1 つでもあれば、直しません。
3. **時間のずれの判定**: B の最初と最後のブロックで、ラップの中央値の差が 0.3 秒を超えるか、失敗/周の差の 90% 区間が 0 を含まなければ「ずれあり」。
4. **ずれありのとき**: 候補のブロックの基準を、前後の B のブロックの値から、ブロックの番号で直線で内挿します。
   - 1 日目: ブロック 2・3 は B1 と B4、5〜7 は B4 と B8 のあいだ。
   - 2 日目: 2・3 は B1 と B4、5・6 は B4 と B7、8 は B7 と B9。
- 順位には直した値を使います。直す前の値も並べて出します。

## 9. 順位の決まり

### 9.1 点数と交換の目安

- **S = Δ失敗/周 + λ × Δラップの中央値(秒)**(Δ = 候補 − 基準。小さいほど良い)
- **λ = 1.0**: 「失敗を 0.1 回/周減らすためなら、ラップが 0.1 秒遅くなってもよい」。
  - **ユーザーはまだ決めていません。これは既定の仮定です。**
  - 10/23 の夜の判定までにユーザーが別の値を決めたら、その値を使い、deviations.md に書きます。
  - 報告には、λ = 0.5 と 2.0 でも順位が変わるかを並べます。

### 9.2 1 日目 → 上位 2 本(T1・T2)

- **出られる候補**: 数えた周が 12 以上・「安全で中止」でない・「回れない」でない。Δ失敗/周の 90% 区間の下端が 0 より大きいもの(はっきり B より悪い)は除く。
- **並べ方**: S を 0.05 刻みに丸めた値の小さい順。同じなら (1) R1 の強い衝突/通過が小さい、(2) 失敗の交代/周が小さい、(3) 先に走った、の順。
- **R1 の枠**: 次が全部そろえば、2 位を入れ替えます(R1 の課題を 2 日目に確かめるため)。
  - 上位 2 本のどちらも、R1 の強い衝突/通過が B の半分以下でない。
  - B の R1 の強い衝突が 3 回以上ある。
  - 出られる候補の中に、R1 の強い衝突/通過が B の半分以下のものがある → その中で S が最も小さいものを 2 位に。
- 1 日目の上位 2 本は「B より良い」とは言いません。選ぶための目安です。

### 9.3 2 日目 → ベストモデル

- **判定は 10/24 の周だけで行います。** 10/23 の周で選んだので、10/23 の値は良い方に偏るからです。10/23 の値は並べて出します。
- **B より良い**と言える条件(全部)
  1. S の 90% 区間の上端 < 0。
  2. Δ失敗/周の 90% 区間の上端 ≤ +0.10(安全が悪くない)。
  3. R1 の強い衝突/通過の点推定 ≤ B。
  4. 「安全で中止」なし。
  5. 基板の再起動/4 分が B より 1 回以上多くない。
- 2 本とも満たせば、S(0.05 刻み)の小さい方。同じなら失敗/周の小さい方 → risk の低い方 → T1。
- **満たす候補が無ければ「B のまま」**です。S の点推定がいちばん小さい候補は「次に試す候補」として書きますが、良いとは言いません。
- ベストモデルを推奨のモデル(data/drive_recommended.json)にするかは、ユーザーが決めます。エージェントは変えません。
- B+上限は、ベストモデルの順位とは別に「初見」として出します。

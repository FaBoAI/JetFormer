## 4. 比べ方(protocol の要約)

- 1 日目: B・C1・C2・B・C3・C4・C5・B。1 ブロック = 1 モデル・AI 側で数える 240 秒。慣らしは数えない(初めてのモデルは R1 の起点 3 つ目から、2 回目以降は 2 つ目から)。
- 2 日目: B・T1・T2・B・T2・T1・B(T1・T2 = 1 日目の上位 2 本)。A 案なら、リカバリー v2 の置き試し → B+上限 → B を足す。B 案なら、T1・T2 のブロックを 300 秒にする。
- 設定は 1 日のあいだ同じ。変えるのはモデルだけ。
- 主の指標は失敗/周。点数 S = Δ失敗/周 + λ × Δラップの中央値(λ = 1.0 は**既定の仮定**。ユーザーは未決定)。
- 90% 信頼区間は 3 周のかたまりのブートストラップ(10,000 回)。
- 電池の減りと時間のずれは、その日の B の 3 回で直す。
- 2 日目の判定は 10/24 の周だけで行う。条件を満たす候補が無ければ「B のまま」。

## 12. 限界(決まった文。結果に合わせて足す)

- 周が少ない: 1 日目は候補 1 本 約 20 周。失敗/周は ±0.34 回/周、ラップは ±0.44 秒、R1 の強い衝突/通過は ±0.18 の幅があります(10/10 の first_trial からの見込み)。3 割より小さい差は見えません。
- 1 日目の上位 2 本は、1 日目の周で選んだので、1 日目の値は良い方に偏ります。だから判定は 2 日目の周だけで行います。
- 1 回の走行の中の周は、互いに似ます(3 周のかたまりで抽出しても、走行ごとの違いは 1 日目には測れません)。
- 1 日 1 本の走行の候補は、その時間・その電池の影響を受けます。B の 3 回で直しますが、B の 3 回だけで分かるずれは直線までです。
- コース・照明・取り付けが 10/10 と違えば、10/10 の数(R1 の 6/9 など)とは直接比べられません。
- 速さと安全の交換の目安 λ = 1.0 は、ユーザーが決めていない既定の仮定です。
- 「差が見えない」は「差が無い」ではありません。
- 机上の L1 と実車の結果の対応は、候補 5〜8 本ぶんだけで、言えるのは向きの傾向までです。
- 速度上限の B+上限は約 20 周の「初見」で、カード 2(B 22・B+上限 43・B 22)の代わりにはなりません。

## 13. 道具との対応(bench_report.py を書く人へ)

- 指標の定義は **protocol.json の metrics が正**です。tools/section_scorecard.py の今の数え方(10/21 の docstring)とは、次が違います。bench_report.py で protocol に合わせるか、合わせられなければ deviations.md に書いてください。

| protocol | section_scorecard(10/21) | 合わせ方 |
|---|---|---|
| 周 = 数える区間の中の AI の R1 の起点(周 j = [ta_j − 0.5, ta_{j+1} − 0.5)) | 周相当 = ジャイロの向きの変化 ÷ 360° | 通過(起点)の一覧から数え直す |
| 衝突は数える区間の AI の衝突を全部数える | 「立て直し中」(失敗の交代 → 戻してから 2.5 秒)の衝突は別に出す | 別に出した分も足す |
| 失敗/周 = 衝突 + stuck・preemptive の交代 | (無い) | 交代の分類から足す |
| ラップ = 起点 → 次の起点(ずっと AI・交代・戻し・HOLD・再起動なし) | 起点 → 次の起点(5〜16 秒・ずっと AI・0.2 秒を超える途切れなし) | HOLD・交代・再起動で外す。5〜16 秒の枠は外さない(外すなら deviations) |
| 数える区間 = ta_K − 0.5 秒から AI の 240 秒 | その日の AI のログ全部 | 説明欄の block・cand と K で切る |
| 基板の再起動の周を除く | 再起動の数を出す | 周ごとに除く |

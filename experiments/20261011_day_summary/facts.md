## 1. JetFormer のモデル設計(`jetformer/model.py`、`docs/model_design.md`)

### 1.1 入力とトークン

| 入力 | 中身・正規化 | エンコーダ | トークン |
|---|---|---|---|
| カメラ | IMX219 を V4L2 直接で取り込み、224×224 RGB・30fps。ImageNet 正規化。走行時も学習データと同じ JPEG q92 を一度通してから入れる | ResNet-18(ImageNet 事前学習、avgpool・fc を除く)→ 512×7×7 → 1×1conv | 7×7 = **49** |
| ToF | VL53L9(STEVAL-VL53L9)の 42×54 ゾーン、**2チャネル**: 距離(mm/4000、0〜1、0=無効)と信頼度(0〜7 → 0〜1)。エンコーダの中で有効マスクを3チャネル目に足す | 小CNN 4段(32→64→128→256、stride 1,2,2,2) | 6×7 = **42** |
| IMU | ICM-20948 の直前 **10サンプル**(100Hz = 100ms)× [加速度/g 3軸、ジャイロ rad/s 3軸] | MLP(60→256→256) | 1 |
| 今の状態 | [(ステア µs−1500)/500、(スロットル µs−1500)/500、eRPM/20000(±3でクリップ)]。学習時は人の操作値、AI走行時は前フレームの予測(ゲイン前)。モデルB は操作値の2つを0にする(eRPM は残す) | MLP(3→256→256) | 1 |
| 走行ジャンル | one-hot(6: 0未設定・1〜3駐車・4高速走行・5低速走行) | 線形(埋め込み) | 1 |
| 出力用トークン | 学習可能 | — | 1 |

合計 **95トークン**。各トークンに学習可能な位置埋め込みと、モダリティ埋め込み(6種類)を足す。

### 1.2 融合と出力

- **Transformer Encoder 4層・256次元・8ヘッド**(FFN 512、pre-LN、dropout 0.1)で、全トークンを自己注意で融合。融合は**最終段の1回だけ**。
- 出力用トークン → LayerNorm → 全結合 → **ジャンル別の出力ヘッド**(6ジャンル分を1つの線形層でまとめて計算し、one-hot で該当ジャンルを選ぶ。TensorRT でも特別な処理が要らない)。
- 出力は **1〜10フレーム先(33〜333ms、約0.33秒)の [ステアリング, スロットル]**(正規化値。×500+1500 で µs)。
- 走行では `future_actions[k]` を「先読み」k+1 として1つ選ぶ(既定1、当日は主に3 = 0.1秒先)。ゲインはステア中心・スロットル中立(学習データで止まっているときの人の操作値の中央値。first_trial は 1443/1498µs、clean_driving は 1441/1496µs)を基準に掛ける。18:33 以降、速度のゲインは前進側にだけ掛ける。
- ジャンルの効き方の確認(机上の検証データ): ほぼ同じ画像に「高速走行 = 1600µs、低速走行 = 1400/1450µs」と教えると、ID を変えるだけで 1600/1601µs ↔ 1399/1449µs を出し分けた。

### 1.4 TransFuser との関係

TransFuser について一般に知られていること(Prakash・Chitta・Geiger「Multi-Modal Fusion Transformer for End-to-End Autonomous Driving」CVPR 2021、拡張版は IEEE TPAMI、実装 github.com/autonomousvision/transfuser):

- 入力は前方カメラ画像と、LiDAR 点群を鳥瞰図(BEV)のグリッドにしたもの。目標地点(GPS のターゲットポイント)も使う。
- 画像と LiDAR をそれぞれ CNN で処理し、**複数の解像度(4段)**で両方の特徴をトークンにして Transformer で融合し、各ブランチに戻す。
- 出力は自車座標の未来の**ウェイポイント**(GRU で予測)で、PID 制御器でステア・アクセル・ブレーキに変える。
- CARLA シミュレーターのエキスパートを模倣学習する。拡張版は深度・セマンティクスなどの補助タスクも学習する。
- (細部は版によって違う。動画で細部に触れる場合は論文で確認すること)

**同じところ**

- センサーごとに別のエンコーダで特徴を作り、トークンにして Transformer の自己注意で相互参照させる(カメラと距離センサーの幾何的な投影は使わず、注意で対応づける)。
- 模倣学習(未来の行動を L1 で当てる)で、1回の推論で複数ステップ先を出す。

**違うところ(JetFormer の設計判断)**

| | TransFuser | JetFormer v0 |
|---|---|---|
| 融合 | 4解像度の多段融合 | **最終段の1回だけ**(Orin Nano で30fpsを確実にするため) |
| 距離センサー | LiDAR(BEV グリッド) | **54×42 ゾーンの ToF**(カメラから5cm以内)。距離+信頼度+有効マスク |
| ほかの入力 | 目標地点(速度などは版による) | **IMU 100ms・今の操作値と回転数・走行ジャンル**をそれぞれトークンに |
| 出力 | ウェイポイント → PID | **行動そのもの**(10フレーム分のステア・スロットル)。自己位置が無い RC カーなので |
| 条件づけ | 目標地点 | **走行ジャンル**: トークン入力 + ジャンル別ヘッド(条件付き模倣学習 CIL の分岐ヘッド方式) |
| 画像 | より大きいバックボーン | ResNet-18、224×224 の1台 |
| 補助タスク | あり(拡張版) | なし(次の検討事項) |
| 学習データ・実行 | シミュレーターのエキスパート | **実車の人の運転**(当日 約7分〜15分)、Jetson 上で TensorRT FP16 |

### 1.5 学習の設定(`tools/train.py`)

- 損失: 未来10ステップ × 2 の L1(誤差の µs 表示は ×500)。AdamW(lr 3e-4、weight decay 1e-4)、コサイン減衰、バッチ64、GPU では FP16 混合精度。
- 色の揺らぎ(RGB ごとに 0.8〜1.2倍)。間引き(stride)3 = 10fps 相当。
- 操作値が100ms以内に無いフレーム・未来が揃わないフレーム・ジャンル未設定は使わない。シーン単位で学習/検証を分ける。
- 20:36 以降は、衝突の前後(既定は水平4G以上の1秒前〜2秒後)を学習から外す。clean_driving では 2.5G を使った。

### 3.2 「今の操作値をまねる」発見(14:25・14:56、`tools/evaluate.py`)

検証シーン 135449-0003(587フレーム)で、1〜10フレーム先の誤差を、**教師あり**(今の操作値 = 人の値。学習と同じ条件)と **自己入力**(今の操作値 = 前の予測。AI走行と同じ条件)で測り、「今の操作をそのまま続ける」と比べた。

| ステア誤差 µs(1フレーム先 → 10フレーム先) | 教師あり | 自己入力 | 今の操作を続ける |
|---|---|---|---|
| lowspeed(2シーン学習) | 66.5 → 89.1 | 68.2 → 89.3 | 20.0 → 157.4 |
| lowspeed_b(4シーン学習) | **36.1** → 105.4 | **64.7** → 100.1 | 20.0 → 157.4 |

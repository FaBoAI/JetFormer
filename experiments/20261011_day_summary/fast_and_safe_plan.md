## 0. 結論

**道筋は5段。①測れる状態にする → ②モデルの外の安全層で R1・GM・DE を守る → ③データで「遅く入って速く出る」を教える → ④後半の直線で速さを取り返す → ⑤学習で人の手本を超えにいく。**

- 衝突の 91% は R1・GM・DE の3か所で起きる。原因の確からしさは場所で違う。R1 は進入速度(グリップの限界)で根拠が強い。GM は低μ(芝+PTFE)で、もっともらしい。DE は「緑マットを出たあとも右へ曲がり続ける」走り方と速さで、仕組みは仮説。
- AI が人より遅いのは周の後半(直線とスイーパー)で、ヘアピンでは人と同じか速く見える(ヘアピンの比較は区間の境目の置き方に左右される)。だから **「ヘアピンは遅く入り、直線で速く」** すれば、衝突を減らしながら速くできる見込みがある。R1・GM・DE に速度上限をかけても、損は計算で 1周 +0.25秒ほど(推定)。ただし人並みに R1 を攻めるモデルでは、R1 の上限の損は最大 +0.3秒になりうる。
- 速度ゲインはモデルに打ち消される(raw ∝ gain^−1.13)。速さは「eRPM を見る閉ループの速度目標」か「モデルへのペース入力」で決める。
- **速さと安全は、一部で交換になる(5.1)。** ToF ガードの減速は、正しい警告での減速を含めると 1周 +0.3〜+0.8秒かかる(開ループ)。床が見えるのは約1.9m 先までなので、約2.9 m/s を超えると ToF だけでは止まり切れず、当たる強さを減らすだけになる。DE は人でも 3.0 m/s(6000 eRPM)を超えると当たる(1/23 対 10/37)。速くする施策は、DE の上限と区間を絞った減速と組で入れる。
- **1回の A/B/A(各 43周)で見えるのは、衝突/周の −40〜−50% 以上の差だけ。** 2週間の目標(−23%)は1回の比較では確かめられない。採否は地点ごとの指標で決め、目標は全走行を合わせた値と信頼区間で報告する(4.1)。

## 3. 施策の優先順位

並べ方の基準は4つ。(1) 自分たちのデータで仕組みと数字が見えているか(確度)、(2) 効果をコストで割った大きさ、(3) 失敗したとき安全側に倒れるか、(4) 後の段の前提になるか。

確度: **高** = 仕組みと数字が自分たちのデータでそろう。**中** = 仕組みは見えるが、閉ループでの効き方が未確認。**低** = 仮説や文献に頼る。
効果の基準は 006/007(衝突 1.17回/周、衝突なしの周 9.9秒)。施策どうしの効果は足し算にならない(R1 にはデータと上限の両方が効く)。006/007 は設定が混ざった走行(多くはスロットルゲイン 1.8〜2.0)なので、固定設定の基準では上乗せは小さく出る見込み。「〜になった場合」と書いた数字は上限の目安で、効果の予測ではない。

## 4. 実験の順番とゲート

### 4.1 共通のルール(ロードマップ 6.4 の走行カードに加える)

- 1走行 = 1設定・AI 側 4分以上。設定は固定(ステア 1.3・速度 1.0・先読み 3・ジャンル5・ガードは記録のみ・リカバリー v2 ON)。スライダーは動かさない。走行の前後に幾何チェック(`sensor_check.py`)。外れた試行は評価に使わない。
- **層とモデルを同時に変えない。** モデルを比べる走行(実車#1・#4)では、層はシャドー(計算と記録だけ)にする。層を比べる走行(実車#3)では、モデルを固定する。
- **層ごとに、その場所の指標で採否を決める。** R1 の上限は「R1 の強い衝突/通過」、GM の上限は「GM の接触/通過」、DE の層(上限+整形)は「DE の衝突/通過」で判定する。層は効く場所がおおむね別々なので、1回の A/B/A で層ごとの効果をある程度分けて見られる。ただし R1 の上限は GM への進入速度も下げ、GM 出口 → DE の連鎖もあるので、下流の場所の変化は上流の層の効果を含む。DE の上限と整形は分けられない。
- **1回の A/B/A で言えること(検出力)。** 基準 1.17回/周、A 44周(前後 22+22)・B 43周、片側 5%、ポアソン(`src/review/power_check.json`):

  | 比べたい差 | 検出力 | 検出力 0.8 に要る周(各条件) |
  |---|---|---|
  | 衝突/周 1.17 → 0.59(−50%) | 0.88 | 43 |
  | 1.17 → 0.70(−40%) | 0.69 | 約60 |
  | 1.17 → 0.86(−26%。安全層 v1 の見込みの悪い側) | 0.38 | 約150 |
  | 1.17 → 0.90(−23%。2週間の目標) | 0.30 | 約200 |
  | 衝突なしの周の割合 33% → 40% | 0.11 | 200周でも 0.39 |
  | R1 の強い衝突/通過 25% → 5% | 0.75(40通過) | 約50 |
  | R1 の強い衝突/通過 25% → 10%(2週間の目標) | 0.48 | 約100 |
  | DE の衝突/通過 55% → 25% | 0.80(40通過) | 約40 |

- **だから採否は地点ごとの指標(通過あたり)で決め、衝突/周は「悪くなっていない」ことの確認に使う。** 43周で言える「悪くなっていない」は、比(B/A)の点推定 ≤1.1 かつ上側 95% 限界 ≤1.5 まで(衝突が各 50件で率が同じでも、上限は 1.39)。それより厳しい「悪くなっていない」は 43周では判定できない。2週間・2か月の衝突/周の目標は、同じ構成の全走行を合わせた点推定と 90% 信頼区間で報告する。
- **ラップ**: AI の衝突なしの周の標準偏差は 0.16秒(8周)と小さく、各条件 15周あれば差の 90% 信頼区間は約 ±0.1〜0.2秒で、0.3秒の悪化は判定できる(標準偏差が 0.3秒でも ±0.18秒)。衝突なしの周が各 15周に届かないとき(衝突なしが 33% なら 43周で約14周)は、全部の完全な周(標準偏差 0.71秒、各 43周で ±0.25秒)と区間の時間で判定する。
- **片側の採否の規則**: 安くて安全側の層(R1・GM・DE の速度上限)は、地点の指標で差が出なくても、衝突/周とラップが悪くなっていなければ残し、次の走行の周を足して判定し直す(各 40通過の検出力 0.75 では、効いている層を4回に1回見落とす)。仕組みが仮説の層(DE 整形)と、速くする層(後半の速度目標・ペース)は、効果が示せたときだけ採る。
- **強い衝突**は collision_map と同じ 4G 以上で自動で数える(R1 は起点の −0.05〜+1.0秒、DE は緑マット出口 +0.3〜+2.0秒。`explore_data` 付録B)。
- 中止の条件(ロードマップ 4.4 と同じ): 最初の10周で衝突が 20回を超えた、後退の暴走、HOLD、衝突直前の速度の中央値が基準より 0.5 m/s 以上高い。**足したもの**: 意図しない後退(リカバリー以外で車が後ろへ動いた)1回、ブレーキが R1 の旋回中に出た、車の電池が G0 で決めた打ち切りの電圧を下回った(その電池での試行は終える)、Jetson の電源が落ちた(その走行は使わない)。
- **電池と電源**: 各走行は満充電の電池から始め、電池番号を A と B に偏らせない。Jetson の電池は 10/10 には約30〜60分おきに切れていた(電源断の時刻からの推定)ので、1.5〜2時間の実車では走行の切れ目で 2〜4回替えるか、容量の大きい電池にする。Jetson での学習は AC 電源で、1本ずつ行う(8GB・スワップなしで、メモリが尽きると本体ごと再起動する)。
- **新しく記録するもの**: 各フレームで「どの層が出力を決めたか」と層の作動率、R1 の進入速度の分布、DE の出口のヨー、区間ごとの時間。モデルが良くなったかどうかは、**層の作動率が下がること**(モデルが自分で遅く入れるようになった)でも測れる。

### 5.1 速さと安全の交換(レビューで追加)

## 6. 既存のロードマップとの関係

### 6.1 段階ごとの対応

ロードマップの骨組み(共通基盤 → 段階A 事前学習 → 段階B コース精度データでファインチューニング → 段階C オフライン RL → 段階D オンライン、「B → C を先に回し、A は後から差し替える」)はそのまま使う。この計画は、そこに**モデルの外の「安全層」の流れ**を足し、段階B の中身を具体的にしたもの。

| ロードマップの段階 | この計画で入れるもの | 変えること・足すこと |
|---|---|---|
| 共通基盤(3.1)とゲート0 | N0、N4、再生のハーネス、通過ごとの品質表(`lap_quality.py`)、drive_report の地点別の指標 | 統一データセットの項目に「どの層が出力を決めたか」を足す。ESC のブレーキ量の表と、カメラの内部パラメータを足す |
| (新)安全層(制御) | N1、N2、W2、W3、W5、T1、T2 | ロードマップには無い流れ。学習した方策の外に、確かめられる簡単な層を置き、危ないときだけ出力を変える(Simplex 型)。学習なしで効き、ゲインと違ってモデルに打ち消されない。ロードマップの「安全の床」(3.5・4.4)の具体的な形になる |
| 段階B(精度データ) | N3(D1)、W1(D2・D5・D6)、W4/T5(HG-DAgger)、T3(合成データ)、T4(ペース) | 6.2 の 2〜5・7・8 |
| 段階C(オフライン RL) | T6 はロードマップ 4章のとおり | 安全層を入れた後の AI のデータには、速い R1 の進入が無い。「R1 は遅く入る方が良い」というアドバンテージを学べるのは、上限の無い既存のデータ(6200 以上の進入: AI 8回・人 12回)があるから。両方を混ぜる。層が出力を変えたフレームは、モデルの出力(`action_model`)と実際に出した値(`action_exec`)の両方を残して印を付ける。どちらを手本にするかは机上で比べる(仮説) |

| 段階D(オンライン) | L2 | 前提(G8)に、安全層 v1 を安全の床として加える。ジャイロの位相(C1)は、走行中の位置の手がかり(ロードマップ M4)の一部を先に満たす。要所(R1 開始・GM・GM 出口・LH 進入)での周ごとの標準偏差は 0.18〜0.52m で目標(≤0.5m)に近い。ただし緩いカーブの中は 1.2〜2.2m で足りない |

## 8. 次にやる3つ

### 1. ゲート0を 10/14 の朝までに満たす(N0)

- **何を**: (1) カメラと ToF の取り付けを、学習データの角度(バンパー 7±1行)に合わせて固定する。走行の前後に `sensor_check.py`(実装済み)で点検し、固定した後に ToF の床基準を取り直す。床に印を置き、ToF の光線モデル(今は 1列 1.2°・1行 0.55°。仕様は 1ゾーン約1°)を較正する。(2) 電源: 基板の電源を駆動系から分け、電池の電圧を記録する。Jetson は満充電の電池で走らせ、残量を記録する。長い学習は AC 電源で行う。(3) 車輪を浮かせて安全確認。(4) ESC のブレーキ量を実測する。(5) カメラの画角と内部パラメータを測る(T3 と画角の判断に使う)。(6) 車の電池1本で走れる時間と、試行を打ち切る電圧を決める(実車の予定はすべて「1本 3〜4分」の仮定に乗っている)。Jetson の電池の持ち(10/10 は約30〜60分おきに切れた)も測り、実車の間に替える回数を決める。(7) リカバリー v2 を R1 の板に鼻先を付けて ≥10回試す(成功 ≥8回・後ろへの接触 0・返すまで ≤2.5秒)。合格しなければ、評価の走行でも2秒待たずに取り返す。
- **できたかの判定**: G0(4.3)。
- **なぜ一番か**: これが無いと、どの施策の効果も測れない。夜の 2.86回/周は、センサーの角度のずれ・速い設定・早い交代と重なっていて、原因が分からなかった。基準の 006/007 も設定が混ざっていたので、実車#1 の固定設定の値が、この計画の効果の見込みを読み直す最初の基準になる。

### 2. 安全層 v1 を作り、再生で確かめてから実車に出す(N1・N2・W2)

- **何を**: R1 の進入の上限 2.5 m/s(2.75 m/s も再生で比べる。合図は、ジャイロの位相とモデルの予測ステアの OR)、GM の上限 2.2 m/s、DE の上限 3.0 m/s(GM 出口から 1.5秒)、DE 出口のステア整形(左に +50〜80µs)、ブレーキの規則(1 m/s 未満では出さない、R1 の旋回中は出さない、最短 0.2秒保つ)を、`drive.py` の出力の層として作る(**コードの変更はユーザーが判断**)。全 AI ログで再生して G1 を通す → 実車#1(10/14)でシャドー記録 → 実車#3(10/20)で A/B/A(G4)。
- **期待効果**: 衝突 1.17 → 0.50〜0.99回/周、ラップ +0.24秒(推定。混ざった設定の 006/007 での値で、固定設定では上乗せが小さくなりうる)。1回の A/B/A では −40% 未満の差は見えないので、採否は R1・GM・DE の通過あたりの衝突で決める。R1 で止まる衝突が減るので、交代も減り、4分以上の連続の試行が取りやすくなる。
- **なぜ2番か**: R1 は「速度が限界を超えている」ことが、人と AI のデータ、グリップの計算、モデル自身の予告(8/8)の3つでそろっている。いちばん確かな原因で、学習なしで効き、ラップの損も小さい。B2 より先に実車で確かめるのは、学習の遅れに左右されないため。

### 3. 実車#2 で「遅く入って速く出る」データを集め、B2 を作る(N3・W1)

- **何を**: 実車#2(10/16)で、R1 と LH は 5000 eRPM 以下で入り、緑マットを出たら右へ切り続けず、DE(緑マット出口から約1.5秒)は 6000 eRPM 以下、SW・HS は速く走る周を、60〜90秒の連続収集で低速 ≥30・高速 ≥20周集める(合格率 45% なら約110周・約18分)。立て直しを3種類 × 10〜15回。N3 の選別(速い R1 進入の手前を外す、`--impact-g 2.5`、ジャンルの付け直し)と合わせて B2 を学習する(10/17〜18、AC 電源で1本ずつ)。実車#4(10/22)で A/B/A(G3)。「危ない手前で早めに交代して前進で抜ける」修正データ(W4)は、電池が足りないので 3週目の実車#5 に回す。
- **期待効果**: R1・DE・GM が人並みになった場合で、モデルだけで衝突 0.6〜0.75回/周、ラップ −0.1〜−0.6秒(上限の目安。仮説)。
- **なぜ3番か**: 層は「守る」だけで、モデルの走り方は変えない。R1 の速い進入は学習データから来ている(ジャンル5 の 22%)ので、手本を直すのが根本の対策。後の HG-DAgger・ペース・オフライン RL も、この手本の上に積む。

## 11. 不確かな点

1. **効果の見込みはすべて仮説か、開ループ・運動学の計算。** 閉ループでは、減速するとモデルの入力(eRPM)が変わり、上限を外した直後にモデルが加速し直すおそれがある。実車でしか分からない。
2. 衝突の内訳と減り方は、006/007(first_trial、1日・1コース)の速度帯でだけ使える。基準モデルが変われば分布も変わる。
3. DE の仕組み(ゲインによる右への戻し舵の増幅、GM 出口の空転)は仮説で、ゲインを固定した比較はしていない。DE の合格基準(ヨー > −20°/s)は 60通過からの目安。
4. 区間と通過はジャイロの向きで決めた(±0.1〜0.3秒)。探索ごとに区間の境目が違い、時間の絶対値は境目に依存する。データ探索の AI の R1 通過数は collision_map(目視確認済み)と合わない(33 対 36)ので、比べるときは collision_map を優先した。
5. ESC の型番、ブレーキの減速度(2.6〜3.0 m/s² は約0.6秒分の記録だけ)、左 1895µs と 2000µs の切れ角の差は、実測していない。R1 の上限がブレーキで間に合うという計算(7/7)は 2.8 m/s² を仮定している。
6. ToF の光線モデルと仕様の食い違い、カメラの 1920×1080 モードが切り出しかどうかは、実測していない(要確認)。
7. 夜の 009/010/101 の悪化(2.86回/周)の原因は切り分けられていない。
8. モデルB は実車で走っていない。自己入力の評価はモデルB に構造上有利。
9. 人の最速 7.2〜7.3秒の周は、R1 起点の区切りでは確かめられていない(要確認)。
10. 日程は、実車が 1回 1.5〜2時間・電池 4〜7本で回り、ゲート0 を 10/14 の朝までに満たす前提。満たせなければ1週ずつずれる。コードの変更(層・重み付きの学習・ペース)は、すべてユーザーが判断する。
11. **基準の 006/007 は、1走行に 13〜22通りの設定が混ざった走行**(スロットルゲインは大半が 1.4〜2.0、ステア 1.0〜1.8、006 は先読み 5)。場所ごとの衝突の内訳と、層・選別の効果の見込みは、この条件での値。R1 の速い進入はスロットルゲイン 1.8〜2.0 に集中していて、固定設定(速度 1.0)では今の値も上乗せも小さく出る可能性が高い。ゲイン 1.0/1.0 の区間は R1 3通過しかない。
12. 検出力はポアソン(同じセッション内の周ごとのばらつきはポアソンより小さい)と、セッションの中の A/B/A を仮定した。セッションの間の違い(電池・取り付け・運用)はこの計算に入っていない。
13. 電池1本の走行時間(3〜4分)と Jetson の電池の持ち(約30〜60分)は、記録とロードマップの仮定からの推定で、実測していない。
14. ToF ガードで止まれる速さ(約2.8〜3.0 m/s)は、遅れ 0.15秒・減速 2.6〜3.0 m/s²(未実測)・床が見える距離 約1.9m からの計算。ブレーキで旋回中のグリップが減るのは一般論で、この車では確かめていない。
15. 交換の目安(衝突 −0.1回/周 ≒ ラップ +0.1秒)は提案で、ユーザーが決める。

## 12. レビューで直した点(2026-10-11)

計画と3つの探索を、効果の根拠・速さと安全の交換・検出力・実車の安全・Orin Nano と電池での実現性・順番の観点で見直した。確認の計算は `src/review/`(CPU・読み取りのみ)。

1. **基準の交絡を明記した。** 006/007 は設定が 13〜22通り混ざり、AI の 6200 eRPM 以上の R1 進入 12回のうち 11回はスロットルゲイン 1.8〜2.0 の区間だった。「速い進入は学習データから来ている」を「データと高いゲインの両方(仮説)」に直し、層と選別の効果は固定設定では小さく出うると書いた(1章・3章・5章・11章)。
2. **R1 の上限を 2.75 → 2.5 m/s(2.75 も再生で比べる)にした。** 右いっぱいの半径 0.59m でのグリップの限界は 2.4〜2.6 m/s で、ゲイン 1.0/1.0 の R1 の強い衝突 2回は 5398・5645 eRPM で入っていた。損は +0.045秒/周。予測ステアの合図だけでは間に合わない通過もある(26/29)ので、位相の合図が前提(3.1)。
3. **DE の上限 3.0 m/s を安全層に足し、精度データとペースで DE を速くしないことにした。** 人の DE の衝突は 3.0 m/s 未満で 1/23、以上で 10/37。探索は「直線(DE〜SW、HS)は速く」としていて、自身の所見と食い違っていた(3.1・3.2・3.3・9章)。
4. **速さと安全の交換を表にした(5.1)。** ToF ガードの減速の費用は、誤警報だけの +0.1〜+0.3秒ではなく、正しい警告を含めて +0.3〜+0.8秒/周(006/007 で全警告 1.21秒・誤警報 0.29秒)。約2.9 m/s を超えると ToF では止まり切れない。交換の目安(衝突 −0.1回/周 ≒ +0.1秒)を提案した。
5. **2か月のラップの目標を条件付きにし、「見込みの悪い側に置いた」という誤った説明を直した。** B2 と後半の速度目標は同じ区間に効くので足し算しない。ガードの減速を全区間に入れるなら ≤9.8秒(2章・5章)。2週間のラップの目標は、層の損 +0.24秒を入れて ≤10.2秒にし、G4 の「悪化 0.3秒以内」とそろえた。
6. **検出力の表を足した(4.1)。** 各 43周で見えるのは衝突/周の −40〜−50% 以上。2週間の目標(−23%)は約200周、衝突なしの周の割合 33% → 40% は 43周で 0.11 で、どちらも1回の A/B/A では判定できない。「信頼区間が重なれば悪くない」をやめ、比の点推定 ≤1.1・上側 95% 限界 ≤1.5 にした。効いている安い層を見落とさないよう、片側の採否の規則を入れた。
7. **速くする段の安全の判定に歯を付けた。** 「衝突 +30% 以内」は 43周では見分けられないので、G6・G7 に強い衝突(4G 以上)/周と衝突直前の速度を足した。後半の速度目標は G5 合格の後に限り、位相・ステア・ToF で床(下限)を外す条件を付けた。
8. **実車の安全の手順を足した。** リカバリー v2 は作動 0回のまま評価の運用(2秒待つ)に入っていたので、10/13 に置いて試す検証(≥10回)を入れ、合格したときだけ2秒待つ。ブレーキは R1 の旋回の前だけにした。中止の条件に、意図しない後退・旋回中のブレーキ・電池の電圧・Jetson の電源断を足した。
9. **実現性を直した。** 実車#2 の収集(精度データ 合格 50周+立て直し+HG-DAgger 40回)は、電池 1本 3〜4分の仮定では 10本以上要るので、HG-DAgger を 3週目の実車#5 に移した。電池1本で走れる時間と Jetson の電池の持ち(10/10 は約30〜60分)を G0 で測る。学習は AC 電源で1本ずつ(8GB・スワップなし)。
10. **順番を入れ替えた。** 安全層 v1 の A/B/A を実車#3(10/20)、B2 を実車#4(10/22)にした。学習の要らない、いちばん確かな施策を先に確かめ、学習の遅れに左右されないようにするため。
11. **効果の言い方を直した。** 「人並みになった場合」「半分になった場合」の数字(W1・T3・D2・M3)は上限の目安で、予測ではないと明記した。DE 整形の効きは、固定設定のステア 1.3 ではゲイン 1.0 案で約6°(1.6 のときの半分)なので、左 +50〜80µs を主の案にし、効果を 0〜−0.36 に広げた。

**探索の本文で見つけた問題**(本文は直していない。この計画が優先する)
- `explore_data.md` 1.3・D3: 人の DE の衝突は「6000 未満 0/23」ではなく 1/23(午後の 5000 未満で1回)。D2 の「直線(DE〜SW、HS)は速く」は 1.3 の所見と食い違う。1.2 の「AI が学習データの進入速度の分布をまねている」は、高いスロットルゲインと交絡している。
- `explore_control.md` C2: R1 の上限 2.75 m/s の根拠「5500 未満で 1/21」の1回は、ゲイン 1.0/1.0 の区間の衝突(007 の 244.30秒、5398 eRPM)とみられる(`r1_cap_check.json` の照合から。要確認)。C6 と 3.2 のガードの費用 +0.1〜+0.3秒は誤警報だけの値(本文の同じ節に、正しい警告を含めると +0.8〜+1.6秒とある)。C3 の速度の下限は、ガードが記録だけの間はガードで止まらない。

- 3つとも: 目標と効果を 43〜60周の検出力で確かめられる前提で書いているが、−23% 程度の差は 1回の A/B/A では見えない。電池1本 3〜4分は未実測の仮定。

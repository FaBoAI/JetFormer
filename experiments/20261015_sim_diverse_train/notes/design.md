## 2. Q1 — シミュレーターの閉ループで走れるようになるか

### 2.1 腕

| 腕 | データ | 量 | 学習 / 検証のサンプル(間引き 3) | 1 エポックの見込み | 問い |
|---|---|---|---|---|---|
| A0・A1・A2 | 10/14 のまま | 20・30・10 分 | — | — | 基準(作り直さない) |
| **S-DIV** | 5 モード 75 + D1 30 + D2 30 = 135 シーン | **45 分** | 20,847 / 5,203 | 約 125 秒(30 エポックで約 65 分) | いろいろな走りで走れるか(主) |
| S-MOD | 5 モード 75 シーン | 25 分 | 11,391 / 2,839 | 約 68 秒(約 35 分) | ばらつき 対 量(削れる) |
| A4(DAgger) | 一番良い腕 + DAgger 12 シーン、10 エポック続き | — | — | 約 135 秒 × 10 | Q1b(最初に削る) |

**S-DIV にベストラップの 20 分(A0 のデータ)を入れない理由**: 最速の線 1 本の 20 分で、最速モードの見本・DART のきれいなフレームと同じ方策の走りです。
足すのは量だけで線のばらつきはほぼ増えず、学習の時間は 1.45 倍(約 95 分)になります。**前の教師のデータ** も入れません(作者の RC 教師の 1 本の線のくり返しで、
今日の問いは「新しいいろいろな走りのデータ」だから)。**重み付けはしません**(そのままつなげる。5 モードが学習サンプルの 55%、D1・D2 が 23% ずつ)。

**S-MOD を 2 つ目の腕にする理由**: 10/14 の A1(30 分)は A0(20 分)よりデータが多く、DART の効果と量の効果を分けられませんでした。
S-MOD は 25 分で A1 より少なく、それでも A1 より走れれば「量よりばらつき」と言えます。また S-DIV と比べると、DART・余裕の線の上乗せが分かります。

### 2.2 作り方と IMU の位相

- 10/14 の A0〜A2 と同じ: `tools/train.py --policy jetformer_v0 --epochs 30 --lr 3e-4 --seed 0 --stride 3 --batch 64 --no-command-input --impact-g 2.5`、
  ImageNet から、最良のエポックは各腕の val。10/14 の `dart_train.py` を写した道具で、jf-heavy --mem 3G --lock big、毎エポック last.pth(電源断のあとは同じコマンドで続き)。
- workers は 1(10/14 の A1 は 90 シーンで workers 2 がメモリの上限 3G に当たった。S-DIV は 135 シーンなので最初から 1。足りなければ 0)。workers は色の揺らしの乱数の流れだけを変える。
- **IMU の 3 つの位相**: シミュレーターの IMU の時刻はカメラに対して 0 / 3.3 / 6.7 ms ずれる 3 フレーム周期があり、間引き 3 の学習は位相 0 しか見ていない
  (ベストラップで見ていない位相の誤差は S-R で 1.18 倍)。**今日は位相 0 のまま** にしました。今日の主の比べは位相 0 で学習した A0〜A2 との差で、
  位相の扱いを変えるとデータの効果と作り方の効果が分けられないからです。代わりに、S-DIV・S-MOD の val の全フレームで位相ごとの誤差を測り(参考)、
  見ていない位相が 1.3 倍を超えたら次の手として「全部の位相で学習」を報告に書きます。
- 合わせたフォルダー: data/datasets には作らず、`experiments/20261015_sim_diverse_train/train/data/<腕>/` にシンボリックリンクとつなげた splits.json を置きます
  (10/14 の make_combined.py の写し)。ジャンルの表は、5 モードと 10/14 のデータセットで名前の書き方が違う(「駐車1」と「駐車(1)」)ので、id 0〜8 がそろっていることだけ確かめます。
  学習の前に、読み込んだサンプル数が元の合計と同じ・ジャンル 0 のサンプル 0(離脱復活の外したフレームが入らない)・ジャンル数 9 を確かめます。

### 2.4 判定(結果を見る前に固定)

c = 完走の数(12 本)、fs = ゲート 0 の開始 9 本で最初の直線を抜けた数、g4 = 同じ 9 本で点 4 のゲートを通った数、d = 進んだ道のりの中央値。
前日の基準 c_ref = max(c(A0), c(A1), c(A2)) = 0、g4 は 3 つとも 0。

| 判定(S-DIV) | 条件 |
|---|---|
| **効いた** | c ≥ 6 かつ c − c_ref ≥ 4 |
| **一部効いた** | 上でなく、c − c_ref ≥ 2、または **g4 ≥ 5**(前日どの腕も通れなかった点 4 のゲートを、ゲート 0 の開始の過半で通った) |
| **悪くなった** | 上でなく、c ≤ c_ref かつ fs ≤ 4(DART・余裕の線で直った最初の直線の失敗が戻った) |
| **差なし** | それ以外 |

- **S-MOD(ばらつき 対 量)**: c(S-MOD) − c(A1) ≥ 2、または(両方 0 のとき)g4 の差 ≥ 3、または(どちらも点 4 を通らないとき)d(S-MOD) ≥ 1.5 × d(A1) = 17.1 m なら「量よりばらつき」。
  そうでなければ「ばらつきの効果は見えない」(S-MOD は量が少ないので「量の効果のほうが大きい」とまでは言わない)。
- **DART・余裕の線の上乗せ(S-DIV 対 S-MOD)**: 完走の差 ≥ 2(両方 0 なら g4 か fs の差 ≥ 3)で「上乗せあり」、−2 以下(同じく −3 以下)で「悪くなった」、ほかは「差なし」。
- **一番良い腕**: 完走 → g4 → d の順(前日は完走 0 で決められなかったので g4・d を足した)。
- 速さ: 完走した走りの時間 / T_fast(同じ開始)の中央値 ≤ 1.05 で「最速の先生に近い速さ」。5 モードには速さ 50〜100% が入るので遅くなることは予想される(判定には使わない)。
- Fisher の p、開始ごとの S-DIV 対 A2 の進んだ道のりの符号検定は参考。

### 2.5 予想と危うさ(結果を見る前に書いておく)

- 期待: 5 モードの見本は開始が 24 か所・線が 8 通り・離脱復活の戻しを含むので、「線から外れた状態」をたくさん見る。点 4 のゲートの手前で内側へ早く入る癖が、
  アウト寄り・レイトエイペックスの線の見本で直るかもしれない。
- 危うさ: 1 つのジャンル 8 の頭に違う線・違う速さが混ざるので、JetFormer は **線と速さの平均** をまねする(どの線か・どの速さかの指令が無い)。
  平均の線がゲートの端に寄るなら、かえって点 4 を外す。速さいろいろ(50〜100%)のぶん周回は遅くなる。
- 5 モードの見本のうち、絶対壁にぶつからない・経路いろいろの安全シールドが替えた操作も正解ラベルになっている(1 シーン 0〜3 フレーム)。

## 3. Q1b — DAgger(条件付きで今日できる。最初に削る)

**できるかの下調べ(この段)**: 10/14 の道具で、先生(teacher_core.mjs の fast・margin)・ブラウザの記録の差し込み口(import map で `./rc-speed-controller.js` を
自分のモジュールに替える)・Node の付け替え(relabel_scene.mjs・relabel_dataset.py)・記録の検証と取り込みはそろっています。アプリは開始の約束の検査
`assertRcTeacherContract` を **差し込んだモジュールの関数で** 呼ぶ(app.js 507 行)ので、開始の範囲は自分のモジュールで決められます。
ただし、**閉ループの評価の走行は画像を残さない**(結果の JSON と軌跡だけ)ので、学習した JetFormer が行った状態の画像は、ブラウザの記録で描き直す必要があります。

足すもの:
1. **再生 → 先生の差し込みモジュール**: フレーム k まで、JetFormer が閉ループで実際に適用した操作(評価の JSON)を再生し、k から先生が 20 秒まで運転する。
   info.dart に先生のきれいな操作と「JetFormer の操作との差」を noise として出す(10/14 の DART と同じ形。jf は出さない)。
2. **付け替えの道具の写し**: 乱しを乱数の決まりから作り直す代わりに、記録の info.dart.noise を読む(前回の行動 = 実際に適用した操作)。
3. 開始の約束の検査を D0〜D11 に広げる。

手順: 一番良い腕で **評価と別の開始 D0〜D11**(8 個はゲート 0 の小さなずれ、4 個はゲート 5・15・24・31)の単周を走らせる → Node で T_fast・T_margin のどちらが多くの状態から
立て直せるかで先生を選ぶ → 切り替えのフレーム k = 先生に任せて完走できる最後のフレーム → 12 シーンを記録・検証・取り込み・付け替え → 元の腕の best から 10 エポック(lr 1e-4)→ E0〜E11。

**止める条件(go / no-go)**: G1 Node で単周の操作を連続周回で再生して k まで ≤ 1e-6 m で同じ、G2 ブラウザの試し 1 シーンで k の位置が ≤ 2 cm、
G3 付け替えの写しの再生 ≤ 1e-9・D1 の 2 シーンで 10/14 の道具と同じ正解。どれか不合格なら「今日はできない」として止めます。元の腕が 10/12 以上完走したらやりません。

**DAgger の状態を評価と別の開始から集める理由**: 評価の E0〜E11 の走行の状態をそのまま学習に入れると、同じ開始で評価したときに「見たことのある状態」になり、効果を大きく見せてしまうため。

### 4.2 評価と判定(10/13 のまま)

- 10/13 の `tools/sim_cotrain_eval.py`・`sim_cotrain.py` を実験フォルダーに写し、名前の表に C-DIV を足します。A・B・C の予測は前の npz をそのまま読みます。
  **写した道具で C の種 0 を予測し直し、10/13 の npz と同じ(≤ 0.01 µs)** ことを確かめてから C-DIV を予測します。
- 主指標: 保留した実機の人のきれいな走行 11 シーン・4,670 フレームの L1(10 ステップ × [ステア, スロットル])。
- **A と比べる**: 「良い」= 2 つの種の両方が A の 2 本より小さく、平均の改善 > 0.626 µs(best)・1.322 µs(last)。「悪い」は逆。ほかは「同等」。best だけ「良い」は「同等」に下げる。
- **C と比べる**: 同じ規則で、閾値は best 2 × max(0.477, 0.313) = **0.954 µs**、last **1.322 µs**。
- 種 1 を削ったら「暫定(種 1 つ)」の判定(種 0 が基準の 2 本の外にあり、平均との差が閾値を超えたとき)。
- 参考: ずれへの強さ(「ずれに強い」= A の 0.8 倍以下かつ両方の種で A 以下。C の 0.61 倍とも並べる)・ジャンル別・速さの癖(10 µs)・**低速の直線 HS の前進の偏り**
  (10/13 の確認で C が強く前進を出した所。5 モードの速さのばらつきで変わるかを見る。今日は先に決めた参考の測り)・R1/DE・崩れ・シミュレーターの L1(前の教師の val 12 シーンと、5 モードの保留 15 シーン)・C が悪かった 2 シーン。
- 主指標は判定とは別の短い道具でも計算し直します(削らない)。
- 推奨をモデル B から替えるのは「良い」かつ 10 µs 以上かつ崩れなしの腕だけ。今日は実車で試さないので、そのときも「実車の A/B/A の候補」と書くだけです。

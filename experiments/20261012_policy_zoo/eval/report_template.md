## 0. 結論

**ベストのモデルは `jetformer_v0` のまま(= 今走っているモデル B)。机上では、新しい 4 つの方策のどれも v0 より良いと言えない。**
先に決めた規則の 4 番(「良い」方策が 1 つも無いとき)で決まった。推奨のエンジンも今と同じモデル B のエンジンで、走行と同じ手順で読めて回ることを確かめた(6 章)。

- **人の運転をまねる精度(主指標)**: v0 より 10 µs 以上良い方策は無い。msfusion(TransFuser多段型)は v0 とほぼ同じ(+0.0 µs)。
  tcp は +0.4 µs(0.9%)、act と dinov2 は約 +1.1 µs(2.2%)悪い。この 3 つは、種 2 本 × best/last の 4 通りすべてで v0 の 2 本より悪かった。
  小さいが一貫した差である。ただし、どれも実用上の差の閾値 δ = 10 µs(L1 の約 20%)よりずっと小さい。
- **難しい場所(R1 の進入・DE の出口)の出力**: どの方策も、v0 との差は −8.4〜+7.2 µs に収まった。「良い」の条件を満たしたものは無い。
  msfusion は DE の出口で v0 より右寄り(−8.4 µs)で、95% の区間が 0 をわずかに外れたので「悪い」になった。
- **崩れ**(直線で前進が弱まる・向きを間違える)は、どの方策にも無かった。
- **ずれへの強さ**: msfusion だけが「強い」(画像を数行ずらしても誤差がほとんど増えない)。dinov2 は画像のずれには非常に強いが、ToF を 1 行ずらすと誤差が 12〜14 µs 増える。
- **速さ**: 全部が走行の速さのゲート(6 ms)の内。v0 2.4 ms・act 2.6 ms・tcp 2.6 ms・msfusion 3.2 ms・dinov2 5.0〜5.1 ms(推論 1 回)。
- **dinov2 の扱い**: 普通の FP16 のエンジンでは種 1 が精度のゲートに落ちた(2.85 µs > 2.5 µs)。先に決めたとおり、判定の候補からは外した。
  LayerNorm・Softmax だけ FP32 で作り直したエンジン(`fp16_norm_fp32`)は 2 本とも合格した(1.78・2.05 µs)ので、走行タブでは選べる。
  仮に候補に入れても、ベストは v0 のまま変わらない。

**「どれが賢いか」を一言で言うと**: 新しい 4 つは、どれも今の JetFormer v0 と同じくらい賢い。v0 を超えるものは無かった。違いは 0〜1.1 µs(0〜2%)で、実車で見分けられる大きさではない。
なので、今の走行のモデル(モデル B)を変える理由は無い。机上の結論は実車の改善を示さない(規則 7)。実車では、まずモデル B だけで基準値を取る(7 章のカード 1)。

これは「v0 の学習の条件(lr 3e-4・cosine・30 エポック・AdamW wd 1e-4・勾配のクリップ 1.0・バッチ 64・AMP)を全方策に使い、方策ごとの調整をしない」場合の結論である(D10)。
この条件は v0 に合わせて決めたものなので、v0 に有利な可能性がある。

## 2. 手順(結果を見る前に固定)

- **判定の規則**: spec §5 をそのまま写し、レビューで決めた逸脱 D1〜D13 を足して、保留データのどの予測よりも前(19:29)に `results/zoo_rules.json` に固定した。この評価では変えていない。
- **計算の手順**: `eval/protocol.json`(19:50、予測の前)。道具は `tools/policy_zoo.py`(predict・crosscheck・engine-check・evaluate・figures)。
- **主指標 L**: 保留した人のきれいな走行(人の 11 シーン、4,670 フレーム、衝突の前後を除く)で、PyTorch FP32(best.pth)の予測と人の操作の差の絶対値を
  10 ステップ × [ステア, スロットル] で平均したもの [µs]。今の操作値を入れないモデルなので、教師あり = 自己入力(走行と同じ)。
- **基準とばらつきの幅**: 基準 R = v0 の種 0・1。δ = max(10 µs, {モデル B, v0 種 0, v0 種 1} の L の範囲)= **10 µs**。
  「良い」は Δ ≤ −δ かつ 2 本とも v0 の 2 本より小さいとき。best.pth と last.pth で分類が変わったら「良い」と言わない。
- **副指標**: R1(進入前 0.4 秒のスロットル)・DE(緑マット出口〜0.8 秒のステア)を、保留の通過(R1 17・DE 14)で通過ごとのブートストラップ 10,000 回。
  「良い」には 99.375% の区間(8 回の比較の補正)・両方の種・4 組すべてで 10 µs 以上・シーンの平均を引いた差の区間、の全部が要る(D1〜D3)。
  「悪い」は 95% の区間の上限 < 0。ほかに、崩れ(直線の前進の強さ・前進の偏り・向きの正解率)、ずれへの強さ(画像を 3 行上下・明るさ ×0.8・×1.2・ToF を 1 行下)。
- **陰性対照**(D4): v0 の種 1 を「方策」、{v0 種 0, モデル B} を基準にしたもの(NC-A)と、その逆(NC-B)。同じ方策の別の種どうしで、判定が偶然に出ないかを確かめる。
- **判定の規則**(`zoo_rules.json` の verdict_rules_effective):
  1. 候補 = v0 以外で、ゲートを 2 本とも満たし、主指標が「悪い」でなく、崩れでなく、R1・DE のどちらも「悪い」でない方策。
  2. 候補の中に主指標が「良い」ものがあれば、それがベスト。
  3. 無ければ、主指標が「同等」で R1・DE のどちらかが「良い」ものを「机上の候補」にする(陰性対照が「良い」・崩れにならないときだけ)。
  4. どちらも無ければ、ベスト = `jetformer_v0`(モデル B のまま)。

**表の確かめ**: 保存した予測から CPU で評価をもう一度計算し(予測はやり直していない)、保存済みの `eval/zoo_eval.json` と全項目で一致(差 0 か所)、表(`eval/tables.md`)も同じ文字列になった(`eval/verify/verify.json`)。
モデル B の予測は、前回の実験のキャッシュ(`pred_B.npz`)と同じ(差の最大 0.0 µs)で、モデル B の L = 49.14 µs も前回の値と同じ。

## 5. 方策ごとの得意・不得意

数字は種 2 本の値。どの差も δ = 10 µs よりずっと小さく、学習のばらつき(種どうし・best/last で 0〜1 µs、R1・DE の出力で 7〜8 µs)と同じくらいなので、**「傾向」として読む**。

### jetformer_v0(基準。モデル B と同じ形)

- 得意: 主指標は 49.15・49.46 µs(新しいコードの 10 本の中で最小は v0 種 0)。ステアの近い先は、v0 種 0 の k1 41.6 µs が 11 本の中でいちばん小さい。速い(推論 2.4 ms)・小さい(14.1M)。
  新しいコードで学び直しても、モデル B(49.14 µs)をほぼ同じに再現した。
- 不得意: 画像を 3 行下へずらすと誤差が増えやすい(+1.4・+2.5 µs。msfusion・dinov2 は +0.1〜+0.6 µs)。

### act(ACT型)

- 得意: 交代の後の人の修正(学習データの中の参考)では v0 より少し近い(124〜125 対 128〜129 µs)。ずれへの強さは種 0 だけ良い(+0.55 µs)。
- 不得意: 主指標で約 1.1 µs 悪い(4 通りすべてで v0 より悪い)。スロットルの遠い先が弱い(k10 53〜54 µs、v0 50.5〜51.2 µs)。ジャンル 5 で少し悪い(42.7〜43.3 対 41.3〜41.4 µs)。
  種どうしの差がいちばん大きい(0.87 µs)。学習の収束も v0 より遅かった(10 エポックまで 55〜65 µs、`training.md`)。
- R1 の出力は v0 より +7 µs 遅め、DE の出口は +6 µs 左寄り(どちらも 99.375% の区間が 0 を含む)。DE の 95% の区間は 0 を外れた(+0.4〜+11.4 µs)が、「良い」の条件(99.375%・4 組すべてで 10 µs 以上・シーンの平均を引いた差)には届かない。

### tcp(TCP型)

- 得意: 種どうしの差が小さい(best 0.07・last 0.09 µs。best と last の両方で 0.1 µs 未満なのは tcp だけ)。ステアの遠い先(k10 55.6・57.0 µs)は v0(55.9・57.2 µs)と同じくらい。
  通過点(ADE 0.18・0.23 m)と目標速度(誤差 0.22・0.24 m/s、偏り +0.05・+0.02 m/s)も出せる。
- 不得意: 主指標で 0.4 µs 悪い(4 通りすべてで v0 より悪い、小さいが一貫した差)。ステアの近い先(k1 45.0・43.0 µs)が v0(41.6・42.4 µs)より種の平均で約 2 µs 悪い。
  直線の前進の強さが v0 より 3.9% 弱い(崩れの線 5% にいちばん近い)。
- 通過点と目標速度を使う出し方(`tcp_mode 1`・`3`)は、今の較正ではまだ使えない(D13)。hybrid の L1 は 67〜73 µs、R1 の進入の見積もりは 2,200〜2,500 eRPM で、人(5,167 eRPM)よりずっと遅い。
- **速度の上限**(`speed_cap` 2.75 m/s、操作の枝に掛ける): R1 の窓のスロットルは +24 µs 弱まり(95% 区間 +1.4〜+52.2・+2.3〜+50.5 µs)、見積もった進入の中央値は 4,660 → 4,005・4,736 → 4,374 eRPM に下がる。
  spec §5.5 の「上限が使える(机上)」の条件は満たす。ただし上限はコースの全部で効くので、**直線の前進の強さも 71〜74% 下がる**(直線では人の速さが 2.75 m/s を超えるため)。
  上限は「全体の速さの上限」で、R1 の手前だけを遅くするものではない。机上で言えるのは指令の変わり方までで、上限の効き目は実車でしか分からない。
  上限を試すカード(spec §5.7 の別のカード)は、D13 のとおり、写像を直すまで行わない。

### msfusion(TransFuser多段型)

- 得意: 主指標は v0 と同じ(49.30・49.31 µs)。**ずれに強い**(ΔL1 0.60・0.53 µs、v0 の 0.71 倍)。とくに画像の上下のずれ(−0.22〜+0.56 µs)。
  スロットルの近い先(k1 40.2・40.7 µs、v0 42.1・42.3 µs)と遠い先(k10 49.3・49.8 µs)が全方策でいちばん小さい。
  交代の後の人の修正(学習データの中の参考)も、ログ単位で保留した 3 窓で 130.8・134.8 µs と、v0(143.6・156.5 µs)より小さかった(3 窓だけなので根拠にはしない)。
- 不得意: DE の出口で v0 より右寄り(−8.4 µs、95% の区間 −17.0〜−0.4 µs)。前回の記録では、AI は DE の出口で人より右へ曲がりすぎて失敗していたので、右寄りは規則どおり「悪い」の向きとして判定する。これで候補から外れた。
  ただし陰性対照も同じ大きさの差を出したので、ばらつきの可能性がある。ステアの遠い先が種 0 で悪い(k10 61.0 µs)。推論が少し遅い(3.2 ms)・大きい(18.9M)。
  学習の初め(1〜10 エポック)に検証が 91〜150 µs まで暴れ、学習の L1 も v0 の 2 倍(32 対 14 µs)で、学習の条件が合っていない可能性がある(D10)。

### dinov2(DINOv2型)

- 得意: **画像のずれ・明るさの変化に非常に強い**(画像を 3 行ずらしても −0.03〜+0.28 µs、明るさ ±20% で ±0.04 µs)。
  スロットルの近い先が良い(k1 40.5・41.1 µs)。交代の後の人の修正(学習データの中の参考)は全部の窓で 120〜121 µs と小さい。学習する重みが 2.87M と少なく、学習のメモリも 475 MB と小さい。
- 不得意: 主指標で約 1.1 µs 悪い(4 通りすべてで v0 より悪い)。ステアの遠い先が悪い(k10 62.0・61.3 µs、v0 55.9・57.2 µs)。ジャンル 5 で少し悪い(42.7〜43.0 µs)。
  **ToF を 1 行ずらすと誤差が 12.4・13.9 µs も増える**(ほかの方策は 0.2〜3.0 µs)。画像の特徴を凍結しているので、場所の手がかりを ToF に強く頼っていると考えられる(仮説)。
  推論がいちばん遅い(5.0〜5.1 ms、走行ループの見積もり 8.3〜8.4 ms)。普通の FP16 のエンジンでは精度が足りない(LayerNorm・Softmax を FP32 にする必要がある)。
- R1 の出力は v0 より −8 µs 速め(進入の見積もり 5,037〜5,427 eRPM で、人に近い)。区間は 0 を含み、last.pth では「悪い」になった。

## 9. 注意と限界

1. **机上の数字だけ。** 実車では何も走らせていない。ログの車は方策の指令に反応しないので、閉ループの速さ・衝突は分からない。
2. **方策の差は、学習のばらつきと同じ大きさ。** 主指標の方策の差(0〜1.1 µs)は、種どうしの差(0.01〜0.87 µs)・best と last の差(最大 0.87 µs)と同じくらい。
   R1・DE では、v0 の種どうし(陰性対照)だけで ±7.5 µs 動き、NC-B は 95% の区間で「悪い」になった。通過ごとのブートストラップの区間には学習のばらつきが入っていない。
   種は 2 本だけなので、p 値は出していない。
3. **主指標の「保留」は同じセッションの中の保留**(D8)。検証の 11 シーンは学習のシーンと同じ記録から取られ、3 か所は 0.033 秒で続いている。その前後 1 秒を除いても結論は同じ(表 3)。
   best.pth もこの検証で選んだので、主指標は少し甘い。エポックを選ぶことによる甘さは、終盤の検証の揺れが大きい方策ほど大きい(D9)。last.pth の値も並べた。
4. **保留の R1・DE は 17・14 通過しかない。** 区間が広いのは当然で、「良い」が出なくても「差が無い」とは言えない。セッションの外にあるのは AI の R1 4 通過・DE 4 通過と、交代の後の人の修正の 3 窓だけ。
5. **学習の条件は v0 向け**(D10)。msfusion は学習の初めに検証が暴れ、学習の L1 も v0 の 2 倍だった。act・tcp は収束が遅かった。方策ごとに学習率などを調整すれば結果が変わる可能性がある。
6. **dinov2 の判定は FP16 のゲートで決めた**(D7)。作り直したエンジン(`fp16_norm_fp32`)は結果を見た後の案なので、判定の候補に入れていない。入れても結論は同じ。
   64 フレームの差の最大はエンジンを作るたびに揺れる(同じ設定で 1.72・1.78 µs など)。
7. **速さの比較は同じ道具の値**(run_numpy、100 回の空回しの後 600 回)。走行ループ・カメラ → PWM は、モデル B の実車の値に run_numpy の差を足した**見積もり**で、新しい方策の実車の値は測っていない。
   測り直すと約 0.15 ms 揺れるので、0.3 ms より小さい差には順位を付けない(D11)。tcp の値には制御器(`tcp_mode ≠ 0` のとき)の時間が入っていない。
8. **主指標は、人の今の操作を入れずに人をまねる誤差**である。人の今の操作をそのまま続けるだけの予測(走行中には使えない)は、3 フレーム先のスロットルで 15.8 µs と、どのモデル(44〜47 µs)よりも小さい。
   L1 の値そのものを実車の精度と読まない。比べるのは方策どうしの差だけ。
9. **R1 の進入の見積もりは粗い**(対応表と実際の進入の順位相関 0.41)。
10. **tcp の通過点・目標速度の正解は、記録の IMU・車輪の回転から作ったもの**(`tcp_labels_v1`)。tcp_mode 1・3 のスロットルの写像は、正解の目標速度を入れても人のスロットルとの相関 0.48 で、まだ使えない精度(D13)。
11. **3 本目の種(O1)・方策ごとの調整(O2・O3)はしていない。**
12. **jetformer-web はまだ古いコードのまま**(11:13 から)。走行タブの一覧の上の方に新しい 10 本が出ているが、方策を見分けない。再起動(主の作業)までは、新しい 10 本(とくに出力が 3 つある tcp)を走行タブで選ばない。

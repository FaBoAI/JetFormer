# 実車の A/B/A のカード(real_accuracy_20261015)

> **このカードは、ユーザーが実車で試すときのためのものです。** この作業では車を走らせていません(実車・PCA9685・I2C に触れていない)。
> カードに載せたのは、保留データで「良い」と判定され、介入の集合(S3)で「悪い」が無い方策だけです。どれも差は 10 µs 未満の
> **机上の小さな改善**です。走行の推奨は **モデル B のまま** です。
> 見直し(`review.md`)で、カードの数字は保存した予測から数え直して一致を確かめました。

## 共通の決まり(protocol.json の aba_card_template)

- 並び: **B → 候補 → B**。各 5 周。
- 3 回とも同じ電池の帯で走ります(走る前の電圧を記録)。
- 走行の設定は、ゲイン ステア 1.3・スロットル 1.0、先読み 3 です。予測の重ね合わせ(ensemble_j)は 0(オフ)のままにします。
- 記録すること:
  - 周回時間
  - 衝突の回数
  - 取り上げ(人が止めた・持ち上げた回数)
  - 直線の eRPM(HS・DE の区間の中央値)
  - R1 を通過できたか
- 読み方:
  - 候補の 5 周が、前後の B の 10 周より、周回時間で良く、衝突・取り上げが増えていなければ「候補が良さそう」とします。
  - 1 回の A/B/A は少なく、偶然もありえます。良さそうなら、もう 1 回 A/B/A をくり返して決めます。

## 候補 1: ENS(v0 と msfusion の予測の平均。組 P2 を 1 つのエンジンにまとめたもの)

- **保留データの結果**: 2 つの組 P2・P3 の L1 は 46.43 / 46.92 µs でした。A は 49.15 / 49.46 µs です。
  - 差は best −2.63 µs、last −2.33 µs で、規則では **「良い」** です。
  - 介入の集合(S3)では −10.0 µs で、こちらも「良い」です。崩れはありません。
  - **ただし**、新しい種の v0 は A より 0.86 µs 悪く出ました(FRESH-A が「悪い」)。v0 の 4 本のばらつきで閾値を計算し直すと(結論の規則 3 の感度)、ENS は **「同等」** になります。改善は小さく、際どいと読んでください。
- **エンジンのゲート(合格)**:
  - FP16 のエンジン `experiments/20261015_real_accuracy/ens/ens_p2_fp16.engine`
  - PyTorch FP32 との差は最大 0.86 µs です(上限 2.5)。
  - run_numpy は中央値 4.12 ms・p99 4.86 ms です(上限 6・8 ms)。モデル B の v0 は約 2.4 ms です。
  - 走行のループは約 1.7 ms 長くなる見込みです(見積もりで、実測ではありません)。
- **走らせる前に要ること**: このエンジンはまだ走行タブの一覧に出ていません。protocol で data/runs の外に置いたためです。
  - 走らせるには、data/runs に学習結果のフォルダーを 1 つ作り、エンジンと model_config.json を置く必要があります。
  - この作業ではしていません。

## 候補 2: GAIN(電池の効きの補正。B の出力に後処理を足す)

- **やること**:
  - 走行中に、直前 5 秒の「(中立 1498 − 出したスロットル)÷(前進 eRPM / 1000)」の中央値 g_t を求めます。前進 eRPM が 2,000 より大きいフレームだけを使い、30 フレームに満たなければ補正しません。
  - 衝突(水平 2.5 G 以上)の後 2 秒のフレームも外します。保留データの計算では「衝突の 1 秒前」も外していましたが、走行中はこれから起きる衝突は分かりません。見直しで「後だけ外す」形でも計算し直し、結果は同じでした(むしろ 0.02〜0.1 µs 良い。`review/gain_causal_check.json`)。
  - 保留データでは g_t を **人が出したスロットル** から求めました。走行中は **AI が出したスロットル** から求めることになり、補正 → スロットル → 回転数のループでの動きは、まだ確かめていません。
  - 前進側のスロットルを、中立 − (中立 − 出力) × clip(g_t / g_ref, 0.8, **1.3**) にします。g_ref は高速 36.41・低速 36.86 です。
  - 実車のカードでは、上限を 1.3 にします。
- **保留データの結果**:
  - 主指標は −4.16 µs(A)・−4.19 µs(新しい種)で、規則では **「良い」** です。S1・S3 で「悪い」はありません。
  - **この改善は、ほぼ 1 シーンから来ています。** 電池の減ったシーン 20261010-193638-0003 で、誤差は 96.7 → 59.5 µs になりました。
  - ほかの 10 シーンでは、+0.4 µs(同等)と、少し悪くなる向きです。
  - 上限 1.3 にすると、主指標の改善は −1.66 µs です(参考)。
- **走らせる前に要ること**: この補正は、まだ走行のプログラム(jetformer/drive.py)に入っていません。
  - 走行の設定に「電池の補正」を足すコードが要ります。
  - この作業ではしていません。
- **試し方**: 次の 2 回で、B → B + 補正 → B を走ります。
  - 電池が新しいとき
  - 15 分走って減ったとき
  - 効くのは減ったときだけのはずです。新しいときに悪くならないことも見ます。

## 載せなかったもの

- ROT(位相を回す): 「同等」でした。
- TE(時間方向の平均): 「同等」でした。走行の既定(オフ)のままにします。
- SAME(同じ形の平均): 「同等」でした。
- GAINL(電池の補正を学習のラベルに入れる): 2 本目の種が電源断で削られ、判定していません。種 0 だけの参考では、後処理(GAIN)だけのときとの差が best −0.48・last −0.40 µs(閾値の中)で上乗せは無く、介入の集合では last で +5.5 µs と悪い向きでした。

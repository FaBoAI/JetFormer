# シミュレーターと実機を混ぜた学習(案 C)の評価 — 実機の精度は上がったか

> **呼び名**: モデルは **TransFuser軽量型(JetFormer v0)**(`jetformer_v0`。今の走行のモデル B と同じ形)。データは **実機**(`clean_driving_20261011`、人のきれいな高速・低速の周回 52 シーン、ジャンル 4・5)と **シミュレーター**(`jetformer-simulator-id8-20min_20261012-150956_b55616cf`、60 シーン、ジャンル 8)。
> 腕: **A** = 実機だけ(10/12 の v0 の種 0・1)、**C** = シミュレーターと実機を混ぜて学習、**C+FT** = C のあと実機だけで微調整(finetuning)、**A+FT** = A を同じ方法で微調整(対照)。

## 0. 結論

**実機の精度は上がりませんでした。** シミュレーターを混ぜて学習しても(C)、そのあと実機のデータで微調整しても(C+FT)、保留した実機の人の走行に対する誤差は、実機だけで学習した A と「同等」でした(先に決めた規則の 3 番)。走行のモデルはモデル B のままです。

| 腕 | 主指標 L1(2 つの種の平均、best.pth) | A との差 | 判定(best・last の両方) |
|---|---|---|---|
| A(実機だけ・基準) | 49.30 µs | — | — |
| C(混ぜて学習) | 49.73 µs | +0.43 µs(+0.9%) | **同等** |
| C+FT(C → 実機で微調整) | 49.71 µs | +0.41 µs(+0.8%) | **同等** |
| A+FT(A → 実機で微調整・対照) | 49.24 µs | -0.06 µs(-0.1%) | **同等** |
| モデル B(参考) | 49.14 µs | -0.16 µs | — |

(+ は A より誤差が大きい = 悪い向き。「良い」と言うには、2 つの種の両方が A の 2 本より小さく、かつ平均で 0.626 µs(= 2 × A のばらつき 0.313 µs)より大きく改善する必要がありました。)

- **混ぜるだけ(C)**: A より平均 0.43 µs(0.9%)大きい誤差でした。2 つの種 × best・last の 4 通りすべてで A の 2 本より大きく、悪い向きにそろっています(ただし best と last は同じ種の重みで独立ではなく、実質は 2 つの種です。本当の差が無くても、2 つの種がそろって A の 2 本より上(悪い側)に来る確率は 1/6 あるので、強い証拠ではありません)。ただし差は閾値 0.626 µs より小さいので「同等」です。
- **混ぜてから微調整(C+FT)**: A より平均 0.41 µs 大きく、「同等」です。微調整で C から変わった量は -0.015 µs(best)・-0.100 µs(last)で、微調整は C の誤差をほとんど変えませんでした(C+FT − C も「同等」)。C+FT は 2 つの種の差が 0.747 µs と大きく(ばらつきが大きい: 2 × s_A を超える)、種 1 だけ見ると A の範囲に入ります。
- **シミュレーターの効果(C+FT と A+FT の比較)**: 同じ微調整をした A+FT と比べても C+FT は 0.47 µs 大きく、「同等」です。A+FT − A も -0.058 µs で「同等」なので、12 エポックの追加の微調整そのものにも効果はありませんでした。
- **速さの癖は、ジャンルの平均では移りませんでした。ただし低速の直線では少し移っています**: シミュレーターは実機より速く走りますが(スロットルの中央値 1267 µs vs 1315 µs)、ジャンル別の前進の偏りの A からのずれは最大 3.9 µs で、目安の 10 µs より小さいままでした(先に決めた規則では「移りなし」)。ただし、レビューで場所別に見ると(後から見た内訳で、判定には使いません)、低速(5)の直線(場所の札 HS、411 フレーム)では前進の偏りが A -1.0 / +0.8 µs に対して C -11.3 / -22.9 µs、C+FT -4.0 / -26.8 µs で(負 = 人より強く前進)、C は両方の種、C+FT は種 1 で、A の種どうしの差(1.9 µs)と 10 µs の目安を超えて強く前進を出していました。ジャンル別の頭は速さの違いの大部分を分けて持てていますが、この直線だけは分けきれていません(9 章)。
- **ずれへの強さは上がり、微調整のあとも大部分が残りました**: 画像を数行ずらす・ToF を 1 行ずらすなどの小さなずれで誤差が増える量(ΔL1)は、C が A の 0.61 倍、C+FT が 0.67 倍で、どちらも先に決めた「ずれに強い」の条件(0.8 倍以下・両方の種で A 以下)を満たしました。A+FT は 1.00 倍で変わりません。微調整で ΔL1 が変わった量は種ごとに -0.02 / +0.12 µs で、C で得た強さ(A との差)のうち微調整で戻ったのは平均で約 16%(種 1 で大きい)で、大部分は残りました。ただし、差は 0.3 µs ほどで、主指標の 49 µs に比べると小さな量です。
- **シミュレーターのことは覚えていて、微調整でもほぼ忘れませんでした**: シミュレーターの 12 シーン(C では学習に入ったシーン)で、C はジャンル 8 の頭で 5.6 µs、C+FT は 7.7 µs でした(+2.1 µs 増えただけ)。実機だけの A は、頭 5 で 158.7 µs(頭 4 で 160.7 µs)と大きく外れます。C が A より良くなった 153 µs のうち、微調整で失ったのは 1.4% だけです。
- **難しい場所(R1・DE)と崩れ**: どの腕も R1・DE で「良い」にはなりませんでした。崩れ(直線で前進が弱まる・向きを間違える)はどの腕にもありません。DE で C+FT − A が -3.0 µs(95% の区間が 0 をわずかに外れて「悪い」の印)でしたが、同じ作り方の種どうしでも DE で 2.8 µs、R1 で 7.7 µs の差が出るので(10/12 の陰性対照)、それとほぼ同じ大きさです。参考の項目で、判定には使いません(3 章の表 5・6)。
- **速さ**: 6 本とも TensorRT FP16 のエンジンで走行の速さのゲート(6 ms)の内です。run_numpy の中央値は 2.29〜2.43 ms で、A(2.37・2.36 ms、10/12 に測定)と同じです。エンジンと PyTorch の差は最大 0.86〜1.61 µs(ゲート 2.5 µs)。

**まとめ**: この条件では、「シミュレーターのデータで先に学び、実機のデータで仕上げる」やり方で、実機の精度は上がりませんでした。平均では 0.4 µs(1% 弱)悪い向きでしたが、区別できない幅の内です。得られたのは、小さな入力のずれへの強さと、シミュレーターの場面への当てはまりです。どちらも微調整のあとも大部分が残りました。走行の推奨はモデル B のままで、実車の A/B/A で試す候補もありません(「良い」の腕が無いため)。

**レビュー**: 保留データの漏れ・比べ方の公平さ・ドロップの表・数字の再計算を CPU だけで確かめ、判定と結論を覆すものはありませんでした。差は場面で一様ではなく、2 つのシーン(とくに低速の直線)で大きく悪く、ほかではわずかに小さい向きでした(後から見た内訳。9 章)。

この結論は、TransFuser軽量型(JetFormer v0)・この学習の条件(A と同じレシピで調整なし。混ぜる割合はシミュレーター 2 : 実機 1)・このシミュレーターのデータ(60 シーン・合成の先生)に限ります。机上の結論で、実車の走りを測ったものではありません。

## 2. 手順(学習の前に固定した protocol.json のとおり)

- **フレーム**: 10/12 と同じ保留の表(`rl_evaluate.pred_table()`、10,985 フレーム、key `3d339512`)。主指標は人の 11 シーンのきれいな走行(未来が有効・車両の値が有効・2.5G の衝突の前後でない)4,670 フレーム(ジャンル 4: 1,922、ジャンル 5: 2,748)。
- **予測**: PyTorch FP32(best.pth・last.pth)。ジャンルは aligned の mode(4・5)。10/12 と同じ `policy_zoo._Frames`・`_predict_frames`。確かめ: 10/12 の v0 種 0 をこの評価の道具で予測し直すと、10,985 フレームすべてで 10/12 の予測と差 0.0 µs(L1 49.1459 / 49.1459 µs)。
- **主指標 L**: |予測 − 人|(10 ステップ × [ステア, スロットル])の平均 [µs]。腕の値 = 2 つの種の平均。
- **ばらつき s_A** = {A 種 0, A 種 1, モデル B} の L の範囲 = 0.313 µs(best)・0.661 µs(last)。**良い** = 腕の 2 本が A の 2 本より小さく、かつ平均の改善 > 2 × s_A(0.626 µs)。**悪い** = その逆。ほかは **同等**。last.pth でも同じ計算(閾値 1.322 µs)をして、best だけ「良い」なら「同等」に下げる。|差| ≥ 10 µs なら「実用上の差」。
- **腕どうし(副)**: C+FT vs C、C+FT vs A+FT を同じ規則で(ばらつき = 基準の腕の種の範囲と s_A の大きい方)。
- **副指標(判定は変えない)**: ジャンル別・速さの癖・R1/DE(10/12 と同じ通過の選び直し 10,000 回)・崩れ・ずれへの強さ・交代の後の人の修正(参考)・シミュレーターの L1(参考)・エンジンの速さ。
- **10/12 と同じ値か**: A・モデル B の値を 10/12 の予測から同じ道具で計算し直し、protocol.json に写した 10/12 の値と比べた → **すべて一致**(3 章の表 13)。

## 4. 判定(protocol.json の conclusion_rules を順に当てた結果)

1. C+FT vs A: **同等**(+0.412 µs、閾値 0.626 µs、実用上の差 なし)。C vs A: **同等**(+0.428 µs、2 つの種 × best・last の 4 通りすべてで A の 2 本より大きく、悪い向きにそろっています)。
2. C+FT が「良い」ではないので、C+FT vs A+FT(**同等**)はシミュレーターの効果の判定に使いません。
3. C+FT・C のどちらも「同等」→ **「シミュレーターを混ぜても実機の保留データの精度は上がらなかった(A と同じ)」**。
4. 走行の推奨を変える条件(「良い」かつ 10 µs 以上かつ崩れなし・ゲート合格)を満たす腕はありません → **推奨は モデル B のまま**。ゲートは全腕 合格、崩れは なし。
5. 机上の結論で、実車の改善を示すものではありません。TransFuser軽量型(JetFormer v0)・この学習の条件・このシミュレーターのデータに限ります。

### 9.5 結論は、先に決めた規則と種のばらつきから言えるか — 言えます

- 規則のとおり: C・C+FT とも、「良い」の条件(2 つの種の両方が A の 2 本より小さい)を best でも満たしません。C+FT の小さい方(種 1、49.340 µs)も A 種 0(49.146 µs)より大きいです。
- 種のばらつき: 種 2 本の範囲は A 0.311・C 0.477・C+FT 0.747・A+FT 0.545 µs で、s_A(0.313 µs、3 本の範囲)はやや小さめの見積もりです。この 4 つの範囲から種 1 本の標準偏差を見積もると約 0.46 µs で、2 本の平均どうしの差の標準誤差も約 0.46 µs です。C+FT − A は +0.41 µs(悪い向き)なので、改善があるとしても約 0.5 µs(1% 程度)より小さいと見るのが妥当で、10 µs の実用上の差はありません。ばらつきをもっと大きく見ても、閾値が広がるだけで判定は「同等」のままです。
- 「C は 4 通りすべてで A より悪い向き」は、best と last が同じ種の重みなので実質 2 つの種です。本当の差が無くても 1/6 の確率で起きるので、「混ぜると悪くなった」とも言えません(0 章にもこの注を足しました)。

### 9.6 後から見た内訳(判定には使いません。読み方の注意)

- **差は場面で一様ではありません。** C の +0.43 µs は、2 つのシーンでの大きな悪化から来ています: 20261010-152707-0001(ジャンル 5)+4.7 µs、20261010-193638-0003(ジャンル 4)+4.4 µs。どちらのシーンも C・C+FT の 4 本すべてが A の 2 本より悪く、全体の差への寄与はこの 2 シーンで +1.03 µs、残りの 9 シーンで -0.60 µs です。ほかの 9 シーンだけで比べると C が平均 0.78 µs、C+FT が 0.94 µs 小さい向きでした(C が A より小さいシーンは 11 のうち 8、C+FT は 9)。ただし、9 シーンの差は A+FT − A のシーンごとの揺れ(-2.0〜+1.2 µs)と同じくらいで、後から選んだ分け方なので、改善の証拠にはなりません。

## 1. 結論

**反証できませんでした。RL のベストラップは、ユーザーのシミュレーターの規則の中では本物です(valid = true)。**

- 停止から 1 周は **8.092 秒**(教師 8.931 秒)、フライングラップは **7.656 秒**(教師 8.370 秒)です。
- 元の sim-core.js・現行コース・ブラウザと同じ設定で、作り直した値は RL の段の値と完全に同じでした。
- 33 ゲート・黒シートの全幅の横断・衝突 0 は、ユーザーの確認器と自前の確認器の両方で通りました。
- 小区間を 8 分の 1 にしても、開始を大きくずらしても、周は成立しました。

ただし、次の 3 点は注意が必要です。周の有効さは変わりませんが、実車への持ち込みと報告の書き方に効きます(5 章)。

1. **縦と横の頭打ちが別々という sim の単純化を、教師より多く使っています。** 合成の加速度が μg を超える時間は 37% で、教師は 17〜21% です。摩擦円を入れた反事実の物理では、RL も教師もぶつかりました。
2. **舵の速さに敏感です。** 舵の速さを 1.2 から 1.0 rad/s にすると、RL は衝突します(教師は完走します)。1.5 rad/s とブレーキ 1.0 m/s² でも、連続周回の 2 周目に衝突します。μ・遅延・時定数には、RL のほうが教師より強いです。
3. **学習済み ONNX の 8.964 秒は条件が違います。** この値は遅延 1 フレームと前進ゲイン 1.01 の条件です。同じ条件の RL は 8.37〜8.48 秒なので、差は 0.87 秒ではなく 0.48〜0.60 秒です。それでも RL のほうが速いです。

## 4. 物理の単純化の使い方と、操作の荒さ

### 4.1 縦と横の頭打ち(摩擦円がない)

sim-core は、加速(6 m/s² と μg)・ブレーキ(1.2 m/s²)と、横(ヨーレートを μg/|v| で頭打ち)を別々に制限します。そのため、曲がりの限界で走りながら同時に加速できます。この使い方をフレームごとに数えました(`rl_check_r1/friction_actions.json`)。

|---|---:|---:|---:|---:|---:|
| 合成の加速度 > μg の時間 | 37% | 37% | 21% | 17% | 29% |
| 合成 / μg の 95% 点 | 1.16 | 1.17 | 1.05 | 1.05 | 1.10 |
| 合成 > 1.25 μg の時間 | 2.5% | 2.3% | 0% | 0% | 0% |
| 横の頭打ちのまま加速している時間 | 13% | 11% | 6% | 2% | 9% |
| 小区間のうち横の頭打ち(sim の traction_limited) | 37% | 37% | 14% | 9% | 24% |

- 反事実として、自前の積分に摩擦円(縦の加減速を √((μg)² − a_lat²) まで)を入れました。どちらの制御もこの変更を知らない条件で走らせると、RL は 8.20 秒に柱の脚(ゲート 0 の手前の下の壁)へ、教師は 3.54 秒に黒シートの手すりへ衝突しました(`friction_circle.json`)。
- つまり、**どちらもこの単純化に頼っています。RL だけの抜け道ではありません。** ただし RL のほうが多く使っています。教師との差 0.84 秒のうち、どれだけが実車でも残るかは、この確認では言えません。

## 5. 見つかった問題・注意

1. **【報告の書き方】学習済み ONNX と条件の違う値を並べている。** rl.md の要約と 1 章の表は、RL の遅延 0 の 8.092 秒と、遅延 1・前進ゲイン 1.01 の 8.964 秒を並べています。そのうえで「ONNX より 0.872 秒速い」と書いています。同じ条件の RL は 8.37〜8.48 秒なので、差は 0.48〜0.60 秒です。結論(RL が速い)は変わりません。
2. **sim の単純化(縦と横が別々の頭打ち・横の頭打ちに損がない)を、教師より多く使う。** 摩擦円の反事実では RL も教師もぶつかるので、RL だけの抜け道ではありません。ただし、実車でも教師より速く走れるとは言えません。
3. **舵の速さに敏感。** 舵の速さ 1.0 rad/s で衝突し(教師は完走)、1.5 rad/s とブレーキ ≤ 1.0 m/s² では 2 周目に衝突します。RL の段の「頑健さ」(ROB24・E0〜E5)は開始の姿勢についての主張で、物理のずれには当てはまりません。
4. **REC60 の「noise」の 30 条件は、RL には効かない。** 雑音は sim の `observe()` のレイにだけ掛かり、RL の観測(`features.mjs`)はそれを使いません。そのため REC60 は、実質的に「開始 ±3 cm・±3° の 60 条件」です。この確認では、格子・範囲の外・全ゲートの開始で補いました。
5. **ユーザーの確認器だけでは RL の周を合格にできない(仕組みどおり)。** 確認器は外部の ONNX の証跡を要求します。RL の周で落ちたのは証跡の項目だけで、物理と判定の項目はすべて通りました。
6. ゲートを 1 つ外すと、観測の「目標ゲート」が外したゲートのまま残ります。そのため方策は戻ろうとして、内側の手すりにぶつかります(舵の速さ 1.0 rad/s の衝突がこれ)。sim は外したゲートでは終わらないので、外れたあとの立て直しは学習されていません。
7. 方策は正解の位置・コースの形・目標ゲート・障害物までの距離を観測に使います。教師としては問題ありません。ただし JetFormer は、カメラ・ToF からこの走りを再現する必要があります。

## 6. 直すべきこと(この段の判断)

- rl.md の要約・1 章の表・findings で、学習済み ONNX の 8.964 秒が「遅延 1 フレーム・前進ゲイン 1.01」の値だと明記してください。並べる RL の値は、同じ条件の 8.37〜8.40 秒(遅延 1)と 8.48 秒(遅延 1 + ゲイン 1.01)にしてください。「0.872 秒速い」は「同じ条件で 0.48〜0.60 秒速い」に直してください。
- 周の有効さ(H1)を取り消す問題は、見つかりませんでした。

## 0. 結論

**オフライン強化学習の学習と評価に使ってよい。** 以下の1件のバグを直してから、ラベルとデータセットを作り直した。

- 行動ラベル・未来の行動・報酬・リターンは、生ログから独立に計算し直した値と全部一致した。
- 場所の印(R1・GM・DE)は、10/10 の診断(R1 の進入速度、DE 出口のヨー)を数字のうえで再現した。

**直したバグ(1件)**: 強い衝突で基板が再起動すると、衝突と、その後の失敗による交代が、再起動の前後のマスク(区間の外)に入っていた。
- その罰(−1・−2)がリターンに入らず、区間は「打ち切り」で終わっていた。
- 該当は 155820 と 181504(どちらも train)で、AI の衝突 4件(7.1〜11.1G が3件)と、失敗による交代 2件。
- いちばん強い衝突の手前が「悪くない状態」に見えていた。
- 直した中身(`tools/label_events.py` の `carry_penalties`): 罰を直前の AI の区間の最後のフレーム(衝突の 0.23〜0.5秒前)へ移し、その区間を「失敗による交代」で終わらせる。テスト 2件を足した。
- 作り直した結果、変わったのはこの2本のログの `reward`(10フレーム)・`mc_return`(586フレーム)・`end_code`(141フレーム)だけだった。

**後の段階が知っておくべき制約(重要な順)**

1. **検証用の AI のデータでは R1 を判定できない。**
   - val の AI のログ(172505・204208)には、R1 の通過が 4回しかなく、R1 の衝突は 0回。
   - AI の R1 の強い衝突 11回のうち 9回は 173445(ai_run_007、train)にある。
   - ゲートC の R1 の判定は、ログ単位の交差推定(下の 5分割案)で、173445 を保留した fold で行うしかない。
2. **介入の検証セットは、ほとんどが学習用のログから作られている。**
   - 29窓のうち 26窓(採点 1,352/1,570)は、ai_mix の train の AI のログから作られている。
   - 採点するフレーム(人の修正)そのものは学習に入らない。ただし、交代の直前 3秒の AI のフレーム 1,524枚は train の使えるフレームに入っている。
   - ai_mix で学習した方策と、人だけで学習したモデルB をこのセットで比べるのは公平でない。
3. **リターンには打ち切りの偏りがある。**
   - 使えるフレームのうち、失敗以外の終わり(打ち切り・ログの終わり・運用上の交代)から 3.3秒以内にあるものは、人で 14.5%、AI で 8.7%。
   - これらのリターンは小さく出る。n ステップのアドバンテージでは、`end_code` が 1(失敗)の区間だけを終端とし、それ以外は V で補うか外す。
4. **人の操作値に、受信機の読み取りの異常がある。**
   - 使える人のフレームのうち 84枚(val 35枚)で、未来のスロットルが 900µs 未満(最小 149µs)だった。10ms のサンプル 1〜2個だけの値。
   - clean_driving(モデルB の学習)にも同じものがある。方策の学習・評価では、`future_actions` が 950〜2050µs に収まるフレームだけを使うことを勧める(外れるのは 89枚。936µs の異常も含む)。
5. **AI のフレームはすべてジャンル5(低速走行)。** ジャンル4(高速走行)は人のデータだけ(使える 9,955枚)。

### 2.3 AI の行動ラベル(out を評価時のゲイン ステア 1.3・速度 1.0 で割り戻した値)

生の AI_CMD から独立に計算し直して照合した。計算は、ステア = 1443 + (out − 1443)/1.3、スロットル = out(速度のゲイン 1.0 は前進側も同じ)。

| 照合 | 一致 / 照合数 |
|---|---|
| `action_label`(AI のフレーム全部) | 22,088 / 22,088(差 < 0.01µs) |
| `future_actions[:,0]`(future_valid の AI のフレーム) | 18,875 / 18,875 |
| `future_actions[:,k]`(k=1..9、AI_CMD の i+k 行。途切れのないもの) | 163,341 / 163,341 |
| `vehicle[:,:2]` = 1フレーム前の行動ラベル | 21,709 / 21,709 |

**記録時のゲインが一定の区間で、raw との関係を見た。** 張り付き・hold を除くと、割り戻した値 − 1443 = (記録時のステアゲイン/1.3)·(raw − 1443) + trim/1.3 が、0.5µs 以内で 100% 成り立った。
- ゲインが一定のログ: 155820(1.0/1.0)、160306・163247(1.6/1.0)、171639(1.0/0.8)、172505(1.5/0.9)、181504(1.0/2.0)、203924(1.7/1.35)、204605(1.5/1.0)。
- 204208 は2通り、172910 は21通り、173445 は13通りのゲインが混ざっていた。
- 例外は 181504 の 6.7% だけ。食い違う 143フレームは、すべてリカバリー(assist=2)・中止(assist=3)のフレームで、出力が上書きされている。もともと行動ラベルから外してあるフレーム。
- 振れ幅の比(ラベル/raw)の中央値は、どの組み合わせでも g/1.3 に一致した。例: g=1.0 で 0.769、1.6 で 1.231、1.8 で 1.385。

**注意(仕様どおりだが、知っておくこと)**

- スロットルは評価時のゲインが 1.0 なので、ラベル = 実際に出した値になる。記録時の速度のゲイン(0.8〜2.0)は、AI のスロットルのラベルに入ったまま。
- ステアが上下限に張り付いたフレームは、ラベルが 1102.2µs(または 1783.8µs)になる。本当はどれだけ切りたかったかは分からない。
  - 張り付いたフレームの数: 173445 は 987、172910 は 536。
  - 割り戻した後に |ステア − 1443| ≥ 340µs の割合は、使える AI のフレームで 14.0%、人で 19.8%。
- 使えるフレームの k=0 の分布:
  - |ステア − 1443| の中央値: AI 77µs、人 116µs。
  - スロットル − 1498 の中央値: AI −141µs、人 −183µs。人のほうが速い。

### 2.7 train / val の分け方

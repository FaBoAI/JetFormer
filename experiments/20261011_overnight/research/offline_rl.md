## 0. 結論

**判定: 「オフライン強化学習の最小形」を今すぐ始める。本格的なQ学習(CQL・IQL・TD3+BCのアクター・クリティック)とオンライン強化学習は後にする。Decision Transformer はやらない。**

| 時期 | やること | 理由(要点) |
|---|---|---|
| **今(1〜2週間)** | ① 報酬・失敗ラベルの作成(衝突・交代・リカバリー・速度)② AI走行データを学習に使えるデータセット形式にする ③ **価値関数をモンテカルロ回帰で学習し、アドバンテージで「良い行動」の印を付けて条件付き模倣学習**(π*0.6 の RECAP 型)。比較のため重み付き模倣(AWR型)も作る | Q学習をしないので、データに無い行動(OOD)を過大評価する問題が起きない。推論グラフはほぼ同じ(入力トークン1個)で TensorRT 2ms のまま。Jetson で回せる。今のデータに「決定的な場面で、良い行動と悪い行動が両方ある」(R1 の進入速度など)ので、理論上もBCより得をしやすい条件([Kumar 2022])に合っている |
| **後で(データ2〜3時間・ロカライズ・評価手順ができてから)** | IQL(エクスペクタイル)+チャンク単位の n ステップ価値([Q-chunking])、TD3+BC/BC-SAC型の行動正則化。その後、介入を報酬にした実車でのオフライン→オンライン微調整(RLIF / HIL-SERL / RLPD / WSRL) | ステッチング(良い区間のつなぎ合わせ)で人の最良ラップに近づける可能性がある。ただしハイパーパラメータに敏感で、シミュレータなしでは選べない。クラウドGPUが要る |
| **やらない** | Decision Transformer / リターン条件付き教師あり学習、素の CQL を Jetson で端から端まで、実車でゼロからのオンラインRL | 衝突の有無は「運」(数十msの差)に左右されるので、リターン条件付けは失敗しやすい([Paster 2022]、[Brandfonbrener 2022])。CQL は調整が難しく、小規模データでは BC に負けることが多い([Kumar 2022]、[Koirala 2024]) |

**先に無いと始められないもの**(6章に詳細):
1. AI側のデータを学習に使うためのデータセット作成(行動ラベル=実際に出した `out`、ゲインの扱い、補助中・hold・基板再起動の除外)
2. 失敗ラベル(衝突・交代の理由・リカバリー)と報酬の自動計算。進みの報酬には、コース図への当てはめを**人のログ12本にも広げ、保留検証をする**こと(今は AI走行ログ5本だけ、1.5節)
3. **1回の走行=1設定・4分以上**の運用(10/10 夜の3本もゲインと先読みを走行中に変えていた)と、交代の理由の記録
4. 電源の安定(AI走行ログで基板の再起動が20回)
5. 実車でのA/B/A評価の手順(衝突/周の 1.6倍の差を見分けるには **各条件60周**必要)

**最小実験の要約**(5章): 既存の全ログ(人 約22分+AI 約12分)で、報酬 = コース上の進み(当てはめが無いログは前進距離で代用)− 衝突 − 交代、価値 = 3秒先までの割引リターン(価値には、学習時だけ使える「コース上の位置」も入力してよい)、N=30フレーム(1秒)のアドバンテージで上位約30〜40%に「良い」の印を付けて JetFormer を再学習。オフラインで「R1 手前で減速するか」「保留データで価値が衝突を予測できるか(AUROC)」「直線で遅くなっていないか」を確かめてから、実車で ベースライン → 新モデル → ベースライン を各60周。

| 区間 | 006 | 007 | 010 | 101 | 読み方 |

- ログ全体では、AI の「進み / 走った距離」は 0.91〜1.03 だった。人が交代した後の区間(位置直し・後退・向き直し)は 0.47・0.29・−0.31(007・010・101)で、**前進距離の報酬は、人の位置直しにも点を与えてしまう**。
- 1秒先までの報酬和(AIのフレーム 13,371個)で比べると、2つの報酬の順位相関は 0.75、RECAP 型の「良い」印(上位35%)の一致は 83%、「良い」集合どうしの重なり(Jaccard)は 0.60 だった。3秒先でも 0.73・81%・0.56 で、**ほぼ変わらない。違いは雑音ではなく、区間による系統的な偏り**である。
- 偏りの向き(3秒先、「良い」になったフレームの割合、前進距離 → 進み): **GM 53% → 26%**、HS 3% → 17%、LH 1% → 9%、R1 24% → 19%。前進距離を報酬にすると、芝で速くタイヤを回す行動が「良い」に入りやすい。これは 3.2節で心配した「芝で空転して点を稼ぐ」報酬の悪用が、データ上でも起こりうることを示す。
- もう一つの読み方: 生のリターンで上位を選ぶと、区間で「良い」の割合が 1%〜68% と大きく偏る。**だからリターン(filtered BC)ではなく、状態ごとの基準を引いたアドバンテージで印を付ける必要がある**。価値関数が弱いと、この偏りがアドバンテージにも残る。そこで、**価値関数にはコース上の位置(進みの位相・区間)を入力として与える**(学習時だけ使う「特権情報」。方策は位置を使わないので、走行中の位置推定は要らない。非対称アクター・クリティック [R54] と同じ考え方)。

**結論**: 進みの報酬は、AI走行ログ5本では今すぐ使える。人のログ12本は、同じ当てはめを回せば使える見込み(カメラの目印は人のログにも写っている)。ただし、保留検証(目印を半分隠して残差を見る)を済ませるまでは、**前進距離の報酬と両方で学習し、結果が変わらないことを確かめる**(感度分析)。

## 2. 文献調査(2022〜2026)

### 2.1 いつオフラインRLが模倣学習(BC)に勝つか

- **Kumar, Hong, Singh, Levine (ICLR 2022)「When Should We Prefer Offline RL Over Behavioral Cloning?」** [R1]
  - 専門家データでも、**少数の「決定的な状態」**(そこだけ特定の行動が必要)がある場合と、初期状態が変わる場合は、オフラインRLがBCに勝ちうる。
  - ノイズを含む準最適データでも、最適方策の行動がデータに含まれていれば、長いホライズンでBCより有利になる。
  - 逆に、素の CQL は BC に負けることが多く、調整が要った(AntMaze Medium・専門家データで、素の CQL 20.8% に対し BC 53.2%、調整後の CQL 55.9%。表1)。
  - 上位k%だけ使う filtered BC は使えるサンプルが減るので、スケールが悪い。
  - **JetFormer への意味**: R1 の進入速度はまさに「決定的な状態」で、しかもデータに良い例と悪い例が両方ある。AI は 5500 eRPM 未満の進入で 21回中1回しか当たらず、6200 以上では 8回中6回当たった。人は 13回中0回と 9回中4回だった(`collision_map.md`)。DE の向きも、人のデータに良い例(左寄り +15°)がある。
- **Brandfonbrener ほか (NeurIPS 2021)「Offline RL Without Off-Policy Evaluation」** [R2]: 行動方策の価値を推定して1回だけ方策を改善する one-step 法は、D4RL の多くで反復型(CQL など)と同等以上だった。外挿の誤差が積み重ならないからである。→ 最小実験を「1回だけの改善」にする根拠。

### 2.2 代表的なオフラインRL手法と、JetFormer との相性

| 手法 | 中身 | 相性 |
|---|---|---|
| **CQL** [R3] | データに無い行動のQ値を下げる正則化 | ✕(今は)。α や正則化の調整が難しい。F1TENTH のオフライン比較では「critic と保守項の損失が発散して調整が難しい」と報告されている [R12]。端から端まで画像でやるのは重い |
| **IQL** [R4] | データにある行動だけで Q/V を学ぶ(エクスペクタイル回帰)。方策は AWR で取り出す | ○(後で)。OOD 行動を問い合わせない。FastRLAP の事前学習にも使われた(τ=0.7)[R20]。一方 RoboRacer の実車比較では、IQL 事前学習+15分の微調整は、継続オンライン SAC より遅く、ばらつきも大きかった(平均ラップ 12.13秒・σ1.20 対 10.44秒・σ0.20、古典制御 10.97秒)[R22]。ただし IQL のデータは SAC の学習走行から作っており、その一部はシミュレーションの可能性がある(論文の記述があいまい)|
| **TD3+BC** [R5] / **BC-SAC** [R24] | アクターの損失 = −Q + BC 項 | △(後で)。JetFormer の決定的な出力ヘッドとそのまま合う。Waymo の BC-SAC は、最も難しい場面で失敗(安全事象)を 38%以上減らした。ただし学習は、記録から作った閉ループのシミュレーション(2D 自転車モデル、他車は記録の再生で反応しない、10秒の区間)の上で行っており、純粋なオフラインではない [R24] |
| **AWR / AWAC** [R6][R7] | 行動をアドバンテージの指数で重み付けして回帰 | ◎(今)。損失に重みを掛けるだけで、構造を変えない。ただし π*0.6 の比較では「AWR は遅い方策になりスループットが低い」とされた [R9] |
| **Cal-QL** [R8] | CQL の Q 値をスケールを保って下限化し、オンライン微調整で崩れにくくする | ○(オンライン微調整の段階)。PA-RL は Cal-QL で OpenVLA を実機 40分で成功率 40% → 70% にした [R16] |
| **Decision Transformer** [R10] | 目標リターンを条件に行動を系列予測 | ✕。確率的な環境では「運良く得たリターン」で条件付けてしまい失敗する [R11]。理論上、ステッチングに必要な仮定が動的計画法より強い [R12b]。F1TENTH のシミュレーション比較では、複数コースで DT が良かった場面もある [R12] |

### 2.3 アドバンテージ条件付き方策(RECAP / CFGRL)— 最小実験の土台

- **π*0.6 / RECAP(Physical Intelligence, 2025)** [R9]
  - 価値関数: 分布型(201ビン)、**モンテカルロ回帰**(TD ではない)。報酬は1ステップごとに −1、失敗で −C_fail。
  - アドバンテージ: Nステップ(事後学習で N=50。事前学習では N=エピソード長)。
  - 「改善の印」= 1[A > ε]。ε は「良い」の割合が事前学習で約30%(デモデータの中で)、微調整で約40%(各反復の評価走行の中で)になるように選ぶ。洗濯の課題では約10%まで絞った(付録の記載)。
  - 学習中に印を **30% の確率で落とす**。これで、条件付き方策と条件なし方策の両方として学習でき、推論では分類器なしガイダンス(CFG)が使える。
  - **人の修正操作は常に「良い」**とする。
  - 結果: 最も難しいタスクで処理量が2倍以上、失敗率が約半分。同じデータの AWR と PPO は「はるかに及ばない」(AWR は遅い方策)。
  - 規模: 1反復あたり 300〜600 試行。数万時間の事前学習の上で行っている。
- **CFGRL(Frans, Park, Abbeel, Levine 2025)** [R13]: 拡散のガイダンス重みが「方策改善の強さ」になることを示した。教師あり学習と同じ手軽さで、データの行動より良くできる。価値関数の学習方法は扱っていない。
- **JetFormer への当てはめ**: すでに「走行ジャンル」をトークン+ジャンル別ヘッドで条件付けしている。これと同じ仕組みで「良い/悪い」の印を入れられる。全ヘッドを1つの線形層でまとめて計算しているので、「良い」ヘッドと「全データ」ヘッドの出力は1回の推論で両方出る。CFG のような外挿 a = a_all + β(a_good − a_all) も追加の計算なしでできる。ただし、L1 回帰(中央値)の決定的な出力で β>1 の外挿が正しい保証はない。実験用のつまみとして扱う。

### 2.4 拡散・フロー方策+Q、行動チャンク

- **Q-chunking(Li, Zhou, Levine, NeurIPS 2025)** [R14]
  - 批評家を行動チャンク Q(s, a_{t:t+h}) で定義すると、補正なしの n ステップ backup になり、バイアスが無い。
  - 標準は h=5(「たいてい良く、計算も安い」)。h を {1, 5, 10, 25, 50} で比べた実験(cube-triple)では、h=10 まで良くなり、h=25 は序盤は速いが最終性能は h=10 に届かず、**h=50 は1回も成功しなかった**。長すぎるチャンクは反応性を損なう、と著者は推測している。
  - 行動の制約は2通り。QC はフロー型BC方策から N 個のチャンクを出して Q 最大を選ぶ(KL ≤ log N − (N−1)/N で、N が制約の強さになる)。QC-FQL は BC 項で距離(W2)を抑える。
  - **制約**: 予測した h ステップを「開ループで1つずつ実行」する前提で、著者自身が「高頻度の制御フィードバックが欠かせない場面では性能が悪い可能性がある」と限界に書いている。
  - JetFormer は毎フレーム再計画し、先読みk番目の1要素だけを実行している。そのため、n ステップ backup は「実際に実行された10フレームの列」で定義し直す必要がある。
- **Flow Q-Learning(FQL)** [R15]: フローBC方策を1ステップ方策に蒸留して Q を最大化する。推論は1回。
- **IDQL** [R15b] / **Diffusion-QL** [R15c] / **PA-RL** [R16] / **DSRL** [R17]: 生成型の方策(拡散・フロー)から候補を出して、Q で選ぶ・Q の勾配で直す・潜在ノイズを RL で操る。
  - JetFormer の出力は今は決定的な L1 回帰なので、これらは**生成ヘッド(小さなフローヘッド)を足してから**の話になる。トランク(ResNet+Transformer)の計算は1回で、ヘッドだけ数ステップ回すなら、推論時間はほとんど増えない見込み(未計測)。
- **VGAS(2026)** [R18]: 少数デモで微調整した方策(SmolVLA)から N 個のチャンクを出し、Transformer 批評家で選ぶ。LIBERO の平均成功率は BC 39.8% → 49.0%。「推論時の最良N選択は遅延を生み、高頻度の制御には使いにくい」と著者も書いている(遅延の数値は無い)。
- **ValueFormer(2026)** [R19]: 固定した DINOv3 の上の小さな因果 Transformer で、フレームごとの価値と「ミスの検出」を出す。実機(両腕のサンドイッチ組み立て)で、価値から作った学習の重みにより完了率 70% → 85%。ただし n=20 で、著者自身が「誤差の範囲」と書いている。**ラベルの作り方が一番難しい**という指摘は、私たちにも当てはまる。

### 2.6 運転・小型レースカー

- **FastRLAP(Stachowicz ほか, CoRL 2023)** [R20]: 1/10 RCカー(Jetson Xavier NX)で、画像からのオンラインRL。
  - 準備: RECON(低速ナビゲーションの大規模データ)で IQL によって符号器と価値を事前学習し、符号器を固定する。そのうえで、ゆっくり1周のデモから中間地点を取り出す。
  - 報酬: 「次の中間地点の方向への速度」− スタック(10)− 衝突(横加速度がしきい値超え)。
  - 位置: 屋内は T265 の視覚慣性オドメトリ、屋外は GPS+EKF。
  - **衝突を横加速度で検出し、スタック(3秒で0.5 m 未満)なら後退してやり直す**。これは私たちのリカバリー v2 とほぼ同じ仕組みになる。
  - 学習: RLPD(批評家10個のアンサンブル、デモ50%+オンライン50%)。学習はワークステーションで行い、車には推論だけを載せる(10Hz)。
  - 結果: オンライン学習は多くの場合20分未満(最短5分)で、デモ周より最大 40%(表Iの注では「40%超」)速くなった。屋内C では、ベスト 10.9秒・中央値 11.7秒(デモ 17秒、人の熟練者 7秒。熟練者は第三者視点で操作)、衝突の中央値 0。衝突の罰は C_collide = 0.2 s²/m × 横加速度、スタックの罰 10。
  - **示唆**: 私たちのコース規模(1周 約10秒)でも、オンラインRLは現実的な時間で動く可能性がある。ただし前提は、**位置推定(中間地点の方向)**、**自動リセット**、**車外の学習用GPU**の3つ。
- **RoboRacer の継続RL(Siegert ほか, 2026)** [R22]: 4コース(タイヤと床の組み合わせ2通り)で約10万勾配ステップ(40〜60分)事前学習し、5つ目のコースで15分微調整した。論文は「実データだけ」と書くが、IQL 用のデータ源の説明にはシミュレーションの学習走行が出てきて、はっきりしない。報酬は「進み(時間で正規化)×20 − 衝突×16 − 安全ボタンを離されたら×10」で、**私たちの「進み − 衝突 − 交代」とほぼ同じ形**である。
  - 継続 SAC は平均 10.44秒で、古典制御(MAP)の 10.97秒より速かった。
  - **IQL によるオフライン事前学習**(+同じ15分の微調整)は平均 12.13秒(最速 10.80・最遅 14.06秒)、ばらつきも最大(std 1.20秒)だった。著者は「可塑性は有望だが性能は低い」とまとめている。
  - オフラインだけで速さを上げるのは簡単ではないという、数少ない実車の比較になる。
- **F1TENTH オフラインRL(Koirala & Fleming 2024)** [R12]: **シミュレーションのみ**(F1tenth Gym / PyBullet)。オンラインの SAC/PPO は Austria コースで進み35%を超えられず、1周も完走できなかった。
  - 比べたのは IQL・CQL・AWAC・PLAS・TD3+BC・DT・拡散方策と、著者のリターン条件付き決定木(RCDTP)。Q 学習系は「既定のハイパーパラメータでまずまず」と書かれているが、IQL・TD3+BC を個別に評価した記述と周回の数値は本文で確認できなかった。CQL は「保守項と批評家の損失が発散」して調整が難しかった。
  - 1コースでは RCDTP、3コースを混ぜると DT が良かった。実車では試していない(sim2real は今後の課題)。
- **Waymax でのオフライン学習の比較(2025)** [R52]: Waymo Open Motion の約20万場面で、同じ Transformer 構造の BC と CQL を比べた。報酬は経路追従+TTC 2.5秒未満の罰+快適さ。閉ループ(1,000場面)で、成功率 BC-T 17.3% → CQL 54.4%、衝突率 31.1% → 4.1%。BC-T は学習損失は低いのに長いホライズンで失敗した。ただし評価はシミュレーションで、状態は地図・他車の位置まで入った整ったベクトル(画像ではない)、データは約20万場面と私たちより桁違いに多い。単著で査読前でもある。「状態がよく整っていてデータが多ければ、Q 学習が BC を大きく上回りうる」例であり、画像+少量データの私たちにそのまま当てはまるとは言えない。
- **Real-ORL(Zhou ほか 2022)** [R53]: 実機の操作タスクで 800 時間以上・6,500 試行を集めて比べた。オフラインRLは、別の作業のデータも混ぜて使えるときに模倣学習より良くなった。運転ではないが、「AI走行・失敗を含む雑多なデータ」を活かす根拠になる。
- **L2D(Viitala ほか)** [R33]: Donkey car の実機で、**コースアウトによる介入(disengagement)を学習信号**にしたオンラインRL。5分未満の操作で走れるようになった。
- **DeepRacer** [R34] / Duckietown [R35]: どちらも主にシミュレーションの PPO などからの sim2real。実機ログでのオフラインRLの研究は見つからなかった。
- **ReViND(Shah ほか, CoRL 2022)** [R21]: 実ロボットのナビゲーションログだけで IQL を学習した。報酬を変えると行動が変わることを実機で示した。
- **大規模な運転(参考)**
  - Waymo の BC-SAC [R24] とトヨタの PEBC(2025, nuScenes から作ったニューラルレンダリング環境で集めた固定データによる、カメラだけのオフラインRL)[R36] は、どちらも模倣よりも衝突を減らした。PEBC は、専門家の記録から作った「疑似正解軌跡」への BC 項で OOD 行動を抑え、同じ VADv2 の模倣に対して衝突率 73.0% → 51.1%(難しい場面 65.9% → 29.9%)にした。ただし経路の完了率は別の模倣手法(UniAD 57.4%)より低い 52.8% で、全面的な勝ちではない。
  - RAD(3DGS で作った環境で PPO+模倣正則化、衝突率が3分の1)[R37] と comma.ai(学習した世界モデルの中で方策を学習し、openpilot に搭載)[R38] は、**シミュレータを作る**方向の研究になる。
  - 私たちの規模では「後で」の選択肢。
- **小型車で、実車の「純粋なオフラインRL」でラップや衝突が良くなったという論文は見つからなかった。** 近いのは、FastRLAP(オフライン事前学習+オンライン)と RoboRacer(オフラインはオンラインに負けた)だった。

### 2.7 人の好みからの報酬(RLHF 型)

- Preference Transformer [R39]、CPL [R40](好みから直接方策を学ぶ、RL なし)、TrajHF [R41](運転軌跡の拡散モデルを人の好みで微調整し、「攻め/守り」の運転スタイルを出し分けた)。
- 私たちの主な目的(ラップタイム・衝突)は計測できるので、好みの学習は要らない。「走りのきれいさ」や駐車の出来のように、数値にしにくいものを後で扱うときの選択肢になる。

### 2.8 シミュレータなしの評価(OPE)

- **Fu ほか (ICLR 2021) DOPE** [R42]: 高次元の連続制御では、FQE・モデルベースが重要度サンプリング系より良かった(二次資料による。順位相関の表は本文で確認していない)。
- **Fujimoto ほか (ICML 2022)** [R43]: ベルマン誤差は価値の誤差の代わりにならない。有限データではベルマン方程式を満たす準最適解が無数にある。→ **TD 誤差でモデルを選ばない**。
- **Kumar ほか (CoRL 2021) オフラインRLの作業手順** [R44]
  - データ上の平均Q値が上がってから下がり続けたら過学習。**平均Q値が山になったチェックポイントを選ぶ**(アクターが遅れて動く場合は山の次)。TD 誤差と CQL の正則化項は「過小学習(容量不足)」の検出にだけ使う。TD 誤差でモデルの良し悪しを比べないのは、上の Fujimoto 2022 の指摘と合う。
  - 実機のデータは 1タスク 100〜200 軌跡(Sawyer 100、WidowX 200 で成功率 35% のスクリプト方策)。評価は 9〜12 試行。
- **ALOE(2026)** [R45]: 混ざったデータ(デモ・過去方策・介入)から、チャンク単位の TD で「今の方策」を評価する。進捗型の価値は過去の行動の平均を表してしまう、という指摘がある。
- **開ループ指標の限界**: nuScenes では自車の状態だけの MLP が開ループ指標で最先端と並んだ(Li ほか, CVPR 2024)[R46]。NAVSIM [R47] は非反応型の疑似シミュレーションで、この限界を和らげる。→ **µs 誤差(今の val L1)では走りの良し悪しは決まらない**。最終判断は実車でする。

## 3. JetFormer の条件での判断

### 3.1 データ

- 量: 人の操作 約24分(動いている時間。人のログ 20.1分+AI走行ログの人側 3.6分)+AIの操作 11.8分。周は約140。失敗(衝突)はAI 95回・人 53回、交代 57回。
- RECAP の1反復(300〜600試行)と比べると、「試行=周」と数えて約1/2〜1/4になる。数万時間の事前学習も無い。**価値関数をゼロから大きく学習するには少ない**。そこで、BC で学習済みのトランクの特徴を固定し、小さな価値ヘッドだけ学ぶ。
- 行動方策が混ざっている: 人(速い・遅い)、3つのモデル、走行中に変えたゲインと先読み。オフラインRLにとっては**行動の多様さ(探索)になるので、むしろ役に立つ**。ただし、交代の理由とゲインは行動ラベルに正しく反映させる必要がある(3.3)。
- 抜けているもの: リカバリーの成功例(v2 が起動していない)、交代の理由、人のログのコース上の位置(AI走行ログ5本は後処理で有る、1.5節)、走行中に使える位置推定。

### 3.2 報酬

| 候補 | 今作れるか | 判断 |
|---|---|---|
| コース上の進み(コース図への当てはめ)| △→○(AI走行ログ5本は今ある。人のログは当てはめを回せば作れる見込み)| **主報酬**。後処理(未来のデータも使う)なので、走行中には使えないが、オフラインの報酬には問題ない。保留検証が済むまでは下の前進距離と両方で学習して比べる(1.5節) |
| 前進距離(eRPM)| ○ | 当てはめが無いログの**代用**。芝(GM)で過大、ヘアピンで過小になる偏りがある(1.5節) |
| 衝突(2.5G)| ○ | 有無で −1 m 相当(下の値は初期値。感度を見る) |
| 交代(衝突後・走行中・スタック)| ○(理由は推定)| −2 m 相当。運用上の交代(ゆっくり/その他)は報酬に入れず、エピソードを切るだけにする |
| リカバリー開始 | ○ | −0.5 m 相当(v2 が動けばデータが出る) |
| 滑らかさ(ステアの変化、限界張り付き)| ○ | 小さな罰か、評価の制約にとどめる(5〜15%が目標) |
| 周回タイム | ○(途切れた周は除く)| **評価用**。報酬にすると周の区切りに依存し、最初の周にラベルが付かない |
| 走行中の位置(リアルタイム)| ✕ | ジャイロ+eRPM だけでは 1周で 0.5〜3.7 m ずれる。後処理の当てはめは未来のデータを使う。オンラインRL(FastRLAP 型)で中間地点への速度を報酬にするなら、画像の場所認識か外部の位置計測が要る(後で) |
| ToF の危険度(TTC)| ○ | 報酬ではなく、安全の制約・評価の副指標に使う |

**報酬の悪用(reward hacking)の危険**:
- 芝や PTFE でタイヤを空転させると、前進距離が稼げてしまう。**データでも、前進距離の報酬では GM(芝)の「良い」の割合が 53%、進みの報酬では 26% だった(1.5節)**。進みの報酬にすれば、この悪用はかなり減る(ただし当てはめ自体が車輪の回転数(hall)を距離に使うので、目印と目印の間の空転は完全には消えない)。
- 進みの報酬は、ヘアピンで内側を削るほど得をする。内側の壁(R1 の黒いスポンジ、LH のフラップ)に当たる方向へ寄せる力になるので、衝突の罰との釣り合いを感度分析で見る。
- 2.5G 未満で壁をこすりながら走ること(DE の典型)は、罰を受けない。
- 一段高いショートカットを通ったときの扱いが決まっていない。
- 速度報酬が強すぎると、R1 で強く当たる方向に寄る。

### 3.3 行動空間(10フレームのチャンク)

- 今の学習の目標は「実際に出た未来10フレームの操作値」なので、**チャンク=実際に実行された列**として扱えば、アドバンテージ条件付け・AWR とそのまま合う。
- AI 側のデータの行動ラベルは `AI_CMD.out`(ゲイン後に実際に出した値)にする。ゲイン>1 で出した行動を学習したモデルは**ゲイン 1.0 で走らせる**。または、ゲイン前の空間に戻して `(out − 中心)/ゲイン + 中心` を学習する。どちらかに統一しないと、出力が膨らむ。
- 「現在の操作値」の入力は、人のデータではスティック、AIのデータではモデルの前回予測(ゲイン前)になっている。どちらの意味で学習するかを決めて、データセット作成側で揃える。今の作成コードは AI 側のサンプルを使わない(`dataset_card`: SELECT=AI のサンプルは使わない)。
- `assist≠0`(後退の受け付け・リカバリー)と `hold`・基板再起動のフレームは、方策の目標から除外する。ただし、価値の学習には遷移として残す。
- Q 学習(後で)を入れる場合: JetFormer は毎フレーム再計画するので、Q-chunking の「開ループのチャンク」とは違う。批評家の n ステップは「実行された列」で定義し、その列を出した方策との差は行動制約で抑える。

### 3.4 分布のずれ・OOD 行動

- アドバンテージ条件付け・AWR は、**データにある行動の中から選び直すだけ**なので、OOD 行動の過大評価が起きない。安全側で、最初の一歩に向いている。
- そのかわり、改善の幅はデータの中の良い行動に限られる。人の最良ラップ 7.2秒より速くはならない。ステッチングも弱い(one-step)。
- Q の最大化(CQL・TD3+BC・FQL)は改善の幅が大きい。一方で、壁際の「データに無い速度」を過大評価する危険がある。シミュレータが無いので、失敗が実車の衝突として出る。だから「後で」にする。
- ToF ガードは、RL 方策の外側の安全の床として残す(シールド)。評価のときは「記録のみ」と「ON」を分けて計測する。

### 3.5 シミュレータなしの評価

- 段階1(オフライン・合否): 5.4 の4項目。
- 段階2(実車): A/B/A、各60周(1.4)。
- FQE などの OPE は**順位付けの参考**にとどめる(2.8)。
- 将来、3DGS や世界モデルでコースを再現できれば評価の費用が下がる([R37][R38])。ただし作る費用が大きいので、優先度は低い。

### 3.7 リスク

1. **ラベルの交絡**: 交代は人の注意力にも左右される。運用上の交代を失敗と数えると、価値がずれる。
2. **非定常**: 電圧低下・基板再起動・ゲインの変更・モデルの違いで、同じ状態でも結果が変わる。価値が「その日の電池」を学ぶおそれがある。
3. **過学習**: データが少ないので、価値が訓練データのリターンを覚えてアドバンテージが 0 に潰れる。**ログ単位の交差推定(out-of-fold)**で避ける。
4. **遅くなる方向への崩壊**: 衝突の罰が強すぎると、全体に遅い方策になる。RECAP も「AWR は遅い方策」と報告している [R9]。直線のスロットルを監視する。
5. **実車の危険**: 速くなったぶん、衝突は強くなる。ToF ガードと人の交代はそのまま残す。
6. **評価の統計**: 各60周を集めないと、良くなったかどうか分からない。

## 4. 推奨

### 今やる(オフラインRLの最小形+データ整備)

- 報酬・失敗ラベル、AI データのデータセット化、運用ルール(6章)。
- **RECAP 型のアドバンテージ条件付き JetFormer**と、その対照の **AWR 重み付き BC**。
- 人の修正区間は「良い」に固定する(RECAP・IWR と同じ)。
- 理由: 構造の変更が最小で、OOD の危険が無く、Jetson で回せる。今捨てている AI 側 12分と失敗の前後を使える。決定的な状態(R1・DE)に、良い行動と悪い行動の両方がある。

### 後でやる(順番に)

1. 価値ヘッドを**走行中の危険モニタ**として使う。ValueFormer [R19] のように、価値が急に下がったら減速するか警告する。記録のみから始める。
2. 走行中に使える位置の手がかり(画像の場所認識で、コース上の進み 0〜1 を出す)。後処理の当てはめ(1.5節)を教師にできる。オンラインRLの報酬と、走行中の区間別の評価に使う。
3. IQL(エクスペクタイル τ≈0.7)の価値と、実行された10フレーム列での n ステップ backup。クラウドGPUで学習する。
4. 生成ヘッド(小さなフロー)を足して、最良N選択(QC・VGAS 型)か FQL。
5. 実車でのオフライン→オンライン: 介入を報酬にする(RLIF)、RLPD/WSRL/Cal-QL、自動リカバリーをリセットに使う、ToF ガードを ON。FastRLAP・HIL-SERL と同じく、学習は車外で行う。

### やらない

- Decision Transformer、リターン条件付き教師あり学習。
- 素の CQL を Jetson で端から端まで。
- 実車でゼロからのオンラインRL。
- 今の段階でのシミュレータ(3DGS・世界モデル)作り。

## 5. 最小実験(MVE)

### 5.1 データ(追加収集なしで第1回のオフライン検証ができる)

- 2026-10-10 の全 raw ログ: 人のログ 21.8分、AI走行ログ 21.4分(うちAI側 12.3分)。
- 除外: `hold`、基板再起動の前後 0.5秒、`vehicle_valid=False`、途切れ(>0.2秒)をまたぐ区間、駐車ジャンル。
- 実車評価の前に、下の運用ルールで **AI 走行 約100周を追加**する。ゲイン固定(1.0 / 1.3 / 先読み3)、リカバリー v2 ON、交代は「止まって2秒」か「明らかな危険」のときだけ、交代の理由を記録する。
  - 時間にして AI 約16分(10秒/周)。電池4〜5本に分ける。
  - これが RECAP の「1反復」にあたる。

### 5.2 報酬と価値

- 1フレーム(1/30秒)ごとの報酬:

  `r_t = Δp_t − 1.0·[衝突] − 2.0·[失敗の交代] − 0.5·[リカバリー開始]`(単位 m)

  - Δp_t = コース上の進みの増分(`progress_cum_m` の差。後退・逆走は負になる)。当てはめが無いログ・フレームは Δp_t = max(0, −eRPM × 0.5e-3)·Δt で代用する。
  - **比較のため、全部を前進距離にした報酬でも同じ学習をする**。2つで「良い」の印が 83% 一致する程度なので(1.5節)、結果が大きく変わるなら、報酬の選び方が効いているということになる。
  - 失敗の交代 = 衝突後3秒以内、走行中、スタック。
  - 運用上の交代はエピソードを切るだけにする。
- 割引 γ=0.99(30fps で実効 約3.3秒)。
- 価値 V(o_t): BC で学習済みの JetFormer の出力トークン(256次元)を固定して使い、速度とジャンルを足して、2層 MLP で G_t を回帰する。
  - **当てはめがあるフレームでは、コース上の位置(進みの位相の sin/cos と区間)も価値の入力に足す**(学習時だけの特権情報。方策は使わない)。生のリターンは区間で大きく偏る(1.5節)ので、弱い価値でも区間の差を吸収できるようにする。位置あり/なしの両方を作り、保留ログでの予測誤差を比べる。
  - 損失は Huber。RECAP と同じ分布型(51ビン)も比べる。
  - **ログ単位の5分割で交差推定**し、アドバンテージには、自分のログを見ていない V を使う。
- 対照ラベル: 周の残り時間(途切れのない周だけ)+ 失敗の罰。価値の評価だけに使う。

### 5.3 アドバンテージと方策

- A_t = Σ_{k<N} γ^k r_{t+k} + γ^N V(o_{t+N}) − V(o_t)、N=30(1秒。チャンク 0.33秒の3倍)。
- 印 I_t = 1[A_t > ε]。ε はジャンルごとに「良い」が約35%になる値(RECAP の 30〜40% に合わせる)。人の修正区間(交代後の前進部分)は I=1 とする。
- 方策
  - (a) **アドバンテージ条件付き**: 入力に I のトークンを1つ足し、学習中は30%の確率で「不明」にする。推論では I=1。コードを変えずに試すなら、ジャンルを「低速走行・良」「低速走行・その他」に分ける形でも代用できる。
  - (b) **AWR 重み付き BC**: 損失に w = clip(exp(A/β), 0, 20) を掛ける。β は A の標準偏差程度にする。
  - (c) ベースライン: 今の BC(衝突の前後を除外)。
- 3つとも同じデータ・同じエポック数で学習する(Jetson で各約25分)。

### 5.4 オフラインの合否(実車に載せる前に、すべて満たす)

1. **価値の妥当性**: 保留ログで、V が「1秒以内の衝突」を当てる AUROC が 0.8 以上。比較対象は ToF の TTC ルール(既存の 88% 予測)。
2. **R1 での改善**: R1 手前0.4秒のフレーム(R1 の通過は、当てはめがあるログではコース図の区間 R1 の入口、無いログでは `collision_map.md` と同じくジャイロで検出する)で、(a)/(b) の予測スロットルがベースラインより低いこと。予測から見積もった進入 eRPM が 5500 未満の帯に入る割合が上がること。
3. **DE での改善**: 緑マット出口のフレームで、予測ステアがベースラインより左であること(人の +15° 側)。
4. **崩壊していないこと**: 直線区間(当てはめがあるログはコース図の HS・DE、無いログは「ヨーレートが小さく速い」フレームで代用)の予測スロットルの低下が 5% 以内。保留した人のきれいな周での L1 誤差の悪化が 10% 以内。

### 5.5 実車

- 順番: ベースライン → (a) か (b) の良かったほう → ベースライン。
- 条件: 各条件60周を目標にする(最低でも43周。そのときは 2倍の差までしか見えない)。ゲイン固定、リカバリー v2 ON、ToF ガードは記録のみ。
- 主指標: 衝突/周。副指標: 失敗の交代/周、きれいな周の中央値(20周あれば 0.4秒の差が見える)、ハンドルの限界張り付き率。
- 中止基準: 最初の10周で衝突/周が 1.5 を超えたら止める。
- ここで差が出れば、RECAP と同じく「新モデルで走る → ラベル付け → 再学習」を2〜3回まわす。

## 7. 「大規模事前学習 → コース精度データで微調整 → オフラインRL」の流れ

文献の流れは、PTR(オフラインRLで大規模事前学習 → 10デモで微調整)[R49]、FastRLAP(RECON で IQL 事前学習 → オンライン)[R20]、π*0.6(事前学習 → SFT → RECAP の反復)[R9] がほぼ同じ形をしている。JetFormer に当てはめると次のようになる。

| 段階 | JetFormer で何をするか | 必要なもの |
|---|---|---|
| ① 大規模事前学習 | 画像の符号器とトランクを、自分たちの**全ログ**(失敗・AI走行を含む)と公開のナビゲーションデータで学習する。公開データの例は、RC カーを含む GNM/ViNT の混合データ [R50][R51] と RECON。目的は、未来のIMU・速度・ToF の予測(自己教師)と、行動の予測。ToF と IMU は公開データに無いので、画像側だけ事前学習する | クラウドGPU。データ形式の変換 |
| ② コース精度データで微調整 | 今の BC。きれいな周+立て直しの操作(DAgger/IWR 型)。ジャンル別 | 今のパイプライン |
| ③ オフラインRL | 5章の RECAP 型。価値ヘッド+アドバンテージ条件付け。新しいAI走行のたびに反復する | 6章の1〜7 |
| ④(後で)オンライン微調整 | 介入を報酬に(RLIF)、RLPD/Cal-QL/WSRL。リセットは自動リカバリー、安全は ToF ガード | 位置推定、車外GPU、安全な運用 |

- 今いちばん効くのは**②のデータ(R1・DE をきれいに抜ける周)と、③の最小形**。①の公開データの効果は、カメラの画角や高さの違いで限られる。PTR の結果は WidowX のロボットアームで出たもので、そのまま運転に移せるかは確認されていない。
- 価値ヘッドは③で作る。この価値ヘッドは、④の初期化と、走行中の危険モニタにも使い回せる。

## 付録: 計算に使ったスクリプトと出力

`/home/jetson/jetformer_reports/overnight_20261011/research/offline_rl_src/`。すべて読み取りのみ。torch/CUDA は使っていない。`nice` で実行した。

| ファイル | 内容 |
|---|---|
| `inventory.py` → `inventory.json` | ログごとの時間(人/AI)、衝突、交代、リカバリー、周、ガード、基板の再起動 |
| `interventions.py` → `interventions.json` | 交代 57回の分類(衝突後・走行中・スタック・その他)、衝突から交代までの時間 |
| `label_budget.py` | フレーム単位のラベル在庫と、実車評価の検出力 |
| `odom_progress.py` → `odom_progress.json` | ジャイロ+eRPM の推測航法で、1周の閉じ誤差と周どうしの横ずれ |
| `progress_from_map.py` → `progress_from_map.json` | (改訂で追加)コース図に当てはめた軌跡(`../course/tracks_*.npz`)から、周回タイム、区間ごとの「進み / 走った距離」、人の区間の進み |
| `reward_compare.py` → `reward_compare_H30.json`, `reward_compare_H90.json` | (改訂で追加)前進距離と進みで、1秒・3秒先までの報酬和の順位相関、「良い」印(上位35%)の一致、区間ごとの「良い」の割合 |

**数値の注意**:
- 衝突は「水平加速度のノルム − その区間の中央値 ≥ 2.5G、0.5〜0.6秒以内は1回」で数えたので、既存レポートの数え方(||a|−1g|)と少し違う。
- 周は LapCounter をログ全体に流した推定値。シーン削除で途切れた周は時間が伸びる。
- 「走行中の交代」「ゆっくり/その他」の分類は、eRPM のしきい値による推定。
- 1.5節の数値は、並行作業が作ったコース図への当てはめ(`../course/`)をそのまま使った。当てはめ自体の正しさ(保留検証)はこのレポートでは確かめていない。「良い」印の比較は、全フレームをまとめた上位35%で計算した(5.3節のジャンル別・アドバンテージによる印とは違い、報酬の違いだけを見るための簡略版)。
